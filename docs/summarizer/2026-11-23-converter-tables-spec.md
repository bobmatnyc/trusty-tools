# Converter tables spec

Status: draft for owner review. Date: 2026-11-23.

## 1. Goal and non-goals

Goal: the converter keeps table content, so label/value pairs in slide-deck PDFs and PPTX files reach the summarizer, the outline and `find` as rows, not as unrelated lines.

Non-goals:
- Coordinate regrouping. The converter does not rebuild rows from text positions itself. It uses only the tables Xberg reports.
- OCR. `disable_ocr` stays true. Scanned pages with no text layer yield no tables.
- Changing Xberg's detector or its thresholds.

## 2. Facts this spec rests on

Checked against the source on 2026-11-22.
- `workers/summarizer-convert/src/main.rs:91` calls `xberg::extract`. Lines 94-97 return only `doc.content`. `config()` (lines 43-58) sets `OutputFormat::Plain`.
- Xberg 1.3.10 `PdfConfig.extract_tables` defaults to true (`src/core/config/pdf.rs:76`). It runs a grid detector, then a text-layer heuristic if the grid finds nothing.
- `Table` has `cells`, `markdown`, `page_number` (1-indexed) and an optional `bounding_box` (`src/types/tables.rs:12-30`). `Document.tables` holds them (`src/types/extraction.rs:154`).
- PPTX has an explicit table path (`src/extractors/pptx.rs:1403`).
- `PageContent` (`src/types/page.rs:195`) carries per-page text and tables, but `Document.pages` is `Option` and is filled only when page extraction is configured. Whether the current config fills it is not yet checked (question Q1).
- The outline treats `#` headings as structure only for Markdown input (`segment.rs:32`, `pipeline.rs:279`). Converted text is not Markdown, so table markers must be plain lines.
- `CACHE_SCHEMA` is 5 (`crates/trusty-summarizer/src/pipeline.rs:40`).

## 3. Output contract

Where. The worker appends each table after the text of the page it came from, in page order. A table whose page cannot be matched goes at the end of the document. The worker still returns one `text` string, so the wire protocol does not change. Body text keeps `OutputFormat::Plain`. The table itself is the `markdown` field of `Table`.

Marker. Each table block is:

```
[table page=3 rows=5 cols=2]
| Label | Value |
| --- | --- |
| ... | ... |
[/table]
```

The opening marker sits on one line, with a blank line before and after the block. The outline treats the marker line as a section title (`Table, page 3`) so a reader can fetch the rows with `read --lines`. `find` matches cell text and the marker text. Both changes need the segmenter to recognise `[table ` lines in non-Markdown input.

Duplication. Xberg's page text usually already contains the cell text, in reading order. The worker removes it only when safe: a text line is dropped if, after whitespace normalisation, it equals one cell of an emitted table on the same page. Lines that do not match exactly stay. When in doubt the worker keeps the line, so the cost of a miss is repeated text, not lost text. Q2 asks the owner whether to skip de-duplication in v1.

Cache. The table block changes the converted text, so cached results are stale. `CACHE_SCHEMA` goes from 5 to 6. Cache entries written at 5 are not read. Nothing else in the cache key changes.

## 4. Gating against false-positive tables

Xberg's heuristic can report columns of prose as a table. The worker keeps a table only if all of these hold:
- at least 2 rows and at least 2 columns;
- at least 60 percent of cells are non-empty after trimming;
- at least one row has non-empty text in every column;
- no cell is longer than 200 characters, and the mean cell length is at most 80 characters (prose lines break these).

A table that fails any rule is dropped, and its text stays only in the page text. The numbers are starting values. Q3 asks for tuning against real decks.

## 5. Tests

Fixtures are generated by scripts beside `make.sh`, so no third-party file is checked in.
1. `survey.pptx`-style deck with one real table (2 columns, 3 rows), built by a new `make_pptx_table.py`. Expect one `[table page=1 rows=3 cols=2]` block with the cell text, in `tests/worker.rs`.
2. A PDF with a ruled grid (drawn lines, 3 rows, 2 columns), built by an extension of `make_pdf.py`. Expect one table block on page 1.
3. `survey.pdf`. Its output after the change is byte-identical to the output before it (golden text file). It has no table, so no marker appears.
4. A prose PDF with two columns of running text. Expect no table block (gate test).
5. Cache test: a record cached at schema 5 is a miss; one written at 6 is a hit.
6. Repro deck test, marked BLOCKED. It converts a slide-deck PDF and asserts each label sits in the same table row as its value. It stays `#[ignore]` with the reason "BLOCKED: no public repro deck" until a deck that can be checked in exists. The test-result brief §4.5 case is not reproduced on generated slides.

- A1. Moved to #11705 (https://github.com/bobmatnyc/trusty-tools/issues/11705), PPTX table blocks. Text kept for the follow-up: Converting the table PPTX returns text with exactly one line starting `[table page=1 rows=3 cols=2]`, and every cell string appears inside that block.

- A3. `survey.pdf` output equals the stored golden file byte for byte.
- A4. The two-column prose PDF returns zero `[table ` lines.
- A5. For each emitted table, the block follows the text of its page and precedes the text of the next page.
- A6. No cell string of an emitted table appears as a whole line outside the block on the same page, unless de-duplication is switched off (Q2).
- A7. `CACHE_SCHEMA` equals 6, and a schema-5 cache entry is not served.
- A8. Moved to #11705 (https://github.com/bobmatnyc/trusty-tools/issues/11705), outline and `find` entry. Text kept for the follow-up: The outline of A1's output has an entry titled `Table, page 1`, and `find` for a cell value returns a hit inside the block.
- A9. A document with no tables returns the same text as before the change.
- A10. The repro test exists, is ignored, and its reason string starts with `BLOCKED`.

## 7. Open questions for the owner

- Q1. ANSWERED (see Decisions). Does Xberg need page extraction on (`PageConfig`) to give per-page text for placement? If so, the converter pays for it on every PDF. The alternative is placing tables by `page_number` against page-break positions in `content`. Which does the owner prefer?
- Q2. ANSWERED (see Decisions). Ship v1 with de-duplication, or append tables with the duplicate text left in? The second is simpler and safe for recall, at a token cost.
- Q3. ANSWERED (see Decisions). Are the gate values in section 4 acceptable as a start? Real decks may need different values.
- Q4. ANSWERED (see Decisions). May a deck from the owner's own files be anonymised and checked in as the repro, to lift the BLOCKED mark?
- Q5. ANSWERED (see Decisions). Should XLSX (the Xberg 1.4 build) get the same blocks, or stay as its current sheet text?
