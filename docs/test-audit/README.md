# Test-audit verdict log

Internal record for the unit-test audit, issue #11268. It is not published
(it is not in `docs/public-manifest.tsv`).

`verdicts.jsonl` holds one line per Rust test. A reviewer's verdict on a test
stays in the log until the test's normalised body changes, so the audit never
judges the same test twice. Phase 0 rows come from a script and carry no
verdict yet. Phase 1 reviewers fill in `verdict` and `reason`.

## Key

```
<crate>::<repo-relative file>::<module path>::<fn>
```

- `<crate>` is the `[package] name` of the nearest `Cargo.toml`.
- `<module path>` is the chain of inline `mod NAME { … }` blocks inside the
  file, joined by `::`. A test at file top level has no module segment:
  `trusty-secrets::crates/trusty-secrets/tests/on_demand_server.rs::detached_call_role`.
- Two tests with the same path in one file (cfg-gated twins) get `#2`, `#3`, …
  in source order.

## Row schema

Fields appear in this order, compact JSON, rows sorted by key:

| Field | Meaning |
|---|---|
| `key` | The test path above. |
| `body_sha` | sha256 of the normalised body: the body's tokens joined by one space. Comments and layout are dropped; string-literal content is kept. |
| `rules` | Candidate rules that fired, e.g. `["R1","R3"]`. |
| `verdict` | `null` (not reviewed), `keep`, `excessive`, `wrong-target`, `weak`, `flaky`, or `rereview`. |
| `reason` | One line. Script rows: the rule details. |
| `evidence` | `file:line` or a CI run. Script rows: the fn's `file:line` when the row was last written. |
| `reviewer` | `script`, `code-critic`, or a person. |
| `audit_rev` | Commit the row was written against. |
| `date` | UTC date the row was written. |
| `action` | `none`, or the issue that changes the test (`#N`). |

Verdict meanings are in the plan comment on #11268: `excessive` duplicates
other coverage, `wrong-target` tests text, a mock or an implementation detail,
`weak` cannot fail for a real defect, `flaky` has CI history of
nondeterministic failure.

## Rules

The rules flag candidates for review. A flag is not a verdict.

| Rule | Fires when |
|---|---|
| R1 duplicate | Another test in the scanned set has the same `body_sha`, or a Jaccard similarity of 0.85 or more over token 3-shingles (bodies of 40+ tokens; `--near-threshold`, `--min-tokens`). |
| R2 text pin | A compared assertion argument uses an `include_str!` of a `.md`/`.txt`/`.prompt`-style file (directly, through a const, static or loader fn, or through a local bound from one), or a string literal of 8+ words or with markdown markup that the assertion compares against. Message arguments and inputs passed to the code are skipped. |
| R3 no behavioural assertion | No assertion at all, or only `assert!(x.is_ok())` / `assert!(true)`. `unwrap()`, `?` and "does not panic" are not assertions. Counted as assertions: `assert*!`, `ensure!`, `panic!`/`unreachable!` branches, `#[should_panic]`, `unwrap_err`/`expect_err`, calls to `assert*` fns, and calls to a fn in the same file that itself asserts. |
| R4 mock-only | The test binds a mock, stub, fake or spy (by constructor name, or a variable named mock/stub/spy), and every assertion starts at that binding (`fake.calls()`), not at code under test that takes it. |
| R5 constant/derive | Every assertion compares only literals and constants, only fields of a `Default` value, or the two sides of a serde round trip. |
| R6 ignore | `#[ignore]` with no reason string, or an `intent(demo)` ignore. |
| R7 cost | Not implemented. CI keeps no per-test timings (nextest writes no JUnit report), so this needs CI work first. |

Known blind spots: tests generated by a macro invocation are invisible (the
summary counts `#[test]` templates inside `macro_rules!`), assertion helpers
defined in another file are not seen (R3 can flag a test whose helper asserts),
and R1 compares only the crates in the same run.

## Re-running

```
python3 -I scripts/test_audit/inventory.py --crates trusty-secrets trusty-installer
python3 -I scripts/test_audit/inventory.py --all
python3 -I scripts/test_audit/inventory.py --crates trusty-secrets --check   # exit 1 if the log would change
```

The script reads tracked `.rs` files only; it builds and runs nothing. It
prints, per crate, the tests found, the `git grep -cE '#\[(tokio::)?test'`
line count over `.rs` files, how many of those hits are code rather than
comments, and the rule hit counts.

A re-run changes only the crates it scans:

- Same key, same `body_sha`, reviewed: the row is kept as is.
- Same key, same `body_sha`, not reviewed: `rules` and `reason` are
  refreshed; nothing changes unless they differ.
- Same key, new `body_sha`: an unreviewed row is replaced; a reviewed row
  becomes `rereview`, with the old verdict and reason kept in `reason`.
- Test gone: an unreviewed row is dropped; a reviewed row becomes
  `rereview` with reason `test vanished; was …`.

A test is re-evaluated only when its `body_sha` changes. A re-run on an
unchanged tree writes byte-identical output.

Tests: `python3 -I -m pytest scripts/test_audit/tests -q -p no:cacheprovider`.
