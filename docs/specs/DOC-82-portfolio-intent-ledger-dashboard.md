## 1. Scope {#SPEC-LEDGER-01~draft}

**ID:** SPEC-LEDGER-01~draft

- **LDG-1.1** There MUST be exactly one implementation of the Ledger and dashboard data layer (schema, ids, store, derive rules, digest, archive, tally/footer). It lives in the `trusty-architect` crate (`crates/trusty-architect`, which already holds the schema work planned in [#9757](https://github.com/bobmatnyc/trusty-tools/issues/9757)) and is called by every session. Check: a workspace `grep` finds one definition of the id grammar, the status enums and the tally rule; the PM writer, the Architect ingest and the console route all import it.
- **LDG-1.2** A PM project MUST NOT carry its own copy of the Ledger or dashboard code. The only per-project artifacts are data (the store) and hook config generated by tm. This requirement applies to PM projects only. The files tm seeds into the Architect project (the Python dashboard the Architect runs until the Rust implementation replaces it, LDG-1.5) are out of scope: they are not a copy in the sense of this requirement. Owner ruling D9d, 2026-10-27 (decision df-Ddd). Check: the `tm doctor` ledger check fails on a PM project whose tree contains a copy of a prototype script for these features, and MUST skip tm-seeded Architect files.
- **LDG-1.3** The same implementation MUST serve the PM role and the Architect role. The roles differ in store root, collections written and permission (LDG-3.6), not in code. Check: the same function writes a PM goal and an Architect goal; a test runs one fixture through both roots.
- **LDG-1.4** A project MUST get the Ledger from tm with no project edit: `tm fleet init` ([#9457](https://github.com/bobmatnyc/trusty-tools/issues/9457), [#9997](https://github.com/bobmatnyc/trusty-tools/issues/9997)) provisions the Architect store and dashboard; `tm init` / `tm fleet init` for a PM project provisions its store directory, ignore rule ([#9762](https://github.com/bobmatnyc/trusty-tools/issues/9762)), hooks ([#9763](https://github.com/bobmatnyc/trusty-tools/issues/9763)) and PM instruction section. The daemon serves all access (§3). Check: `tm init` in an empty project, then a daemon `ledger` write succeeds with no file copied by hand and no script on `PATH` other than `tm`.
- **LDG-1.5** The prototype (Python) MUST remain the reference until the Rust port is installed and live-checked against the prototype's output; only then is it removed, one feature at a time. Check: each removal PR attaches a diff of Rust against prototype output on the same fixture store (golden bytes from the prototype, committed as test fixtures by issue A).
- **LDG-1.6** Out of scope: cross-host and multi-owner sync ([#9756](https://github.com/bobmatnyc/trusty-tools/issues/9756)), the transcript, secret values (locations only), code review state.
- **LDG-1.7** The Ledger MUST keep one logical data model for PM and Architect sessions (§2) even where the physical layout differs (PM: `state.json` snapshot plus logs; Architect: one JSON document per record). The daemon API (§3) hides the layout. Check: a conformance test reads the same logical fixture through both layouts and gets equal records.

## 2. Data structures (normative contract) {#SPEC-LEDGER-02~draft}

**ID:** SPEC-LEDGER-02~draft

Source of truth: the dashboard JSON Schema set (JSON Schema 2020-12, 14 files), loaded unchanged by the Rust crate. Where this section and a schema disagree, [§7](#SPEC-LEDGER-07~draft) lists it as a gap and the schema is amended; the code never wins by default.

### 2.1 Collections

- **LDG-2.1.1** The Architect (dashboard) store MUST hold these collections, each validated by the named schema. Check: `validate` over the live store reports zero errors; every collection directory has a schema (a collection without one fails `validate`).

| Collection | Record | Schema | Id | Writer |
|---|---|---|---|---|
| `items` | decision (kind question), ask (action), task (task), request R | `items.schema.json` | D, A, T, R + 2 hex | Architect; owner via page (answers) |
| `goals` | goal | `goals.schema.json` | G + 2 hex | Architect; owner via reorder docs |
| `goal_reorders`, `goal_removals` | owner rulings on goals | same-named schemas | doc id free | owner (page) |
| `step_progress` | per-step done flags of an item | `step_progress.schema.json` | = item id | owner/Architect |
| `sessions` | one row per tmux session | `sessions.schema.json` | S + 2 hex | Architect (feed, poller) |
| `questions` | answered owner question, kept until cleared | `questions.schema.json` | Q + 2 hex | Architect writes; owner clears |
| `briefs` | one-paragraph brief | `briefs.schema.json` | `<date>-<slug>` | Architect/PM |
| `accounts` | plan usage meter | `accounts.schema.json` | account slug | poller |
| `effort_tunes` | owner effort setting | `effort_tunes.schema.json` | doc id | owner |
| `meta/state`, `meta/settings`, `meta/seen`, `meta/gh_track` | singletons | `meta-*.schema.json` | fixed | see LDG-2.7.1 |

- **LDG-2.1.2** A PM (session) ledger MUST hold goals (G), decisions (D), asks (A), tasks (T), and the session record, and SHOULD hold briefs (B, [#9759](https://github.com/bobmatnyc/trusty-tools/issues/9759)). Its logical records are the same as the Architect's records of the same prefix (LDG-2.2), so they merge without translation. Check: ingest of a PM record produces a dashboard record that passes `items.schema.json` with no field mapping other than namespacing (LDG-5.3).
- **LDG-2.1.3** The PM store layout MUST be `<project>/.trusty-mpm/dbatg/<session>/` with `state.json`, `log.jsonl`, `archive.jsonl`, `outbox.jsonl`, `acks.json`, `.lock` ([#9757](https://github.com/bobmatnyc/trusty-tools/issues/9757), [#9995](https://github.com/bobmatnyc/trusty-tools/issues/9995)), anchored to the session's launch directory, one store per session. Check: two sessions in one checkout produce two stores with independent counters.

### 2.2 Ids

- **LDG-2.2.1** Every id MUST be `<Prefix><hex2>` in its own store, Prefix one uppercase letter: G goal, P priority, A ask, D decision, T task, S session, Q answered question, R owner request, B brief (PM ledger). Hex digits are 0-9a-f only. Check: `ID_RE` in the Rust crate equals `^[A-Z][0-9a-f]{2}$` and a property test rejects every other form.
- **LDG-2.2.2** A PM-ledger id MUST carry its code: `<code>-<Prefix><hex2>`; the code matches `^[a-z][a-z0-9]{1,7}$`, is unique per host (code registry, #9757), and is never reused by another live session. Check: `init` with a registered code exits non-zero and writes nothing.
- **LDG-2.2.3** There is one counter per prefix per store. The next id MUST be computed from the store (first free id after the highest used, wrapping past `ff` to the lowest free; none when full), never advanced by hand or kept as a stored counter in the Architect store. A PM store keeps `next` in `state.json` and MUST refuse an id already in use. Ids are ephemeral, so an archived id is free and MUST be reissued like any other (Bob ruling 2026-10-24, #10235; permanent records live in tickets, ADRs, specs and memory). Check: the prototype's id unit tests pass in Rust; a wrap test returns the lowest free id; a test reuses an archived id and a test refuses a live one.
- **LDG-2.2.4** Ids recycle. A store MUST keep at least 64 free ids per prefix; the retire candidates are the oldest `done` records by `done_at`. Retirement archives first (LDG-2.8.4), then deletes. Creating new ids is held when the owner does not engage existing ones. Check: a `retire_candidates` test; deletion is refused when the archive write fails.
- **LDG-2.2.5** A recycled id MUST NOT collide with a live reference. A record MUST NOT be retired while another live record names it in `links`, `depends_on` or `goal`. Check: `fsck` reports dangling references; a retire test with a dependent open item refuses.

### 2.3 Records: goals, decisions, asks, tasks

- **LDG-2.3.1** Goal. Required: `kind` (standing|directed|factory), `rank`, `title`, `lifecycle` (active|parked|done|removed), `updated`. A factory goal MUST have `board {label,url}`; lifecycle `parked` MUST have a `parked` object; a non-parked active goal MUST NOT. Check: schema test plus invariants test.
- **LDG-2.3.2** Item (D, A, T, R). Required: `kind` (question|action|task), `status`, `title`, `session`, `goal`, `rank`, `created`, `updated`. Status lifecycle: `open` -> `answered` (D, A, by the owner) -> `done` (with `done_at` and a one-line verified `outcome`); `open` -> `wont_do` or `cancelled` (terminal). Parked is a flag on an open item, not a status. A task also has `running`/`open` in the PM ledger (gap G3). Check: a status transition table test rejects `done` -> `open` and `answered` on a task.
- **LDG-2.3.3** Decision options. A D item MUST carry `options` (2 to 4), exactly one with `recommended: true`, listed first; each option MUST carry `markers {work, scope, risk}`, integers -3..3. A D item MUST carry `specs [{label,url}]` or the literal detail text "no spec". Check: `validate` flags a D item that lacks markers on an option, lacks a recommended option, or has neither specs nor "no spec" in `detail`. Enforcement level is DECIDED in [§8](#SPEC-LEDGER-08~draft) (decision 4): a warning in the store, a hard check in the PM writer for D items that carry `esc: architect`.
- **LDG-2.3.4** Field limits MUST be schema-enforced: `title` at most 120 characters; `detail`, `answer`, `outcome` at most one paragraph (no blank line); a long explanation goes to a brief linked from `doc`/`brief` (pattern `^[^/]+/docs/briefs/.+[.]md$`). Check: schema `maxLength` and a no-blank-line invariant; an over-limit write is refused with exit 2 and files untouched.
- **LDG-2.3.5** Secrets: a write containing a secret-shaped value MUST be refused and the log line MUST record the refusal without the value ([#9758](https://github.com/bobmatnyc/trusty-tools/issues/9758)). Check: a fixture with a key-shaped string.
- **LDG-2.3.6** Timestamps MUST be UTC ISO-8601 with seconds (`YYYY-MM-DDTHH:MM:SSZ`). A minute-precision input MUST be normalized on write, never stored. Check: write `2026-10-19T12:00Z`, read back `2026-10-19T12:00:00Z`.

### 2.4 Session record

- **LDG-2.4.1** Each PM ledger MUST hold one `session` object, rewritten whole, at most 2 KB, with `task`, `next`, `waiting_on`, `owed` (exact values, never "latest"), `agents`, `crons`, `boundary_at`, `ctx_use`, `written_at`. Check: an over-limit field is refused (exit 2); `owed.expect` equal to a vague word is refused.
- **LDG-2.4.2** The Architect keeps the same record for itself (code `ar`), in its Architect store, not in a separate file (gap G11). Check: `digest` of the Architect store contains the session record.

### 2.5 Sessions (dashboard rows)

- **LDG-2.5.1** `sessions` rows MUST carry `name` (tmux session), `state` (idle|working|exited|parked), `status`, `summary`, `updated`; SHOULD carry `goal`, `project`, `progress`, `usage` and `details` (ctx_k, waiting_on, prs, issues). `usage` is written by the feed only and pinned with `if_version`. Check: feed writes touch only `usage`; a conflict skips the row, never overwrites.

### 2.6 Questions

- **LDG-2.6.1** Every answer to an owner question MUST be recorded as a `questions` record (`asked`, `answer`, `status` open|cleared, `answered_at`, `updated`) in the same pass; only the owner clears it. Check: the footer reports `answers_waiting`; a test shows the Architect cannot set `status: cleared`.

### 2.7 Meta

- **LDG-2.7.1** `meta/settings` carries `user_state` (active|remote|away|sleeping), `user_state_at`, `user_state_by`, sleep window, `tz`; the Architect reads it every pass. `meta/state` carries `owner_name`, `updated`, `fleet_usage`; next ids are derived, not stored. `meta/seen` and `meta/gh_track` are page and poller state. Check: each validates against its schema.

### 2.8 Version, change log, archive

- **LDG-2.8.1** Every document write MUST be an atomic replace under an exclusive lock, carry a store-managed integer `version` (absent = 1), and accept `if_version` (0 means must not exist). A mismatch is a conflict (HTTP 409, CLI exit 1) and nothing is written. `version` is reserved: a body that contains it is refused. A batch is all-or-nothing. Check: tests for conflict, batch rollback and the reserved key.
- **LDG-2.8.2** A PM ledger write MUST bump `v` by one, append the log line and outbox line first, then replace `state.json`, then fsync; a kill between steps recovers by replay (#9758). A read-modify-write with a changed `v` logs `tamper` and does not overwrite. Check: a kill-injection test.
- **LDG-2.8.3** Every document change MUST append one line to `changes.jsonl`: `{seq, ts, collection, id, op, version, keys}`, with `seq` strictly increasing; the file rotates by month and rotated files are kept. `changes.jsonl` MUST get a schema (gap G9). Check: `fsck` verifies seq continuity and that the last version of each document matches its change line.
- **LDG-2.8.4** A delete or retire MUST append the full record to the pruned archive (`pruned.jsonl`, one JSON object per line: `{id, collection, deleted_at, by, version, data}`) before removing the document, and the delete MUST fail if that write fails. In a PM ledger the equivalent is `archive.jsonl` written in the same commit as the removal from `state.json`. The memory archive (a trusty-memory note) is written first, the archive file second, the delete last (DECIDED, [§8](#SPEC-LEDGER-08~draft) decision 9). Nothing archived is deleted from disk. Check: `pruned --id` returns the record; a failed archive write leaves the document in place.
- **LDG-2.8.5** Size bar: a PM `state.json` over 8 KB logs `size_warning`; a write leaving it over 16 KB and larger than before is refused with the largest items named. Check: a 17 KB fixture is refused, files byte-identical.

## 3. Storage and access {#SPEC-LEDGER-03~draft}

**ID:** SPEC-LEDGER-03~draft

- **LDG-3.1** The Architect store MUST live under the Architect's data root (configurable, shipped default set by `tm fleet init`) and a PM store under its project as in LDG-2.1.3. Stores are never committed; a fresh project gets an ignore rule (#9762). Check: `git status` after a write shows nothing.
- **LDG-3.2** The format MUST support the two existing formats, one JSON file per document (`dir`) and canonical JSONL per collection (`jsonl`), with a loud refusal of a store in the other format (never read as empty). Check: Rust writer output equals the golden bytes.
- **LDG-3.3** The daemon MUST expose the Ledger as one set of methods, wrapped by an MCP tool and a CLI verb group, with identical schema, limits and exit codes. A PM that cannot run shell MUST be able to use all PM verbs through the MCP tool (#9758). Check: a live PM session with Bash denied writes and reads its digest. Every verb that has a prototype counterpart takes the same arguments and prints the same bytes until the prototype is removed (LDG-1.5); check: a parity test per verb.

| Surface | PM verbs (#9758, #9995) | Architect verbs |
|---|---|---|
| daemon method | `dbatg.init/add/update/close/batch/show/prune/rotate/session_set/digest/fresh/stamp/archive_show` | `architect.dashboard.get/list/set/update/delete/batch/pruned/validate/fsck/tally/footer/ids` |
| MCP tool | `dbatg` (op field) | `architect_dashboard` (op field) |
| CLI | `tm dbatg <verb>` | `tm architect dashboard <verb>` (extends the `tm architect` group of [#9822](https://github.com/bobmatnyc/trusty-tools/issues/9822)) |

- **LDG-3.4** The HTTP surface MUST be the console only (ADR-0032, as cited in DOC-73): a console route (proposed `/architect`, serving the dashboard page and `/api/<coll>[/<id>]`, `/api/batch`, `/doc/<project>/<rel>`) replaces the prototype's standalone server. The route name is DECIDED ([§8](#SPEC-LEDGER-08~draft) decision 6). The route MUST keep the prototype's guards: bind 127.0.0.1, Host allowlist (localhost, MagicDNS name), Origin check on writes, 409 on `if_version` mismatch, a read-only Markdown reader (no dotfiles, no `..`, no secrets-named files, `.md` only). Check: the prototype's document-reader, tailnet and store tests, ported.
- **LDG-3.5** The page MUST keep working unchanged against the new route (same `/api` shape, same 2 s snapshot poll or an SSE feed once the console provides it, [#6851](https://github.com/bobmatnyc/trusty-tools/issues/6851)), and MUST reload on page-revision change (`X-Page-Rev`). Check: a browser live check by a web QA pass.
- **LDG-3.6** Write permission. A PM session MUST write only its own store (and only through the daemon method bound to its session). The Architect MUST write only `acks.json` in a PM store ([#9760](https://github.com/bobmatnyc/trusty-tools/issues/9760)). The owner writes through the page: answers, reorders, removals, settings, clear of questions. Check: a test where a PM writes another session's store is refused; a test where the Architect writes a PM `state.json` is refused.
- **LDG-3.7** Discovery: the daemon MUST publish the console address at `<data dir>/trusty-architect/http_addr` ([#9474](https://github.com/bobmatnyc/trusty-tools/issues/9474)). Check: the file exists after start and is removed on shutdown if still its own.
- **LDG-3.8** The prototype remains until the Rust is live-checked (LDG-1.5). During the overlap exactly one process writes a given store; the daemon refuses to start on a store the prototype server holds the lock for. Check: a ported live-guard test.

## 4. Session-level reporting {#SPEC-LEDGER-04~draft}

**ID:** SPEC-LEDGER-04~draft

- **LDG-4.1** Each session MUST publish its report through its ledger only: no separate status file, no free-text message as the carrier. The report is the ledger state plus the outbox. Check: a `grep` of the PM instruction section finds no second reporting channel; PM notification messages carry a ledger id.
- **LDG-4.2** A session report MUST contain these parts. Check: a schema-valid sample report from each part passes the ingest.

| Part | Content | Format | Where |
|---|---|---|---|
| IL state | session record (LDG-2.4) | `state.json["session"]` | PM store |
| Goals | PM goals with rank, status, `maps` to the Architect goal id | goal records | PM store |
| Decisions and asks | open/answered D and A with options, markers, specs, `esc` | item records | PM store |
| Tasks | open and running T with goal | task records | PM store |
| Progress | `progress {pct, estimated_at, eta, confidence, basis}` on the item or goal | as `items.schema` | PM store |
| Briefs | one-paragraph brief with `doc` | brief record (B) | PM store |
| Context and usage | `ctx_use`; measured ctx, tokens by window | session record and feed | PM store (self-report); Architect feed (measured) |

- **LDG-4.3** Timing. A PM MUST write its ledger once per turn that changed state, as one batch, and always at a task boundary (done, closed, merged, nothing running), with `ctx_use` at the boundary. A decision or ask MUST be written when raised, not at turn end. The measured fields (`usage`, ctx) are written by the Architect feed, never self-reported by the PM. Check: `fresh` exits 0 after the write and 1 after a state-changing turn with none (#9995); stale turns raise a poller alert after two.
- **LDG-4.4** Each PM write MUST also append an outbox line `{seq, epoch, code, id, rev, op, at}` so ingest is keyed `(code, id)` with idempotent apply when `rev` is higher (#9760). Check: replay, reorder and duplicate each leave one record.
- **LDG-4.5** A session MUST NOT report a claim as verified. Fields such as `outcome` and `owed.expect` hold values the Architect can check by command; ingest marks them `reported` until the Architect verifies. Check: ingested records carry `verified: false` until a verification write.
- **LDG-4.6** Delivery failure MUST be visible: a PM sees `UNACKED` after N turns and the dashboard shows a per-session un-acked count (#9760). Check: kill the ingest, write 3 items, the status line shows UNACKED 3; restart, the count returns to 0.

## 5. Architect aggregation {#SPEC-LEDGER-05~draft}

**ID:** SPEC-LEDGER-05~draft

- **LDG-5.1** The Architect MUST read every session's report into one portfolio view, deterministically, without an LLM turn: ingest reads each store's outbox above `acked_seq`, applies idempotently, writes `acks.json`, and updates the dashboard store. The wake decision stays with the poller triage ([#9801](https://github.com/bobmatnyc/trusty-tools/issues/9801) slice 3). Check: ingest with the Architect killed and restarted loses no line and advances `acked_seq` (#9760).
- **LDG-5.2** The portfolio view MUST contain: (a) the owner queue across all projects (open D, A, T, answered-not-relayed, parked, running), (b) goals in rank order with the sessions mapped to each, (c) sessions with state, progress, ctx and usage, (d) accounts and host bands, (e) the answered-questions list. Check: the view over a fixture of three sessions equals a golden snapshot.
- **LDG-5.3** Namespacing. The portfolio id of a record is `<code>-<Prefix><hex2>`. Architect-owned records use the Architect's code (example code `ab`); the existing bare ids in the Architect store (`D01`) are the same records as `ab-D01` and MUST stay valid in display and input (a bare id means the Architect's code). A PM record ingested into the dashboard store MUST keep its PM id and be stored with `origin: {code, session, id, rev}`; the Architect never renumbers or mints an id in a PM's namespace. Display is DECIDED ([§8](#SPEC-LEDGER-08~draft) decision 3): storage prefixes everything, input accepts bare ids as the Architect's code, and bare ids display only inside the Architect's own pages. Check: ingest of `cd-D01` and Architect `D01` yields two distinct records; display of both is unambiguous.
- **LDG-5.4** Dedupe. Ingest is idempotent on `(code, id)` with higher `rev` winning (#9760). A PM decision that restates an Architect ruling is not deduplicated by text; it is matched to the ruling by id reference (`links`) and answered by relay only when covered by a stored ruling or the routine class ([#9764](https://github.com/bobmatnyc/trusty-tools/issues/9764)). An item whose `epoch` changed (store re-initialised) is held, not merged. Check: the acceptance tests of #9760 and #9764.
- **LDG-5.5** Ownership of ids across sessions: a PM owns the ids in its code and is the only writer of them (LDG-3.6). The Architect owns the ids in `ar`, plus the owner-facing numbering of the dashboard (D, A, T the owner sees). When the owner needs a single list, the page shows the portfolio id, not a renumbered one, and the Architect MUST NOT renumber, reorder or drop numbered items the owner has seen. Check: ids shown before and after a pass are a superset of the earlier ones.
- **LDG-5.6** Session-local data MUST stay out of the portfolio view: the PM `log.jsonl`, rotated logs, `archive.jsonl`, tasks that are not blocked, escalated or owner-visible, the full session record (only `task`, `next`, `waiting_on`, `owed` summary, `ctx_use` are projected), raw `outbox.jsonl`. Tasks appear in the owner queue only when `esc` is set or the PM sets `visible: true` (DECIDED, [§8](#SPEC-LEDGER-08~draft) decision 5). Check: the ingest projection test lists exactly the projected fields.
- **LDG-5.7** Counts MUST come from one deterministic path. The footer line, `tally` and any report count are produced by one tally function (Rust: the same function in the crate); no agent counts by hand. The footer is `Dashboard: [localhost](…) · [tailnet](…) — N open dashboard items: …`, with open = status open and not parked, parked counted apart, answers waiting counted from `questions` with status open. Check: a test where a model-written count differs from the tally is flagged by the footer check; a store that cannot be read yields an error, not a zero.
- **LDG-5.8** The Architect MUST scope aggregation to the owner's goals: each ingested record maps to a goal (`maps` for PM goals, else flagged unmapped on the page). Production-critical services MUST never appear in a pause or park proposal. Check: the unmapped count is shown; a fixture session with no goal produces an unmapped flag.
- **LDG-5.9** Retention of aggregated data follows LDG-2.2.4 and LDG-2.8.4: done records older than the keep window leave the dashboard after archive to the project's trusty-memory palace; the PM's own archive is unaffected. Check: a ported archive test.

## 6. Migration for a project that copied the prototype {#SPEC-LEDGER-06~draft}

**ID:** SPEC-LEDGER-06~draft

One downstream project is copying the prototype now. Decided ([§8](#SPEC-LEDGER-08~draft) decision 8): the copy is allowed to continue, pinned and recorded, until the shared implementation ships.

- **LDG-6.6** Until the shared implementation ships, changes to the prototype that a copy needs MUST be made once in the source, then re-copied with a new recorded sha (no fork). Check: the recorded shas of all copies are reachable from the source's history.

## 7. Gaps: schemas versus code and spec {#SPEC-LEDGER-07~draft}

These 17 gaps MUST close before the port removes the prototype. Closure rule, **LDG-7.1**: each gap is closed by a PR that updates the schema, the Rust crate and a test, and the gap row is removed. A CI job fails when a code constant (enum, regex, limit) differs from the schema file.

| # | Gap | Proposed fix |
|---|---|---|
| G1 | The PM ledger has no JSON Schema: `state.json`, session record, `archive.jsonl` line, `log.jsonl` line, `outbox.jsonl` and `acks.json` are defined only in prototype code and the prototype Ledger spec. [#9757](https://github.com/bobmatnyc/trusty-tools/issues/9757) plans the schema. | Add `schemas/ledger/*.json`; Rust types generated from, or checked against, them. |
| G2 | Three id grammars: PM `^([a-z][a-z0-9]{1,7})-([GDAT])([0-9a-f]{2})$`, dashboard `^([A-Z])([0-9a-f]{2})$`, and a permissive document-id regex in the store (`^[A-Za-z0-9][A-Za-z0-9_.-]{0,79}$`). | One grammar (LDG-2.2, LDG-5.3); the store regex stays a path-safety check only. |
| G3 | Task status: the PM ledger allows `open\|running\|done`; the items schema has no `running`. | Add `running` for kind task, or map to `open` plus `run_start`; pick one. |
| G4 | Kind vocabulary: PM `kind` for D/A items is derived (`question`/`action`) and tasks sit in a separate `tasks[]`; the dashboard has one `items` collection with `kind` task. | One `kind` enum in both; PM `state.json` keeps lists but each record carries `kind`. |

| G8 | Timestamp precision: items, goals and sessions require seconds; the PM session record uses ISO minute (`boundary_at`, `written_at`). | One precision (seconds), normalized on write (LDG-2.3.6). |
