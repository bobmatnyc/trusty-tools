## 0. Verdict

`tagent` already routes to Bedrock per agent, delegates to a child that loads its own model, and has a web UI plus a Tauri shell. Five defects stop the stated beta: (1) Opus 5.5 and Sonnet 5.5 requests carry `temperature` and Bedrock rejects them; (2) Bedrock tool-loop turns write no usage record and emit no LLM events, so the model-identity and token rows have no data; (3) a Bedrock-pinned config can still leave Bedrock through several paths listed in 2c; (4) `tagent --help` and every non-`--version` start deploy files into the real `$HOME`; (5) there is no approval prompt, no mid-run steering, and no durable run in `tagent`. `tcode` (`crates/trusty-code`) covers approvals, cancel and session attach better and should be the Codex-side half.

## 2. Open questions

### 2a. Subagent model: own or inherited?

Own. `delegate_to_agent` calls `self.runner.run(agent_name, task)` (`tools/delegate.rs:688`). The dispatcher loads `AgentConfig::by_name_async(agent_name)` (`agents/claude_code_runner/dispatcher.rs:80`); in-process (`agents/in_process_runner.rs:285`) and subprocess (`agents/claude_code_runner/run.rs:495-503`) both load the child's own config and call `chat_with_tools_gated(&cfg.agent.model, ...)`. Nothing is copied from the parent except an explicit `RunContext.model` override, which goes through `cfg.override_model` and keeps the child's pin (`in_process_runner.rs:289-294`). V.
No dedicated "subagent model" key: `SubagentsConfig` has `allowed`, `delegate_allowed`, execution-style keys only (`agents/config.rs:284-310`) V.
Config paths that give main=Opus, sub=Sonnet on Bedrock (all V, no code change):
1. Env: `TAGENT_MODEL_<UPPER_SNAKE_AGENT>` has top priority (`agents/model.rs:152-160`, order at 165-185). Subprocess children inherit env (no `env_clear` in `subprocess/spawn.rs`) V. Example: `TAGENT_MODEL_CTO_ASSISTANT=bedrock/us.anthropic.claude-opus-5-5`, `TAGENT_MODEL_RESEARCH_AGENT=bedrock/us.anthropic.claude-sonnet-5-5`.
2. Overlay TOMLs in `TAGENT_CONFIG_DIR` (beats the `$HOME` tier: `agents/loader.rs:879-901`). Preferred, because it can also declare `aws_profile`/`aws_region`, `[[stores]]` and `delegate_allowed`.
Caveats: `cto-assistant` already pins `bedrock/us.anthropic.claude-sonnet-4-6`, `provider_id="bedrock"`, `aws_profile="cto"`, `aws_region="us-east-1"` (`content/agents/trusty-agents/agents/cto-assistant/agent.toml:38-39`, `[llm]` block) V. Its reachable children `research-agent` and `ticketing-agent` ship bare `claude-sonnet-4-6` with no pin and no `aws_profile` V. A child with no `aws_profile` gets `BedrockEnvGuard::install(None,None)` (`runtime/subagent_exec.rs:206-213`), which clears `TAGENT_AWS_PROFILE`, so the SDK default chain applies: export `AWS_PROFILE=cto AWS_REGION=us-east-1` or declare the fields in the child overlay.
The streaming path ignores `[llm].aws_profile`: `llm/stream.rs:331-334` builds `BedrockProvider::new(model_id, None)` and `trusty-common/src/chat/bedrock_impl.rs:165-173` loads the default chain with region from `TRUSTY_AWS_REGION`/`AWS_REGION` only. Tools-off turns therefore need `AWS_PROFILE` in the environment even when the TOML sets it. V.

### 2b. Every Bedrock request that sets temperature

In trusty-agents (all unconditional, V):
- `llm/bedrock/client.rs:56` `chat_oneshot`. Callers: `llm/single_turn.rs:194` (passes the agent temperature), `knowledge/inference.rs:36` (passes `0.0`).
- `llm/bedrock/client.rs:104` `chat`. No caller in the crate (grep for `bedrock::chat(` empty); it is `pub`-re-exported (`llm/bedrock/mod.rs:20`), so fix it with the others.
- `llm/bedrock/client.rs:155` `chat_with_tools`. Caller: `llm/tool_loop/mod.rs:162`, which is the main assistant turn with tools and every delegated child.
Already safe: the streaming path (`stream_reply_bedrock` -> trusty-common `BedrockProvider`, `chat/bedrock_impl.rs:365` filters through `accepts_temperature`) and trusty-common `inference/bedrock/mod.rs:417-424` V. `tcode` bedrock files have no temperature V.
Reuse: `trusty_common::claude_temperature::accepts_temperature(model: &str) -> bool` is `pub(crate)` in a `pub(crate) mod` (`trusty-common/src/claude_temperature.rs:34`, `lib.rs:123`) V, so trusty-agents cannot call it today. It strips one `bedrock/`/`anthropic/` prefix, reads the family from `us.anthropic.claude-opus-5-5`-style ids, and returns false only for the 5.5 families. Smallest fix: make it public (a `pub fn` re-export, e.g. from `trusty_common::inference::bedrock`), add one helper in `client.rs` that builds the `InferenceConfiguration` (`.set_temperature(accepts_temperature(model_id).then_some(t))`), and use it at the three sites. `trusty-review/src/llm/bedrock/mod.rs:507` already holds a private copy, so reuse beats a third copy. This is a rung-4 change (public API of a shared crate).

### 2c. Paths that can leave Bedrock without an error

All V unless marked.
1. `FALLBACK_MODEL = "anthropic/claude-sonnet-4-6"` (`agents/model.rs:42`) returned as the last tier of `resolve_model` (`model.rs:~190`) when the agent model is empty and `TAGENT_DEFAULT_MODEL` unset. Also the built-in `ctrl` default TOML uses `model = "anthropic/claude-sonnet-4-6"` (`model.rs:~58`).
2. Bare slugs. About twenty bundled agent TOMLs (all except `cto-assistant` and `bedrock-engineer`, plus the `openai/` ones) ship `claude-sonnet-4-6`/`claude-opus-4-6`/`claude-haiku-4-5` with no pin (`content/agents/trusty-agents/agents/*.toml`, e.g. `pm.toml:14`, `research-agent.toml`, `ticketing-agent.toml`, `assistant/agent.toml:40`). They route by ambient credential: `pick_credentials` (`llm/credentials.rs:108-124`) order is `claude-code` (only for `runner=claude-code`), then `ANTHROPIC_API_KEY`, then `OPENROUTER_API_KEY`, else error. It never returns Bedrock. Called from `ctrl/config.rs:167`.
3. `llm/provider_policy.rs` (`[providers] default_provider_id` in `~/.trusty-agents/config.toml`) can pin all unpinned agents to `bedrock`, but `pinned_model_slug` only prefixes (`provider_pin.rs:252-275`), turning `claude-sonnet-4-6` into `bedrock/claude-sonnet-4-6`, which is not an inference-profile id. That fails loudly at the first turn but is not usable. R on Bedrock's exact message.
4. Local Ollama fast path: `[local_inference].enabled` defaults to true (`mcp/config/types.rs:44-48`). If Ollama answers on localhost and the intent qualifies, ctrl and PM turns go to `ollama/qwen3:30b` (`ctrl/ctrl_turn/dispatch.rs:200-206`, `ctrl/pm_task/dispatch/history.rs:249-262`). On a transport failure of the local call it retries on the configured remote model (`local_fallback.rs:100-150`). The persona/assistant path (`persona.rs`) does not use it V.
5. Session overrides `/provider` and `/model` (`ctrl/config.rs:97-170`). A pinned agent refuses a conflicting provider override (`config.rs:104-122`); an unpinned one accepts `openrouter`/`claude-code`.
6. `runner = "claude-code"` agents (for example `claude-code-engineer`) use the Claude CLI subprocess with an OAuth token, not Bedrock (`credentials.rs:108`, `dispatcher.rs:88`).
7. A pinned `bedrock` agent whose AWS chain is broken: `provider_pin::resolve` skips the credential check for Bedrock (`provider_pin.rs` doc at `resolve`), so the failure appears at the first turn as `Bedrock Converse turn 0 failed` (`client.rs:178`) with the SDK text. This does not leave Bedrock, but it is not the clear message the row asks for.
8. Streaming failure falls back to the blocking call on the same model (`persona.rs:~708`); it stays on Bedrock.
Not found: no retry/failover adapter that switches provider inside `llm/` (grep for failover/escalat in `llm/` hit only comments). `routing_model` (haiku, `pm.toml`) is parsed but never read by dispatch (`agents/params.rs:440`, grep shows only struct fields) V.
Change that makes a Bedrock-pinned config fail loudly (M1-T2): one lock, `TAGENT_PROVIDER_LOCK=bedrock` or `[providers] lock = "bedrock"`, checked in `AgentConfig::apply_provider_pin` (`agents/loader.rs:430-470`, also on `override_model` at 501-510): reject any agent whose final slug does not start `bedrock/` or whose `runner` is `claude-code`, naming the agent and the slug. When the lock is set: `resolve_model` returns an error instead of `FALLBACK_MODEL`; `pick_credentials` returns none and `ctrl/config.rs:167` reports "provider lock = bedrock"; the local-inference route is off. Plus a credential preflight in `llm/bedrock/mod.rs:38` `build_client`: call `config.credentials_provider()` `.provide_credentials().await` and map the error to a message naming profile, region and "no other provider is tried".

### 2d. Startup provisioning and isolation

Runs on any invocation except `--version`/`-V` (answers at `runtime/startup.rs:128`, before env loading and provisioning), `tagent config ...` and `mcp-serve` (dispatched before `run_startup_init`, `runtime/mod.rs:174-194`). `--help` is clap-handled after `run_startup_init`, so it provisions (matches the Codex finding). V.
Order in `run_startup_init`: `.env`/`.env.local` loading (`startup.rs:136`, skipped under `TRUSTY_SANDBOX=1`); `ensure_bundled_agents_deployed()` to `$HOME/.trusty-agents/agents/` (`startup.rs:195`, `agents/bundled/mod.rs:462-464,517-522`), refreshing stale bundled files and keeping hand-edited ones (the "6 refreshed / 6 kept" message at `startup.rs:~237-262`); `ensure_bundled_workflows_deployed()` (`startup.rs:207`); `assistants::provision_startup_homes()` creating `~/trusty-agents/<instance>/` (`startup.rs:226`, `assistants/provision.rs:178`); tracing log at `~/.trusty-agents/logs/repl.log` for the interactive REPL (`startup.rs:~310`); state dirs under the project's `.trusty-agents/state` for non-API modes. `--api`/`--serve` return before the state-dir step.
Isolation knobs:
- `HOME=<beta dir>` moves all of the above (`dirs::home_dir()`, `std::env::var_os("HOME")`: `agents/bundled/mod.rs:462`, `agents/loader.rs:894`, `assistants/home.rs:123`). Not enough alone: it also hides `~/.aws` (set `AWS_CONFIG_FILE` and `AWS_SHARED_CREDENTIALS_FILE` to the real files) and the instruction-content cache `~/.trusty-mpm/content` (`trusty-agents-common/src/agent_content.rs:215-222`); without installed content the deploy returns an error and no agents exist (the roster is read from content, not compiled in, #9011). Seed the cache or run from a trusty-tools checkout, which `resolve_content` serves as a dev checkout (R on the exact detection rule).
- `TAGENT_CONFIG_DIR` only changes the primary agents dir; it does not stop the `$HOME` deploy V (`startup.rs:195` has no condition).
- `TAGENT_ASSISTANTS_DIR` relocates `~/trusty-agents` (`assistants/home.rs:58,117-122`).
- `TRUSTY_SANDBOX=1` stops `.env.local` and credential-file loading (`trusty-common/src/credentials/dotenv.rs:44`) but not the bundled deploy V-negative.
- No flag or env var disables the deploy. M1-T5 adds `TAGENT_NO_PROVISION=1` (or ties it to `TRUSTY_SANDBOX=1`) at `startup.rs:195-226`.
