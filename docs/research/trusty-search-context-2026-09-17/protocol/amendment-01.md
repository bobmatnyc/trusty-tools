# Tuning-stage amendment: graph coverage and query routing

Recorded before any held-out evaluation. The first tuning runs exposed two issues: the default graph caps nodes at 100,000, and natural-language identifier questions do not enter the existing exact-match path although the bare identifier succeeds. The six-cell grid remains an exploratory comparison at the production graph cap; do not describe its graph as complete.

Retain the original six-cell selection rule. Rebuild baseline and its selected challenger with the same unlimited graph setting (`TRUSTY_MAX_KG_NODES=0`), record actual counts and zero-vector evidence, and compare on tuning queries before held-out evaluation. Do not select a different chunk treatment using held-out queries.

Add a separately labelled query-routing ablation, using only query text: anchored case-insensitive `Where is IDENTIFIER defined?` becomes `fn IDENTIFIER`. Other queries remain unchanged. This isolates routing from indexing changes. No expected path, symbol label, or oracle seed may affect primary requests. Report original and transformed request text. This is an experimental adapter, not a change to the production query API.

Graph-specific diagnostics may use explicit source-labelled seeds but must be reported separately from end-to-end retrieval. Investigate actual neighbors and graph-added returned hits. Rich-card and lean TOC payload comparisons preserve ranking and source locators, but have different information density; token savings do not prove equal answer quality.

Directed KG adapter (additional tuning ablation): detect `does SYMBOL call` as outgoing or `calls SYMBOL` as incoming using question text alone. Resolve up to three lexical results whose function_name exactly matches SYMBOL, traverse one CallsFunction hop per distinct qualified seed, sort neighbor chunk IDs within lexical seed order, deduplicate, and return at most ten. Materialize exact chunk IDs through paginated corpus reads. All adapter requests are included in end-to-end latency and preserved traces. Unrecognized patterns use the existing graph search; recognized patterns with no graph result return empty (no hidden oracle fallback). The lexical comparison remains normalized lexical retrieval. Report adapter payload separately from intermediate retrieval traffic. Freeze or reject this adapter on tuning before evaluating held-out.

Adapter scores are ordinal ranks 10 through 1, not BM25 relevance or calibrated confidence. This exactly representable encoding preserves scores through the daemon's f32 card schema. An initial directed tuning attempt with fractional ranks failed that identity guard and is excluded; no held-out query was evaluated.

Final routing acceptance rule, recorded before selected-index routing scores and any held-out run: retain definition normalization if exact-symbol top-five hits improve without losses in unchanged question types. Retain direct KG traversal if KG top-five hits strictly improve over normalized graph search and overall top-five hits do not decline, on both baseline and selected tuning indexes. Report all three fixed variants on held-out for attribution; do not retune from held-out results.

Tuning-only efficiency refinement: `directed_seek` preserves the exact same seed selection, graph traversal, ordering and ten-neighbor cap as `directed`, but materializes individual chunk IDs with unfiltered indexed cursor reads (limit=1). It verifies returned IDs exactly and rejects unexpected results. The first adapter's file-prefix pagination fetched unrelated chunks and scanned the corpus. The refined adapter must reproduce its tuning ranks and improve transfer volume before acceptance. Held-out evaluation will compare original, normalized and directed_seek only; no held-out queries have been run as of this amendment.

Final tuning refinement: `directed_name` first asks the graph for the query's bare symbol. The existing graph resolves it only when unique; ambiguous/empty lookups fall back to directed_seek. This avoids an expensive full literal seed scan when the KG already has an unambiguous symbol. Validate only the eight affected tuning KG questions per index (other question routes are unchanged), require identical ranked IDs and lower transfer volume than directed_seek, then freeze. Final held-out comparisons are original, normalized and directed_name over all sixteen questions. No further parameter tuning after that check.
