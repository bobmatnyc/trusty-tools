# Real memory validation: source findings

Read-only source investigation, 2026-09-17. Paths below are relative to `/Users/masa/trusty-search-experiment/worktree`. No private memory/log contents, daemon endpoints, Git mutations, or embeddings were used. Existing query-plan experiment remains unchanged.

## Historical requests

- `crates/trusty-memory/src/prompt_log/config.rs:181` defines RFC3339 event timestamp, hook type, injection kind, palace, verbatim hook stdin `trigger_prompt`, actual injection, counts and duration. Trigger text can instead be SHA256-only. Defaults: 30-day retention, 50MiB rotation; overrides at lines 16–30. Logs live under data_root/logs/enriched-prompts.YYYY-MM-DD[.N].jsonl (`prompt_log/mod.rs:15`).
- `commands/prompt_context/mod.rs:619` parses the JSON envelope's string `.prompt`, otherwise trimmed original payload. Preserve raw input privately and record any extraction. Do not treat notification envelopes as human queries. Exclude automated notifications by fixed envelope rules before running policy, without selecting for supported grammar.
- These are actual user-task requests when originating from UserPromptSubmit, not an exact dump of memory_recall query strings. Recall gets shaped text while KG gets whole user prompt (`commands/prompt_context/mod.rs:456`, `:496`). Log contains shape metrics, not the shaped text. Calling these “reconstructed prompts” would also be wrong when exact `.prompt` is available; label them historical hook prompts.
- Logs are not selected only for successful injections: missing socket resolution logs empty output (`:426`), completed empty compositions are logged (`:517`). However outer BODY_DEADLINE cancellation can abort before logging (`:314`); logger is best effort and configurable. Therefore this is a retained-hook sample, not all user requests. Timestamp is log construction time, not authoritative original submit time.
- `crates/trusty-common/src/memory_core/analytics.rs:98` RecallEvent has palace_id, query_hash, layer, drawer_id, score, occurred_at. Only normalized FNV64 query hashes persist; raw text cannot be recovered from recall.redb. Do not claim that telemetry proves exact historical query text.

## Corpus and safe extraction

- Canonical drawer content and graph rows share `<palace>/kg.redb`, not individual drawer JSON. `store/kg_store.rs:71` DRAWERS keys are UUID bytes and values postcard DrawerRecord. Fields at `:343`: room_id, content, importance, tags, source_file, created_at_ms, drawer_type, expires_at_ms, completed_at_ms, fact_key. No full source revision history or last-verified timestamp exists here.
- TRIPLES (`store/kg_store.rs:27`) keys encode subject/predicate/object; postcard TripleValue carries object, valid_from_ms, valid_to_ms, confidence, provenance (`:327`). History rows have `hist:` prefix plus 8-byte suffix (`store/kg_redb/read_ops.rs:435`). Repeated identical assertions and drawer overwrites do not provide a complete event journal; deletes/TTL pruning lose data.
- Strong read-only API: `trusty_common::memory_core::store::ReadOnlyRedb::open(path)` (`store/concurrent_open.rs:583`, `:603`), then `begin_read()` (`:638`). It opens live O_RDONLY or uses a throw-away recovered copy if writer-locked. Missing file errors. It never writes live data. Public table constants and triple decoders can support a minimal exporter over one transaction.
- `KnowledgeGraph::open` is NOT an equivalent hard read-only guarantee. ReadOnlyClient intent permits direct writable open when uncontended (`store/concurrent_open.rs:49`). `PalaceHandle::open` additionally permits TTL housekeeping. Avoid opening actual live files with either for this experiment.
- On an already-private copy, existing `KgStoreRedb::load_drawers_with_skipped()` (`store/kg_redb/read_ops.rs:273`) handles legacy record decoding and reports skipped drawer count. `dump_all_triples()` (`:416`) exports active and closed triples but silently skips undecodable values/keys. Record raw table counts versus decoded counts and fail rather than silently dropping corruption. Low-level ReadOnlyRedb plus exact legacy decoding avoids copy mutation; reusing store API on a disposable second copy is simpler.
- BM25 JSON (`crates/trusty-memory/src/bm25_index.rs:14`, `:42`) is `{doc_id,text}` array in bm25/bm25_index.json. Useful as a derived-index coverage cross-check, insufficient for canonical timing, room/scope, TTL, or graph provenance. Do not run load_or_create on live JSON: it can quarantine corruption.
- No complete ready-made JSON exporter was found in inspected experiment/scripts paths. Existing Rust experiment helper is useful for offline native BM25/graph evaluation, not source snapshot export.

## Graph provenance and schema mismatch

- Auto triples have provenance `auto:remember`, not exact source spans or drawer IDs (`crates/trusty-memory/src/kg_extract.rs:12`, `:219`). Metadata edges explicitly connect `tag:...`, `room:...`, `topic:...` to `drawer:<uuid>` (`:226`, `:242`, `:257`). Semantic pattern edges connect content entities directly (`:270`), losing direct drawer attribution.
- Actual deterministic extraction emits `is-a`, `works-at`, `uses`, `depends-on` (`kg_extract.rs:325`), whereas synthetic query-plan data uses e.g. depends_on/owned_by. Inventory actual predicates before interpreting coverage. A separately documented deterministic spelling adapter is a storage-schema adapter, not a policy improvement; preserve original predicate and report unsupported predicates.
- Do not invent source fact spans by rendering an existing triple as if copied from its originating drawer. Triple records can be independent graph evidence, with confidence/validity and unresolved source provenance stated. Any later matching to drawer text must be explicitly derived and independently checked.
