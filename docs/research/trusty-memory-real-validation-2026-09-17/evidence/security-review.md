## Observed protections

- Exporter uses `ReadOnlyRedb::open` and one read transaction. Live opening is read-only; writable recovery targets a temporary copy. It does not construct a palace, application state, embedder, or daemon. Row-count/decode failures stop export.
- Exporter creates final output exclusively with mode 0600, prints only counts/digest/copy/version status, and removes its own incomplete final file after a write failure (`memory_snapshot_export.rs:203`, `:207`, `:212`, `:218`, `:224`).
- Compatibility decoding accepts only the canonical current/9/8/6-field postcard shapes with byte-for-byte re-encoding equality (`memory_snapshot_export.rs:76`, `:91`). Legacy tuples match the canonical stored field types/order. Unknown/trailing bytes fail; absent fields and decode versions remain explicit metadata. This does not open writable stores or execute deserialized data. Python carries that metadata only into private prepared/provenance files (`real_adapter.py:143`, `:193`; `real_evaluate.py:281`).
- Final triple-value hardening applies the same exact re-encoding requirement to active and historical `TripleValue` records (`memory_snapshot_export.rs:172`). The existing finite-confidence and key/value agreement checks remain. This narrows accepted input without adding an execution or write path. No new security finding.
- Python resolves and rejects enclosing `.git` paths, exclusively creates mode-0700 directories and mode-0600 files, and rejects overwrite/symlink targets (`real_adapter.py:36`, `:43`). The fixed filenames derive from code, not input content.
- The code parses JSON and typed postcard records. No eval, exec, pickle, unsafe YAML, shell command construction, URL fetching, or model construction was found in the changed files. The inherited helper executes an explicit local executable using an argv list and private pipes, with no shell. The offline tokenizer checks pinned local cache bytes and has no download fallback.
- No credential literals were found by the scoped source scan. All four reviewed files are currently untracked, unignored source/test additions; no secret-bearing file was identified. No secrets baseline was modified.
