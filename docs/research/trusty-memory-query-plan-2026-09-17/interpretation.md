# How to interpret this experiment

## Attribution

The control retains the previously frozen combined policy. The repair arm changes entity handling, relation distinctions, exclusion handling, duplicate charging and its graph candidate lane as a bundle. It cannot establish the contribution of any one repair. The structured arm shares that repaired candidate pool and adds bound directed paths; their difference measures selection behavior on matched candidates. This is not a new embedding ablation or an independent estimate of BM25 versus KG value.

## Relevance and time

Gold required groups assess independently specified answerable evidence. An executor may correctly report a partial request even when every answerable group is present: a second branch can lack the requested stored property. Conversely, an executor's complete status does not prove that the parser understood every part of the original request. Report gold recall and execution diagnostics separately.

Gold forbidden labels include relevant-time but query-incompatible evidence, such as a prohibition with the wrong literal qualifier. Thus the inherited aggregate named safety_violations combines more than temporal/scope safety. Report stale, scope and forbidden totals separately. A negative abstention succeeds only when no task facts are emitted; standing context is allowed within the same token budget.

## Generalization and operational limits

The 32 heldout queries instantiate 16 structures across two families;16 queries contain eight compositions absent from tuning. The corpus and prompts are authored, and the grammar was shared with the fixture author. Unfamiliar supported phrasing remains positive gold. A successful result establishes performance on this bounded test, not unrestricted natural-language understanding.

Prohibition assertions are curated predicates; no claim of extracting semantic polarity from arbitrary source prose is made. Only literal after-HH:MM-UTC qualifiers are supported. Full quoted or supported title-case references are required for reliable boundaries.

Python orchestrates native BM25 and directed eligible postings. The existing helper is a debug build; timings exclude eligibility projection/index construction and do not establish installed-daemon latency. Maintenance is reused unchanged, preserving source clocks and incremental logical records. Native index publication remains a separate production task. No models are constructed and no embeddings are evaluated.

Production code and persisted schemas are untouched. Adoption still needs real-corpus replay, compatible defaults and fallbacks, incremental backfill, bounded maintenance costs and installed-runtime verification under #8246.
