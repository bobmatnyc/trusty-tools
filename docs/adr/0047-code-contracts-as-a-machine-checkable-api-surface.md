# ADR-0047: Code Contracts are a machine-checkable part of the public API

- **Status:** Accepted
- **Date:** 2026-08-15
- **Deciders:** trusty-tools maintainers
- **Issue:** #5724
- **Supersedes:** none
- **Related:** [ADR-0029](0029-msrv-1-94-and-edition-policy.md) (release gates),
  PR #5723 (the type differ this builds on),
  [DOC-38](../specs/spec-linked-documentation.md) (SLD — evaluated as a vehicle
  and rejected; see "SLD is not the right home")

## Context

Three things can change about a published function. Two of them are caught.

| What changed | Caught by | Since |
|---|---|---|
| The item stopped existing, or changed kind/arity | `cargo-semver-checks` | always |
| A type moved under an unchanged shape | `scripts/check_semver_types.sh` | PR #5723 |
| **Behaviour changed under an unchanged signature** | **nothing** | — |

The third gap is not a tooling deficiency to be fixed by a better differ. It is
a category boundary: the contract does not live in the signature, so no reader
of the signature can see it move.

**The instance on record.** `catchup::session_finder::latest_trusty_mpm_snapshot`
carries a byte-identical signature from trusty-common 0.24.2 through 0.34.0:

```rust
pub fn latest_trusty_mpm_snapshot(project_dir: &Path, session_id: Option<&str>) -> Option<PathBuf>
```

Its precondition inverted in #5272. Passing `None` for the session id used to
mean "give me the newest snapshot overall"; it now means "the caller did not
identify itself, so nothing is attributable to it" and returns `None`. Under the
old one-session-per-checkout model the fallback was right; once several PM
sessions shared one snapshot store it started handing callers another session's
file. Session `7bd5c27a…` asked and received a snapshot the log attributes to
`2eb72dca…`, with nothing in the response saying so.

Every tool reported clean. The break shipped.

**Why trusty-common first.** It is the crate where this costs the most: 18
in-workspace consumers, 19 crates.io reverse dependencies including six legacy
pre-monorepo names, and 6 of its last 8 releases carried a real break.

## Decision

**A public API item's contract is stated in its doc comment in a parseable form,
extracted into a checked-in artifact, and verified by tests.**

Four parts, each load-bearing:

### 1. The contract is written in a grammar, not prose

Inside the repo's existing Why/What/Test doc pattern, a contracted item carries
one `# Code Contract` block with `Preconditions:` / `Postconditions:` /
`Invariants:` sections and one claim per `- ` line. The full grammar is the
module docstring of `scripts/extract_contracts.py`, which is the parser — so the
grammar and its implementation cannot drift.

`# Code Contract`, not `# Contract`: the shorter spelling already occurs as
ordinary prose in `file_lock.rs`, and the extractor's fail-closed parser found
that collision on its first run.

### 2. The contract is extracted into a versioned artifact

`crates/trusty-common/contracts.json`, checked in, regenerated by
`UPDATE_CONTRACTS=1 bash scripts/check_contracts.sh --crate trusty-common`. A
doc comment a machine cannot read is discipline; an artifact is evidence.

This reuses existing machinery rather than adding a parallel stack. The
public-surface walk, type renderer, and document loader moved out of
`check_semver_types.sh` into `scripts/lib/rustdoc_walk.py`, and both gates now
import them. What counts as "the public surface" — whether a `pub use` of a
foreign item is ours, whether a blanket impl is ours — is a judgement, and two
copies of it would drift silently. The type differ's 13-case selftest passing
unchanged against the shared walker is the evidence the extraction was
behaviour-preserving.

### 3. Contracts are diffed across versions

`bash scripts/check_contracts.sh --diff <baseline.json> <current.json>` reports
every claim added to or removed from an item present in **both** versions. That
is the payoff: run it between a published baseline and a release candidate and
the `latest_trusty_mpm_snapshot` break becomes a listed finding rather than a
shipped surprise.

Claims are compared as sets of exact strings, so a reworded claim reports as a
removal plus an addition. A machine cannot tell a clarification from a change of
meaning, and asking a human to look is the safe direction.

### 4. Every contract is enforced by a test

Per the `contract-driven-testing` pyramid. A contract test must fail if the
CONTRACT changes, not merely if the implementation does — otherwise the artifact
records a promise nothing keeps.
`contract_latest_snapshot_none_session_id_is_none` was verified against a
temporarily restored pre-#5272 implementation and failed with exactly the #5272
symptom: an anonymous caller handed `session-20260809-020000.md`, a snapshot
belonging to another session.

### Fail closed, everywhere

The same rule as the rest of this gate family, for the same reason: this repo has
twice been bitten by a gate reporting success while checking nothing (#5620's
`0 compared` printing `[PASS]`; the type gap #5723 closed). A `# Code Contract`
block that exists and does not parse, zero contracts extracted, an unknown
rustdoc schema, an unknown `artifact_version`, or zero items common to two
artifacts are each a NO VERDICT (exit 3), never a pass. The shell requires a
positive-evidence marker from the extractor before it will report a clean run.

An item WITHOUT a contract is not an error — adoption is incremental. What is an
error is a block that exists and cannot be read, because that is
indistinguishable from a contract silently dropped.

## Scope and order

| Crate | Status |
|---|---|
| `trusty-common` | **Now.** 10 items, selected by measured break history and cross-crate reach |
| `trusty-embedderd`, `trusty-agents-common` | Next — shared libraries with external consumers |
| Everything else | On evidence: when an item breaks behaviourally, it earns a contract |

Selection is by evidence, never by taste. The ranking used here: items that have
actually broken, then cross-crate entry points named by the common-entry-point
rule, then error contracts a caller must reason about.

## What this explicitly does NOT cover

- **Not run on PRs, and not wired into CI.** It needs a nightly rustdoc build
  (~2 min for trusty-common's 42-feature surface). It belongs beside the
  release-time semver gate, and it is not yet mounted there — that is follow-up
  work, and until it happens the gate is manual.
- **No published-baseline artifact.** `--diff` works today against any two
  artifacts, but nothing yet extracts one from a crates.io release, so
  cross-version diffing is manual.
- **Contracts are unverified claims.** Nothing proves the doc block matches the
  code except the test written beside it. A wrong contract with a matching wrong
  test passes. This buys reviewability and cross-version diffing, not proof.
- **Only 10 of ~12,600 public item positions.** Breadth here would be worthless;
  the mechanism matters more than the count, and the rest can be contracted
  incrementally.
- **`#[non_exhaustive]`, enum variants, and struct fields** carry no contracts
  yet. The walker reaches them and the grammar would apply; nothing has needed
  it.

## SLD is not the right home

DOC-38 and `scripts/check_sld.sh` were evaluated first, per the standing
preference for extending existing machinery.

SLD links a source item to a governing SPEC id — it answers "which spec governs
this?" and validates that the referenced anchor exists. It carries no
representation of what a function promises, and its checker resolves references
rather than comparing content across versions. Storing contracts as spec
references would mean inventing a per-item spec id for each contracted function
and writing the actual claims somewhere else anyway.

The convention this DOES follow is the generated-doc-region pattern
(`docs/reference/generated-doc-regions.md`): a generated artifact, checked in,
regenerated by an explicit command, verified by a gate that fails on drift.

## Consequences

**Good.** The third break class becomes mechanically detectable. Writing a
contract forced the ten items' behaviour to be stated precisely, which is where
the `Ok(0)` / `Err` distinction on `count_active_triples` and the
`Ok(None)` / `Err` distinction on `read_daemon_addr` became explicit rather than
implied. The walker is now shared, so the two gates cannot disagree about the
public surface.

**Costs.** A nightly toolchain is required. Editing a contract means
regenerating the artifact, and forgetting fails the drift check — intended, and
friction. Contract claims are prose inside a grammar, so a reworded claim
reports as a change and needs a human to dismiss it.

**Neutral.** The artifact grows with adoption. At 15 entries it is reviewable in
a diff; at several hundred it would need per-item review tooling.
