# Changelog — trusty-code-tui

All notable changes to trusty-code-tui are documented in this file.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

---

## [0.2.0] — 2026-10-10

### Breaking

- Tool calls render as cards in the scrollback: a `⏺ <tool>(<args>)` header, then the result with its line breaks intact, so `read_file` and `cargo test` output no longer collapses onto one line. A call and its result share one card, matched on `ReplEvent::ToolInvocation`'s `id`, and a delegated sub-agent's card stays inside its block (#4596).
- `ChatLine` gained a `tool: Option<ToolCard>` field, so a `ChatLine { role, text }` literal must now supply it. New public items: `ToolCard`, `ReplApp::tool_cards`, and `widgets::tool_card::tool_card_lines`.
- `ReplEvent::ToolInvocation` gained `failed: bool` and `ToolCard` gained `collapsed: bool` and `failed: bool`, so a literal of either must now supply them. The one in-workspace producer (`trusty-code`) is updated in the same change, and 0.2.0 is not yet on crates.io, so no released consumer is affected. New public items: `ToolCard::is_error`, `ReplApp::toggle_last_tool_card` (#4596).

### Added

- A permission prompt blocks the turn until it is answered (#3422): a `permission_requested` event opens a modal prompt naming the tool, the redacted subject and the matched rule; `y` allows once, `a` allows for the session, `n`/Esc denies, and every other key — Enter included — leaves the prompt pending; the answer is relayed to the backend through the new `TuiEngine::respond_permission`, and `permission_resolved` closes the prompt. A relay that fails reopens the prompt with an inline retry line instead of losing it, so the answer can be sent again. Both the request and the decision are recorded in the scrollback.
- `ReplEvent::DelegationStarted`/`DelegationFinished` (with `DelegationOutcome`) and `ReplEvent::AgentOutput` — the engine-agnostic seam for rendering a delegated sub-agent's block, and for streaming output keyed by `(agent_id, turn_id)` so a primary agent and a sub-agent streaming at once no longer interleave into one chat bubble (#7940).
- `ChatRole::Delegation`/`ChatRole::Delegated` and their scrollback rendering: a `▶ <agent> — <task>` header, gutter-prefixed sub-agent output and tool notices, and a `└ <agent> — <outcome>` footer. The status line names the working sub-agent while a delegation is open and reverts when it closes, with no engine push either way.
- `ReplEvent::ToolInvocation` gained `agent_id`, so a delegated agent's tool calls render inside its block instead of at top level.
- `ReplEvent::SplashUpdated` and `ReplApp::splash`: engine-supplied startup splash lines that replace the banner's generic `{banner_title} v{version}` identity row, so a product can state its own launch facts once. Splash rows word-wrap to the banner's right column instead of being clipped. (#8164)
- `text::elide_middle`: shortens a string to a column budget, eliding whole path components so an over-long path keeps its deepest components whole, and falling back to head-and-tail character elision otherwise. (#8164)

### Fixed

- `text::elide_middle` keeps the repository directory name when it shortens a path. A worktree path under `<repo>/.claude/worktrees/<name>` used to lose the repo name at the banner's 54-column budget while leaving columns unused, so the one name identifying the checkout was the first thing dropped; the deepest-components run is now replaced by `…/<repo>/…/<tail>` when it does not reach the repository, and the repo name is the last thing surrendered. (#8205)
- The chat pane no longer clips the tail of any line it wraps. Its height was computed from logical line count while the pane renders through a wrapping `Paragraph`, so a line wider than the pane was under-reserved by a row and ratatui dropped the continuation — at 80 columns the connect line lost `home <path>`, the home directory the launch line exists to name. Height, bottom-pinning and the published scroll cap now all come from ratatui's own `Paragraph::line_count`, which measures through the same wrapper the renderer wraps with, so a double-width CJK glyph, a run of interior spaces and a leading indent each cost what they are drawn at. (#8205)
- The startup banner's pane is now sized for the rows the banner actually wraps onto below 40 columns, and for the blank row drawn after it, so it no longer loses its top rule to a one-row scroll at any width; what a short terminal cannot show is still scrolled away. It is built at a floor of 40 columns, so every row wraps below that, and the pane was sized by counting its lines — a count that also omitted the blank row drawn after it. Both the banner and the chat are now sized by the one measurement of what the pane actually draws. (#8205)
- Cancelling a turn now shows `cancelling…` until the backend confirms the run has stopped, instead of printing `cancelled` and reopening input on request. A prompt typed during that window queues in the composer exactly as it does during a live turn, so it can no longer reach a daemon that still has a task running — the `-32003 already has a task running` error the operator used to see (#8207).
- A backend that answers "accepted, but not stopped yet" renders as a plain `still cancelling` sentence and keeps input closed; a cancel that fails to land renders as `cancel failed` and never claims the run stopped. No cancel path prints a JSON-RPC code.
- `TuiEngine` gains `cancel_session_reply`, defaulted over `cancel_session`, so an engine with a one-state cancel needs no change.
- the scrollback permission line folds a multi-line subject the same way the boxed prompt does, so a multi-statement `bash` command no longer renders as `echo oneecho two` (refs [#8237](https://github.com/bobmatnyc/trusty-tools/issues/8237))
- Enter pressed while a turn is in flight now records the newline it stands for instead of being dropped, so type-ahead queued across several lines submits byte-identical to what was typed rather than welded together (`echo twoecho three`); the composer shows each queued break as `⏎` (refs [#8240](https://github.com/bobmatnyc/trusty-tools/issues/8240))
- the event loop applies every event already queued behind the one it received before redrawing, instead of one full frame per event — a streaming turn no longer outruns the render path and leaves the pane minutes behind the daemon (refs [#8240](https://github.com/bobmatnyc/trusty-tools/issues/8240))

### Changed

- ratatui and crossterm moved from local `0.30`/`0.29` pins to `{ workspace = true }` (#2872). This crate adopted ratatui 0.30 ahead of the rest of the workspace in slice 2 (#3414), which put two ratatui majors in the build graph by design; the workspace pins are now 0.30/0.29, so that migration window is closed and there is one ratatui major. The resolved versions are unchanged, so no `trusty-code-tui` source changed.
- A completed tool-call card collapses to a one-line summary — `⏺ read_file(src/lib.rs) · ok · 3 lines` — instead of printing its whole result body into the scrollback. **Ctrl-O** expands or collapses the newest card, and `/help` now lists it under a `Keys:` section. No duration is shown: `ReplEvent::ToolInvocation` carries no timing, and timing the TUI's own event arrival would measure the wrong thing (#4596).
- A card the backend reported as failed renders expanded with a red glyph, so the error text never needs a keystroke to read. That verdict is read from `ReplEvent::ToolInvocation`'s new `failed` flag, never from the result text: the `FAILED: ` / `ERROR: ` prefixes trusty-code writes are display text, and rewording them no longer changes how a card renders (#4596).
- Up/Down arrows walk the whole session's prompt history in the input line, instead of Up recalling only the single most recent submission and Down doing nothing. Up steps older, Down steps newer, and stepping past the newest entry hands back the draft that was in progress. Consecutive duplicate submissions are stored once (readline's `ignoredups`). The input is a single line, so readline's "history only from the first/last line" rule is satisfied unconditionally — Up/Down are always history. History is per TUI process: persisting it across launches would need a store this crate cannot reach (it must not depend on `trusty_common` and owns no state directory), so a product that wants cross-launch history seeds `ReplApp::history` at construction (#8181).

### Documentation

- `text::elide_middle`'s stated guarantee now matches its behaviour: the whole-trailing-components promise holds when `…/` plus the last two components fit the width (the prefix costs two columns of the budget), and a width of 0 still yields the one-character `…`. (#8205)

## [0.1.1] — 2026-09-02

### Added

- Full line-editor keymap + Ctrl-C daemon cancel (Slice 5, closes #3417, part of epic #3411, DOC-50 §5 Slice 5): `crate::run::run` now drains `ReplApp::pending_submit`/`pending_cancel` after every `apply` call and dispatches them to `TuiEngine::handle_input`/`cancel_session` on spawned background tasks (`crate::run::dispatch_pending`, private), so the reducer state Slice 4 staged actually reaches the engine — nothing did this before. `TuiModel` gained three defaulted methods (`take_pending_submit`, `take_pending_cancel`, `on_cancelled`) so `event_loop` itself stays engine-agnostic and `TestBackend`-testable; only `run`'s wrapper needs them. Ctrl-C now provably reaches `engine.cancel_session()` — the acceptance criterion this slice exists for — verified by a `MockEngine`-backed test driving the real reducer end-to-end. A new `ReplEvent::Quit` variant relays an engine's `handle_input` `Ok(false)` back into `ReplApp::quit`, since the spawned dispatch task can't reach `&mut ReplApp` directly. Also fixed a keymap parity gap the audit caught: Ctrl-D now only quits on an EMPTY input buffer (tagent's real `crates/trusty-agents/src/repl/tui/keys.rs` behavior — an earlier revision quit unconditionally, silently discarding unsaved input on a stray Ctrl-D). Every other binding (Ctrl-a/e/u, Up/Down, Home/End, Backspace, PageUp/PageDown, Enter) was already at full tagent parity as of Slice 4; this slice only completed the audit and wired the dispatch, it didn't invent line-editing features tagent itself lacks (no Ctrl-w word-delete, no kill-ring, no word-motion — full parity means matching tagent, not exceeding it). `crate::run` split into `run/mod.rs` + `run/tests.rs` (mirroring the existing `app/reduce.rs` + `app/reduce/tests.rs` precedent) to stay under the 500-SLOC production-file cap after the new dispatch code and tests landed.

  **Concurrency hardening (post-review fixes on PR #3477, closes two HIGH + two MEDIUM findings):** a code-critic pass on the initial dispatch implementation found a real double-submit corruption path — nothing prevented a second turn from starting while one was still streaming, so a second `handle_input` task's chunks could splice into the first task's orphaned `streaming_idx` entry. Two fixes close it at the source: (1) `ReplApp::submit_line` now refuses to start a second turn while `Self::busy` is `true` (DOC-50 §5 Slice 5's "blocks user input until cancel completes", implemented literally rather than reasoned away — the Enter-key path additionally checks `!busy` BEFORE consuming the input buffer so a blocked submit doesn't lose the user's typed text); (2) every submitted turn is now tagged with an incrementing generation number (`crate::run::Generation`) and routed through a private per-turn channel + a small forwarder task (`crate::run::forward_while_current_generation`) that only relays events onto the real channel while the generation still matches — closing the second race where `JoinHandle::abort()` only takes effect at the aborted task's next `.await`, so a chunk already queued before a Ctrl-C cancel would otherwise still render as a phantom reply. Neither fix touches `TuiEngine`'s signature or `ReplEvent`'s public shape. Also added to `crate::app`'s disclosed-differences list: Ctrl-C-as-cancel is a deliberate, spec-mandated improvement over tagent (whose real Ctrl-c only clears the input buffer; tagent's cancel trigger is Up-arrow), not an accidental deviation.

  **Stuck-`busy` deadlock fix (second re-review round on PR #3477, closes one HIGH the concurrency fix itself exposed):** the busy-gating fix above meant `ReplApp::busy` staying `true` forever now permanently bricks input, not just shows a stale spinner — and `ReplApp::busy` is cleared ONLY by a terminal `AssistantOutput { done: true, .. }` reaching the reducer. Three real, spec-required `CodeEngine` paths return `Ok(true)` from `handle_input` without ever sending one (`/workstream list`/`activate`, a reconnect-exhausted event pump, a daemon-initiated session cancellation — all of which only push `StatusMessage`/`WorkstreamUpdated`), so any of those left input permanently blocked, recoverable only by the accident of Ctrl-C's reset. Fixed at the dispatch layer, the shared contract every `TuiEngine` (including tagent's future `AgentEngine`) is subject to, not by trusting each engine to remember to self-terminate: `forward_while_current_generation` now tracks a `saw_terminal` flag, flipped whenever it relays an `AssistantOutput { done: true, .. }` or `Quit`; `dispatch_pending`'s completion step drops its `turn_tx` clone and awaits the forwarder to fully drain, then — only if `saw_terminal` is still `false` — sends a new dedicated `ReplEvent::TurnFinished` that clears `busy`/`streaming_idx` and touches nothing else (deliberately NOT a reused empty `AssistantOutput { done: true, .. }`, which would push a stray blank chat entry). The `Err` completion path also now goes through this same drain-then-check sequence for consistency. Net invariant: every `handle_input` completion path — `Ok(true)` with a done chunk, `Ok(true)` with none, `Ok(false)`, and `Err` — deterministically leaves `busy == false` once no task is in flight. `TuiEngine::handle_input`'s doc comment now states the `tx`-lifetime contract this relies on (implementations must not retain a `tx` clone past the call's return) and clarifies that engines are NOT required to send a synthetic terminal chunk just to clear `busy`.

  **TOCTOU race fix (third and final re-review round on PR #3477, closes one HIGH the stuck-`busy` fix itself introduced):** the stuck-`busy` fix's completion step originally compared `generation.load(..) == my_gen` on the spawned completion task before deciding whether to send `TurnFinished` — a genuine check-then-act race under multi-threaded tokio, since nothing synchronized that load against a concurrent cancel + resubmit both bumping the shared counter in the gap before the send. A stale `TurnFinished` from turn N could land after a newer turn N+2 was already in flight and clear its `busy`/`streaming_idx`, reintroducing the streaming-splice corruption class this whole PR closes. Fixed by construction rather than narrowing the window: `ReplEvent::TurnFinished` now carries its own `generation: u64`; the completion task always sends it (no load-then-branch); `TuiModel` gained `set_current_generation`, called by `dispatch_pending` on the single serial event-loop task at the exact point it bumps the shared counter (both the cancel and submit branches); and the reducer's `TurnFinished { generation }` arm applies the reset ONLY if `generation == ReplApp::current_generation` — a comparison that now runs serially on the same task that writes `current_generation`, with no cross-thread race possible. Added a deterministic reducer-level regression test (`apply_turn_finished_with_stale_generation_is_ignored`) proving a stale `TurnFinished` is a no-op once a newer generation is live.
- Slash-command framework with mixed routing (Slice 7, closes #3420, part of epic #3411, DOC-50 §5 Slice 7 / §6 Q4): new `commands` module. `commands::route` classifies a submitted line as `Route::BuiltIn` (`/help`, `/clear`, `/quit`/`/exit` — never reach `TuiEngine::handle_input`) or `Route::Forward` (everything else — domain commands, plain chat, and unrecognized slash commands alike, per the thin-client axiom: the shared crate never rejects a command, only the engine can). `ReplApp::submit_line` calls it directly (no engine handle needed — the built-in table is fixed) so both the Enter-key path and a synthesized `ReplEvent::Submit` (e.g. a picker confirmation) get built-in short-circuiting for free; a built-in never sets `busy`/`pending_submit` since nothing is forwarded. `commands::resolve_forward`/`dispatch_forward` add the DOC-50 §3.2/§6 Q6 inline-picker half: a bare `/name` (no args) matching `TuiEngine::picker(name)` opens `ReplApp::active_picker` instead of forwarding; `commands::compose_selection` composes the `"{dispatch_command} {selected.id}"` resubmission on confirmation, and `ReplApp::confirm_picker_selection` applies it. The picker WIDGET (visual navigation/rendering) is intentionally minimal — a follow-up slice owns the overlay; this slice's scope is routing correctness. Coverage: 137 tests in this crate (23 new).
- App state + widgets (Slice 4, closes #3416, part of epic #3411, DOC-50 §5): the `app` module ships `ReplApp` (the render/reducer model `run::event_loop` drives — chat scrollback, input editor, history, scroll, banner/statusline/command data) plus `app::apply`, a reducer wiring every `ReplEvent` variant to a state transition so the widgets are drivable end-to-end, not just paintable. `widgets::scrollback`, `widgets::banner`, and `widgets::input_composer` are generalized ports of tagent's `repl/tui/{chat,banner}.rs` (`crates/trusty-agents/src/repl/tui/`). `widgets::status_line` is new: it renders `crate::model::StatuslineSegment` (plus the new `StatuslineEmphasis` style hook, see below) instead of tagent's `status.rs`, which was NOT migrated because it hardcodes an OpenRouter pricing formula. `render::markdown` is a verbatim, already-engine-agnostic move of tagent's `markdown.rs`. `layout::draw` composes the widgets into one frame. `text` holds the two pure blank-line-trimming helpers shared by `ReplApp::push_assistant` and the streaming reducer. Coverage: 32 → 116 tests in this crate (tagent's own `repl/tui` test suite — 101 tests — is untouched; this slice does not delete or modify anything under `crates/trusty-agents/`, per DOC-50's atomic-cutover requirement, Slice 10).

  **Disclosed behavioral differences from tagent** (the full list this slice's review round required — Slice 10 plans against it; see `crate::app`'s module doc comment for the authoritative, longer version):
  - **Ported faithfully** (verified against tagent's real `keys.rs`, not its doc comments): Up-arrow recalls `ReplApp::last_prompt` and, while `ReplApp::busy`, also signals `pending_cancel` (NOT the multi-level `history_prev`/`history_next` dead-code browser tagent's own doc comment misattributes to production); Down-arrow calls `history_next()` exactly as tagent's real handler does, even though this is a no-op in both crates today; Ctrl-E pastes only the first non-blank line of the last cached shell block into an empty buffer; the input composer's right-aligned `[thinking...]` label renders whenever `busy` is true regardless of buffer contents, and `busy` is now set `true` at Submit (not on the first streamed chunk), closing the pre-first-token latency gap.
  - **Deliberately NOT ported**: the three-row animated activity panel (spinner/elapsed-timer/rainbow shimmer) — `busy: bool` is this crate's entire generalization of tagent's `thinking`/`busy_since` pair, with no elapsed-time derivation available; inline token counters and all cost/usage tracking (tokens, daily-cost persistence, the pricing formula — DOC-50 Q9); model/provider pickers and the inline LLM-offered/slash-completion choice list (Phase 2, DOC-50 §5 Slice 7+); `AgentScope`'s User/Project color semantic, replaced by a plain `accent_color` field; the shared `trusty_common::banner` splash art and tagent's fixed banner title/command list, replaced by engine-supplied `banner_art`/`banner_title`/`commands`/`recent_activity` fields; the literal `"[trusty-agents] "` status prefix and idle-hint copy, replaced by a generic `status_prefix` field and hint string.
  - `model::StatuslineSegment::Custom` gained an `emphasis: StatuslineEmphasis` field (breaking change to a Slice-1.5 type with zero consumers outside this crate) and a new `Chrome{text, emphasis}` variant was added, both so a future `AgentEngine` can reproduce tagent's bold-cyan bracket prefix, green success framing, and bold/dim `TM:`/`MPM:` distinction — none of which the original segment set could express.

- Initial crate scaffold (Slice 1, closes #3412, part of epic #3411, DOC-50 §3/§5): the `TuiEngine` trait (`setup`, `handle_input`, `cancel_session`, `subscribe_workstream_events`, `shutdown`) and the `ReplEvent` enum (terminal input, submit/cancel, streamed assistant output, tool invocation, statusline/workstream updates, connection loss, clear-scrollback), generalized from tagent's existing `crates/trusty-agents/src/repl/tui/` REPL event model. Also ships the small shared payload stubs (`StatuslineSegment`, `PickerItem`, `CommandDescriptor`, `WorkstreamSummary`) that Slice 1.5 (#3413) will flesh out. No ratatui/crossterm dependency yet — the terminal layer lands in Slice 2 (#3414).
- `ReplEvent::ToolInvocation` carries an `id: String` correlation field (start/complete pairing for Slice 8 tool cards); `ReplEvent::ClearScrollback` covers `/clear` (DOC-50 §5 Slice 7); `WorkstreamActivationChanged`'s field is named `new_active_id` to match the DOC-48 §5.3 SSE wire event exactly.
- Generalization layer (Slice 1.5, closes #3413, part of epic #3411, DOC-50 §3.2): new `model` module replacing Slice 1's provisional stubs with the spec-shaped, engine-supplied data types. `StatuslineSegment` is now an enum (`SessionId`, `Model{provider,name}`, `Project`, `Workstream{id,name}`, `Cost`, `Custom{label,value}`) instead of a flat `{label,value}` struct. `PickerItem` gained an optional `description`; the new `PickerRequest{title, items, dispatch_command}` generalizes tagent's hardcoded `PickerKind::{Model,Provider}` so an engine can name a picker, supply its items, and supply the command dispatched on selection. `CommandDescriptor` gained `routing: CommandRouting` (`BuiltIn` | `Engine`, DOC-50 Q4's mixed slash-command routing) and an optional `args_hint` for autocomplete. `TuiEngine` gained two defaulted accessors, `commands()` and `picker(name)`, so engines can supply a domain command registry and named pickers without breaking existing/future implementors that don't override them. No product-specific logic (e.g. tagent's OpenRouter cost formula) lives in the shared crate — `StatuslineSegment::Cost` carries a pre-formatted string the engine computes.
- The terminal layer (Slice 2, closes #3414, part of epic #3411, DOC-50 §5): `terminal::TerminalGuard`, a panic-safe RAII guard (alt-screen + raw mode + mouse capture) whose `Drop` restores the terminal on both normal return AND panic unwind — fixing a real bug in tagent's current `run_tui` (`crates/trusty-agents/src/repl/tui/run.rs`), which only restores after the event loop returns normally and so leaves the terminal in raw/alt-screen mode if it panics. Unwind-safety is proven by a `catch_unwind` test against an injectable `TerminalOps` seam (no real TTY required). `run::event_loop` is the terminal-generic (any `ratatui::backend::Backend`, unit-tested against `TestBackend`) 100ms-tick / `mpsc::UnboundedReceiver<ReplEvent>` select loop, generalized from `crates/trusty-agents/src/repl/tui/run.rs::event_loop`; `run::spawn_key_reader` is the dedicated OS thread that blocks on `crossterm::event::read()` so it never parks the tokio runtime, forwarding key/resize/mouse-wheel-scroll events; `run::run` is the opinionated top-level entry point tying `TerminalGuard`, the key reader, and an `E: TuiEngine` + `M: TuiModel` pair together. `keys::translate_key_event` is the `crossterm::event::KeyEvent` → Slice 1's crossterm-free `KeyInput` translation boundary, unit-tested for every mapped `KeyCode` variant plus the `Other` fallback and ctrl/alt/shift modifier decoding.

This is a deliberate, crate-scoped divergence from the rest of the workspace's ratatui 0.29/crossterm 0.28 pin — see the dependency comment in `Cargo.toml`. ### Fixed

- **`WorkstreamActivationChanged { new_active_id: None }` now clears `ReplApp::active_workstream` (Slice 6, closes #3418, part of epic #3411).** The reducer previously treated this event as an unconditional no-op for every `new_active_id` value, on the assumption that a follow-up `WorkstreamUpdated` always supplies the display name. That assumption doesn't hold for deactivation: `WorkstreamUpdated`'s payload is a concrete `WorkstreamSummary`, so it can never represent "no active workstream" — a deactivation left the status line showing the stale, no-longer-active workstream indefinitely. The `Some(new_id)` case is unchanged (still a deliberate no-op pending the engine's `WorkstreamUpdated`).

- **`ReplEvent::WorkstreamActivationChanged.new_active_id` is now `Option<String>` (closes #3452, part of epic #3411).** The field was non-optional `String`, but the daemon legitimately publishes a `None` activation target when the active workstream is deactivated with no replacement (DOC-48 §4.2/§4.3) — mirroring `crate::events::Event::WorkstreamActivationChanged` in `trusty-code`, which already declares this field as `Option<String>`. The non-optional shape forced `trusty-code`'s Slice 3 consumer to fall back to a free-text `StatusMessage` for that case (PR #3436); this closes the gap found in that review, while `trusty-tui` still has essentially one consumer.
- Every `# Spec References` block names DOC-50 by its repo-root-relative path
  rather than a `../../../` traversal, so the 25 references they declare are
  checked by `check_sld.sh` instead of skipped (#6605). DOC-38 §2.1 permits a
  file-relative path only in a Markdown visible section.

  0.1.0 becomes the first upload (#4713). `trusty-code` depends on this crate
  from production code, and `cargo publish` refuses a crate whose non-dev

  rather than vendor the seam or freeze the registry copy.

  in-crate MIT `LICENSE`, matching how `trusty-code` and `trusty-mcp` ship.
  The license declaration itself is unchanged — `license.workspace = true`,
  which resolves to MIT.

  directory moves from `crates/trusty-tui/` to `crates/trusty-code-tui/`
  (#6311). The Rust path prefix follows: `trusty_tui::TuiEngine` is now
  `trusty_code_tui::TuiEngine`. No item changed name, signature, or behaviour.

  crates.io and stays unpublished until it is ready, so the rename claims no
