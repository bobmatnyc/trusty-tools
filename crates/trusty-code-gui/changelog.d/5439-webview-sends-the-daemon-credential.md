Added

- `get_daemon_token`, the second thing only the native shell can supply. The tcode daemon requires `Authorization: Bearer <token>` on every route since #5439, and the credential lives in a `0600` file a webview cannot read. The command withholds it entirely when `TRUSTY_CODE_URL` names a non-loopback host, so pointing the shell at a remote daemon cannot make it disclose the local machine's token ([#5439](https://github.com/bobmatnyc/trusty-tools/issues/5439))
- `lib/daemon-auth.ts` installs one credential-attaching `fetch` at bootstrap rather than editing ~30 call sites, so a request site added later is authenticated by default instead of by remembering. `openDaemonEventStream` is the SSE counterpart: `EventSource` has no header API, so it exchanges the credential for a single-use ticket and puts that in the URL. In a plain browser tab, where there is no native shell to ask, the credential comes from a `trusty-code.daemonToken` localStorage override — a `pnpm dev` convenience, not a security boundary ([#5439](https://github.com/bobmatnyc/trusty-tools/issues/5439))
