Added
- New crate `trusty-computer` 0.1.0 with two bins, `trusty-computer` (broker and operator CLI) and `trusty-computer-mcp` (#11460).
- `policy`: the allow list for all 56 cua-driver 0.23.2 tools (6 ALLOW, 13 FILTER, 37 DENY) with the spike's argument checks; `invoke_menu` is denied (#11460).
- `redact`: removes every AXMenuBar element and its markdown subtree from a `get_window_state` reply, returns the element tokens that remain, and fingerprints the redacted tree (#11460).
- `audit`: a fail-closed JSONL log, 0600 and fsynced, rotated at 5 MiB, that records argument keys and text lengths only (#11460).
- `journal`: the per-grant `request_id` journal, capped at 4096 entries, that answers a repeated id without re-running the call (#11460).
- `driver`: the line-JSON client for the cua-driver daemon socket, with per-request timeouts; an `isError` tool result is an error, and the daemon's session-ended refusal is matched on its exact 0.23.2 text (#11460).
- `manifest`: the bounded capability manifest for one lease scope (exact pid and window only), written 0600 (#11460).
- `launcher` and `supervisor`: start, stop, restart and rescope one bounded daemon, launched only through LaunchServices on a private socket under the state dir with telemetry and the update check off. Any CuaDriver other than 0.23.2 is refused, a default daemon socket is refused, and the daemon is identified by socket and metadata pid. A read-only call retries once after its session ends; a mutating call is not re-run (#11460).
- `trusty-computer serve --state DIR` runs the supervised daemon for the scope in `DIR/scope.json`; SIGHUP rescopes and SIGTERM stops it (#11460).
- `broker` and `trusty-computer broker --state DIR`: the broker on `agent.sock` and `operator.sock` (0600 in a 0700 state dir, one broker per dir by `flock`), the only caller of the supervisor's private daemon. A peer of another uid, or one whose credential cannot be read, is refused and audited (#11460).
- The call pipeline: `request_id` journal replay, policy verdict and argument filter on the grant's app, grant scope (live, tool granted, window), desktop lease, daemon scope, token gate, audit `forward`, driver call, menu-bar strip, read-back confirmation of every mutating call (`unverifiable` is not confirmed), audit `done`. Every refusal is audited and fails closed (#11460).
- `grants`: per-app grants kept 0600 in `grants.json`, minted only through the operator consent flow; browsers, terminals, Finder, System Settings and password managers need `allow_sensitive`; an unaudited mint is revoked (#11460).
- `lease`: one desktop lease with a FIFO queue across sessions, released on `release`, disconnect, grant end or 120 s without a call; a handoff rescopes the daemon when the scope differs (#11460).
- A daemon locked out by its manifest idle timeout is restarted; a read-only call is retried once and a mutating call is answered `driver_restarted` without being run (#11460).
- The consent flow: `trusty-computer grant <bundle-id> --pid N --window N` opens `/dev/tty` before it contacts the broker (no TTY: exit 3, nothing sent); the broker shows the app, tools, TTL and a six-digit code in an `osascript` dialog run as a separate helper process, and mints only after a confirm and the matching code. Denied, timed-out (enforced by the broker, not the dialog) and failed dialogs, wrong and expired codes refuse. The CLI prints a one-use `tc-` grant code (120 bits, 300 s) that the agent redeems with `connect`; a session reaches only grants it redeemed. Five bad codes in 60 s lock minting or redeeming out (#11460).
- Operator verbs `grants`, `revoke <grant-id>`, `status`, `lease` and `lockout`. The lockout revokes every grant on disk, drops every code, binding and the lease, stops the daemon and exits the broker (#11460).
- Agent ops `grants` (this session's grants only), `disconnect`, `wait` (up to 5 s, keeps the lease) and `refresh` (restarts the daemon on the grant's scope) (#11460).
- `trusty-computer-mcp [--state DIR]`: a stdio MCP server with exactly 20 static `computer_*` tools (no screenshot, pixel, clipboard or `invoke_menu` tool). Each call goes to the broker's `agent.sock` with a `request_id`, a uuid4 when omitted; a broker refusal is an MCP tool error carrying its code (#11460).
- `trusty-computer install-service [--state DIR] [--sign-identity ID | --no-sign]` signs `trusty-computer` and `trusty-computer-mcp` with the team `4JH68XUHC5` Developer ID (identifier `com.trusty.computer`, hardened runtime), checks for CuaDriver 0.23.2, then writes and bootstraps the `com.trusty.computer` launchd job that runs `trusty-computer broker --state DIR`. A failed sign, verify or version check writes nothing; `--no-sign` warns; a `test-seams` build refuses to register. `uninstall-service` boots the job out and removes its plist (#11460).
