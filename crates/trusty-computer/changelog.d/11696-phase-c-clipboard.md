Added
- `computer_clipboard_write` and `computer_clipboard_read` MCP tools (broker tools `write_clipboard`, `read_clipboard`, FILTER), plain text only. Each needs its own grant flag: `clipboard_write` for a write, `clipboard_read` for a read. Neither is a default tool or grantable by its tool name, and the driver's own `clipboard_read` and `clipboard_write` stay DENY (#11696).
- Size cap: a write over 102400 UTF-8 bytes is refused `clipboard_too_large` before the clipboard is touched; a read takes at most one byte over the cap and refuses `clipboard_too_large` before any redaction. A write admits only `text`, so no `image_path` or `file_path` reaches the clipboard; a read of text that is not UTF-8 is refused `clipboard_not_text` (#11696).
- Redaction on read: the value of a secret-named key (`password=`, `pwd:`, `"api_key": "..."`, `AWS_SECRET_ACCESS_KEY=`), the credential after `Bearer` or an `Authorization` scheme, PEM private key blocks, AWS access key ids, provider keys (`sk-`, `ghp_`, `github_pat_`, `xoxb-`, `glpat-`, `AIza`) and JWTs are replaced with `[REDACTED]`. The agent gets only the redacted text and its redaction count (#11696).
- Every clipboard call writes the audit `forward` and `done` lines with the byte count (and the redaction count for a read), never the text. cua-driver 0.23.2's bounded manifest has no clipboard resource, so the broker runs both tools itself through `pbcopy` / `pbpaste` under a cleared environment (#11696).
