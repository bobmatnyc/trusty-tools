Fixed
- A `tga audit` child that outlives its per-repository timeout is now killed with every process it forked, so the sweep records the timeout and moves on instead of waiting for a grandchild still holding the child's output open ([#8783](https://github.com/bobmatnyc/trusty-tools/issues/8783)). The child runs in a process group of its own, and Ctrl-C is still forwarded to it. That group also holds any trusty-analyze or trusty-search daemon `tga` auto-starts during the run, so a timeout now kills those daemons too, and Ctrl-C sends them `SIGINT` followed by `SIGKILL` 250 ms later; the next run starts them again.
- Draining a stopped child's output — the sweep's `tga audit` log and a clone's stderr — is now bounded to 5 seconds, so a process that escaped the kill cannot hold the run open ([#8783](https://github.com/bobmatnyc/trusty-tools/issues/8783)). A clone or `tga audit` run that exited 0 with its output still held open is reported as failed rather than complete, and a failure reason notes when its log was cut off this way.
