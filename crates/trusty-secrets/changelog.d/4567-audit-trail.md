Added

- Credential access audit trail ([#4567](https://github.com/bobmatnyc/trusty-tools/issues/4567), DOC-45 §9, owner Q2): the `trusty-secrets` server appends one JSON line per access to `~/.trusty-tools/trusty-secrets/audit/audit.jsonl` (override with `--audit-log` or `ServerSettings::audit_log`; deliberately no environment variable), discriminator `"stream": "credential_access"`. `secrets.set` and `secrets.delete` write one record per call, allowed or denied; `secrets.copy` one per key; `secrets.list` only when denied; `scopes` and `doctor` none. The new `server::AuditRecord` holds typed fields only (`ts`, `method`, `decision`, `reason`, `vault`, `key`, `backend`, `project_root`, `caller_pid`) and never a value. The log is 0600 in a 0700 directory, refused on a symlink, a wider mode or another owner, synced before each reply, and rotated to `audit.jsonl.1` at 8 MiB when next opened. The log is opened before an allowed `set`, `delete` or `copy` touches a backend; if that fails, the call changes nothing and fails with the new `audit_unavailable` (code -32072). If the record cannot be written after the backend call succeeded, the change stands and the call still fails with `audit_unavailable` (its text says the change may already have been applied), and `copy` stops before its next key. A denial is still answered with its own kind. A torn last line is ended with `\n` before the next record, and the directory is synced after the log is created or rotated. Only the untracked machine config can turn the audit off (`secrets.audit: false`); a tracked project config that tries is refused with the new `tracked_audit_refused` (code -32073).
