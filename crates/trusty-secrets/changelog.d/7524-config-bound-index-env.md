Security
- A tracked project config `.trusty-tools/trusty-secrets.yaml` that is a symlink, a FIFO, a directory, a device or larger than 64 KiB is refused with `SecretsError::Config` (`config_invalid`) before a byte is read, and the read stops at 64 KiB + 1 bytes ([#7524](https://github.com/bobmatnyc/trusty-tools/issues/7524)). Before, a cloned repository could track that path as a symlink to `/dev/zero` or as a FIFO and hold a server thread and its connection forever. The machine config gets the same type and size checks and may still be a symlink. A config that is not UTF-8 is now `config_invalid` rather than an I/O error. New: `store::config::MAX_CONFIG_BYTES`.
- `TRUSTY_SECRETS_INDEX_DIR` no longer moves the names index of a server on the default socket ([#7524](https://github.com/bobmatnyc/trusty-tools/issues/7524)). The on-demand client passes the caller's environment to the server it starts, so one caller could move the index for every client of the shared server. A server whose socket is in another directory still reads the variable, and `--index-dir` still works on any socket. Any socket in the default socket's directory counts as the default, whatever its file name and however the directory is spelled: another letter case, a relative path, `.`, `..`, repeated `/`, or a symlinked directory. With `$HOME` unknown, or a socket directory that cannot be checked, the variable is ignored.
