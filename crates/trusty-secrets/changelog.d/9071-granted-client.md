Added
- `trusty_secrets::granted`, the tier-3 client (DOC-74 S9): a process `tm secrets exec` started reads one granted value with `granted::resolve(&key)` or a `GrantedClient`. It reads the grant token from the fd named by `TRUSTY_SECRETS_TOKEN_FD` without blocking, puts the token back on the same fd number so child processes share the grant, refuses a socket whose directory is not 0700 or which is not 0600 and owned by this user, and waits 135 s, the server's resolve deadline plus its client margin. It resolves only: it never grants, revokes or starts a server. Every failure is a typed `GrantedError`; a refusal carries the wire code and kind. Unix only, blocking, under the existing `api` feature, which now also enables the already-optional `serde_json` and `libc` (Refs #9071).
- The grant reaches the reading process and its own descendants, not siblings: a sibling of an earlier reader finds the token pipe drained and fails closed with `GrantedError::InvalidToken` (Refs #9071).
- `trusty_secrets::api::TOKEN_FD_ENV`, the one name for the variable that carries the grant token's fd number (Refs #9071).
