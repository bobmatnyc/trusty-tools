Added
- The `trusty-secrets` server keeps the values `secrets.resolve` reads from 1Password or Keeper for the rest of its session, so a second resolve of the same key does not run `op` or `keeper` again or ask for another unlock. Keychain and file values are never cached, and neither is a failed read. The grant, ancestry, agents-flag and audit checks still run on every call; a cache hit skips only the backend read, and a one-shot grant is spent by a hit as by a read. Entries are keyed by backend, vault and key, and `secrets.set`, `secrets.delete` and `secrets.copy` evict the key they write (#7520).
- A cached value is dropped when the backend's section of the account machine config changes, or when that file changes at all (by a stat fingerprint), so a value read under one 1Password or Keeper account never answers under another, even if the file is switched and switched back while a backend opens (#7520).
- A cached value is never served once it is 600 s old, even on a busy server; the next resolve reads the backend again. `trusty-secrets serve --cache-max-age-secs N` sets the max age, and `TRUSTY_SECRETS_CACHE_MAX_AGE_SECS` can shorten it but not lengthen it. A value changed outside the server is seen once its entry reaches the max age or the server exits (#7520).
