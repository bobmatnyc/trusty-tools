Changed
- An Architect session's instructions are now `instructions/architect/architect.md`, then the owner's `AGENTS.md` from the Architect project root under `## Owner overrides (AGENTS.md)`, then `instructions/architect/core.md` last, so no override can displace the core. `AGENTS.md` is read bounded (64 KiB), as UTF-8, and never through a symlink; a file tm refuses is named in the prompt and not applied. A PM never reads `AGENTS.md`. A content release without `architect.md` still gives the Architect the eight legacy supervisor sections, with no `AGENTS.md` (#8436).
- A content source that carries only one of `architect/architect.md` and `architect/core.md`, or an empty one, is refused at load and the error names the file, instead of launching an Architect without its core (#8436).
- The `tm doctor` `session_profile` row now names, for an Architect, its instruction source and content origin and the `AGENTS.md` state, and warns on a refused or unapplied `AGENTS.md`, a core rule the content lacks, a `CLAUDE.md` that `@`-imports `AGENTS.md` or `ARCHITECT.md`, or leftover PM marker blocks (#8436).
