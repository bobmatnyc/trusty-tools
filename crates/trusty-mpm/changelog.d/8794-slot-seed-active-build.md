Fixed
- Builder-slot seeding no longer deletes a slot directory that a running cargo build is using. The seed checks the cargo `flock`s in the slot (`<profile>/.cargo-lock` and the newer build-dir locks), before the clone and again before the replace. It refuses while any lock is held and leaves the slot as it was. A lock file left behind by a finished build does not block the seed (#8794).
- A failed seed no longer writes a marker that reads as seeded. The marker now carries a `status: seeded` line and is written only on success. A failed clone or replace leaves the slot unseeded for the next attempt and records the error in `.slot-<n>.seed-failed` beside the slot. A pre-#8794 marker holding failure text, such as `ColdDirectory("could not replace ...")`, is treated as unseeded and is replaced by the next successful seed (#8794).
- The daemon log now records every slot replace attempt and its outcome: `seeded`, `refused-active-build` with the held lock, or `failed` with the error (#8794).
- The daemon no longer admits a builder into a builder slot that has not been seeded. An admission takes a free seeded slot. When none is free, the builder is admitted without a slot, one seed of the lowest free slot runs off the claim path, and the notice names that slot and the previous seed failure, if any. A seed refused for a running build is now recorded like a failed one (#8794).
- A builder slot handed to a new holder no longer serves the previous holder's builds of the repo's own crates. The handover removes those crates' cargo fingerprints under the slot's build locks, keeps the registry dependency cache warm, and records the new holder in the slot marker. A slot that a running cargo build holds is not handed out (#8794).
- A builder-slot handover no longer deletes the previous holder's fingerprint files inside the claim that the dispatch hook waits on. It moves each of the repo's package fingerprint directories into a `.trusty-invalidated` trash tree in the slot, and the daemon deletes that tree after it answers. On a real slot (about 2,300 package directories, 25,000 files) the claim-path step fell from 0.7-2.9 s to 0.3-0.4 s. A trash tree left by an interrupted delete is deleted at the slot's next handover (#8794).
- A handover whose checkout has no `Cargo.lock`, an unreadable one, or one that names no path package now fails and hands out no slot. Before, it invalidated nothing and still recorded the new holder (#8794).
- The daemon no longer seeds a new builder slot at or above the builder ceiling. Before, when the seeded slots kept failing their handover, each admission cloned one more slot (#8794).
- A symlinked `.fingerprint` directory in a slot is no longer followed during a handover, and the "cargo holds a lock" error no longer says "refused to seed" when a handover refused the slot (#8794).
