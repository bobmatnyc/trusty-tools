Fixed
- tm now removes, once, the sandbox keys and list entries tm 1.14.14 and 1.14.15 wrote into a project's `.claude/settings.json`. At the next launch it deletes only the keys whose value still equals the workspace's `.trusty-mpm/sandbox-roles.json` record, keeps every other key and every entry you added, then records `.trusty-mpm/sandbox-cleanup.json` and never writes that file for sandbox reasons again. A workspace whose `.claude/settings.json` is absent gets the marker too, so a file you write there later is never cleaned. A symlinked `.claude/settings.json` is skipped with a warning naming it, and no marker is written, so the link is kept. A workspace with no record is not touched; a failed cleanup is logged, does not stop the launch, and is retried on the next launch (#12077).
