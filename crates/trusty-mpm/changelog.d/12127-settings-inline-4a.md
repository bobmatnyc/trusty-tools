Changed
- tm no longer writes `outputStyle`, the Architect `model` pin, `autoMemoryEnabled: false` or the stack-profile `skillOverrides` into `<workspace>/.claude/settings.json`. Each launch carries them on its one `--settings` payload instead, so they reach only the sessions tm starts; a bare `claude` in the project no longer picks up tm's output style or skill list. A value you set in `settings.local.json` (or, for `model` and a `skillOverrides` entry, in either project file) still wins, as before (#12127, #12077).
- At the next launch tm removes, once, the values of those four keys that earlier releases wrote into `<workspace>/.claude/settings.json`: `outputStyle` equal to the launch's style, `autoMemoryEnabled: false`, a `model` equal to tm's own record of it, and each `skillOverrides` `"off"` entry tm's stack table names. Any other value stays and is logged; a file holding none is never rewritten; a symlinked file is skipped. A rewritten file is saved with its keys sorted (#12127).
- A launch whose launch-settings record cannot be read or written, or whose `--settings` file carrying those keys cannot be written, is now refused instead of starting without them (#12127).
- The launch-key record (`.trusty-mpm/launch-settings/<hash>.json`) and the one-time cleanup marker (`.trusty-mpm/launch-keys-cleanup.json`) that a launch writes into the checkout are now in the repository's `info/exclude`, so they no longer show in `git status`, and decommission and `tm session delete --project-dir` no longer count them as unsaved work (#12077).
