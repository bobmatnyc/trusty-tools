Security
- `tm hook --pm-guard` now seals the channel question table, `~/.trusty-tools/trusty-mpm/channels/questions.jsonl`, and its `.lock` and `.torn` files as a trust anchor. No session may write, move, delete or link them, the Architect included, whether or not a channel taint is live; neither bypass variable lifts the rule. A write the guard cannot place, and a table location that does not resolve, are now denied to every session, the Architect included. For the Architect, a target in a directory the guard cannot place is denied only when its name could be one of the table's three files or its last three directories (`.trusty-tools`, `trusty-mpm`, `channels`), so routine writes such as `sed -i … src/*.rs`, `> "$OUT"` and `cp a .` after a `cd` are allowed (Refs #9815, #8433).
- The question table no longer opens on a log or lock that is a symlink, has a second hard link, grants group or other access, or is owned by another user; it refuses with an `Unsealed` error instead of narrowing the mode. The torn-line file gets the same check, so a symlink or a FIFO there refuses the open at once; a FIFO can no longer block the open, and with it every later ask and answer (Refs #9815).
