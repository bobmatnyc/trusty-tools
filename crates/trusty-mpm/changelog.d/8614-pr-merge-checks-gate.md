Fixed

- `tm pr merge` refuses (exit 1), with or without `--auto`, while any check on the PR head has failed, whether or not branch protection requires it, and names each failing check (#8614). It also refuses while a check that GitHub would not hold the merge for is still running: GitHub holds a merge only on required checks, so a direct merge lands an UNSTABLE PR at once and auto-merge fires once the required checks pass, and a later failure would still have merged. It refuses too while no check has registered and the base branch requires none. The required checks are the base branch's `.protection` on `repos/{owner}/{repo}/branches/{branch}`, which answers for an unprotected branch too, plus every `required_status_checks` rule on `repos/{owner}/{repo}/rules/branches/{branch}`. A failed or unparseable read of either refuses the merge.
