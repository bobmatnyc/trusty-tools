Fixed
- The pm-guard hook now refuses any command that names a heavy build (`cargo build`, `test`, `clippy`, `check` and the rest of `builders.heavy_build_commands`) it could not lease, whatever the shape: an unknown runner (`entr cargo test`), a second build in a composed command, a build in a quoted substitution, a build beside a leased nested `$(…)`. A `bash -c` string the rule would refuse is leased whole. It used to let such a build run unleased in the shared target directory (#11886).
- A build whose program word is exactly a remote runner (`$EVO`, `${EVO}`, `evo`, `ssh`, `$S/evo-gate-log`, `${S}/evo-gate-log`, `evo-gate-log`) is not refused, so the EVO gate forms `$EVO cargo test -p <crate>` and `"$S/evo-gate-log" --tag <tag> "$S/evo" cargo test -p <crate>` still run. A build that `make`, `mise run` or a script starts without naming cargo is not affected (#11886).
