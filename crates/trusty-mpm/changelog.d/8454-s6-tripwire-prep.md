Added
- `tm hook --egress-guard` now runs a CTO tripwire on a channel-tainted session's gated tool call once the route policy is ready. A call that lands in, or above, a project dir the channel host config lists is denied with check `egress-channel-sensitive-path`, and one JSON line is appended to `~/.trusty-tools/trusty-mpm/channels/tripwire/trips.jsonl`. It judges `Read`/`Edit`/`MultiEdit`/`Write` `file_path`, `NotebookEdit` `notebook_path`, the `Glob`/`Grep` search root and path `pattern`, and a Bash command's cwd, writes, `cd`/`pushd`/`popd` operands, path words, words holding `$` or a backtick, and literal project mentions, after `..`, symlinks and case folding. A path it cannot place (a bare `cd`, `cd -` and `popd` included), a host config it cannot read and a panic each trip. The record and the deny reason name the matched project dir or a fixed cause, never a word of the command. A record that cannot be written leaves the deny. Every other tainted gated call keeps the `egress-channel-tainted` deny, and a policy that is not ready keeps `egress-policy-not-ready`. A project added to the host config is sensitive with no code change (#8454).
- New `tm doctor` row `tripwire_record`: `Ok` when the tripwire record is absent or empty, `Warn` with the trip count and newest timestamp when it holds trips, `Fail` on an unparseable line, an unwritable record directory or `trips.jsonl`, or a missing directory whose nearest existing ancestor is not writable, `Unknown` when it cannot be read (#8454).
- New gate `scripts/check_tripwire_gate.sh` runs the tripwire tests by name and fails on any failure, zero tests run, or a required test that is missing or ignored; `scripts/check_tripwire_gate_selftest.sh` proves each case (#8454).
