Added

- `tm hook --egress-guard` checks the channel route policy before it refuses a channel-tainted session's path tool call (Read, Edit, MultiEdit, Write, NotebookEdit, Glob, Grep, Bash). The policy loads inline under a 1.5 s wait. A missing, unreadable or unparseable `config.yaml`, a denied load, any finding, a project route file not in effect, an empty policy, a load that times out or panics, and a build without the `channels` feature each deny as `egress-policy-not-ready`, with the reason naming the branch. A ready policy falls through to the existing `egress-channel-tainted` deny, so no verdict loosens. Neither pm-guard bypass variable nor a subagent marker lifts it. An untainted session never loads the policy. `tm doctor` adds an `egress_policy_ready` row judged from the daemon view it already loads. Refs #9741, #8454
