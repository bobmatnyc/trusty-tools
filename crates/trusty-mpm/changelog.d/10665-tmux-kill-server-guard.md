Fixed
- `tm hook --pm-guard` refuses a `tmux kill-server` or `kill-session -a` aimed at the fleet's server — the default server, the server an inherited `$TMUX` names, `-L default`, the `-L` label of the `$TMUX` socket, or any `tm-` server such as `tmux -L tm-ws-y`, with case folded as APFS does (`-L DEFAULT`, `-L TM-ws-1`) — and any `kill-session` on that server that does not name a literal non-`tm-` session (no `-t`, `%0`, `$0`, `@1`, `:`, or a `tm-` session), for every caller under every bypass (policy GP-050, #10665). `TMUX_TMPDIR` alone does not make a kill safe, because an inherited `$TMUX` wins over it. A scratch server stays allowed: an absolute `-S` path, an `-L` label other than those, or `env -u TMUX` / `env -i` with an absolute `TMUX_TMPDIR` other than `/tmp`. Every other finding of this rule is log-only (owner ruling Dac): an `-S` the guard cannot resolve, a kill inside a script the command runs, an interpreter, `ssh` or an alias, and a command the guard cannot read all run, and the guard writes a would-refuse line to `pm-guard-would-refuse.jsonl` beside `pm-guard-denials.jsonl`.
