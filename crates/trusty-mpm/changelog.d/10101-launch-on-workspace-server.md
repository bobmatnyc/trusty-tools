Changed
- A fresh managed PM launch creates its tmux session on its project's private tmux server, named for the project root, so every PM of one project shares one server, and stores that server's socket on the session record; the runtime launch, resume, task injection and reuse checks follow it there. `TM_WORKSPACE_TMUX=0` keeps the default-server launch for one release. Existing sessions and the Architect stay where they are (#10101).
- Resuming a session whose workspace tmux server crashed restarts that server and recreates the pane instead of refusing the resume (#10101).
- Stopping a session on a workspace tmux server reads its `claude` pid on that server, so the stop sends SIGTERM rather than only Ctrl-C (#10101).
- Pane capture, input-box reads and command sends for a daemon-registered session stay on the default tmux server, where those sessions live; the pane-id backfill, the tmux environment heal and the reactivate foreground check use the record's server (#10101).
- A probe of a workspace tmux server is bounded and at most one runs per server at a time: a hung server reads as unknown at once instead of gaining another blocked tmux client on every check, and the by-name lookup behind `tm attach` and a session snapshot refuse rather than block (#10101).
- A session whose workspace tmux server vanished is classified by the server's socket: a socket that is gone (a clean exit, a kill of the last session, `kill-server`) is a deliberate stop and is not auto-resumed; a socket that is still there but refuses connections (a crash) stays auto-resumable, as does any session started before the last host boot. A server that lists only unmanaged sessions is not read as lost (#10101).
- A resumed or auto-relaunched PM on a workspace tmux server has its new `claude` found on that server, so its session id is rebound (#10101).
- The runtime-exit reaper reads each session's panes on that session's own tmux server: a workspace-server PM whose `claude` exits is marked stopped, and a same-named pane on the default server no longer stops it; a server whose panes cannot be listed stops none of its sessions (#10101).
- The orphan GC sweeps every live workspace tmux server, and boot adoption adopts a session found on one with that server's socket (#10101).
- `tm` attach outside tmux attaches with `-S <socket>` to a session on a workspace server; inside tmux, a session on another server opens a new window in the caller's session that runs the attach, and a session on the same server is switched to as before (#10101).
