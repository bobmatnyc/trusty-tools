Fixed
- `tm hook --pm-guard` now refuses `op item get`, `op document get` and `op inject` when their output reaches the tool output (stdout, `-o -`, or `--out-file /dev/stdout`), and refuses `op run --no-masking`. A read captured into a variable or written to a file with `-o`/`--out-file` or a redirect is still allowed, as is `op run` with its default masking. `op item $SUB …`, where the second subcommand word is chosen at run time, is now refused like `op $SUB …`.
- The guard reads the `op` subcommand by position and ignores the words after `--`, which belong to `op run`'s child. `op run --no-masking -- cat read -o FILE` is now refused, and `op run -- npm run inject` and `op item list --vault inject` are allowed. An `op run` whose own words include one known only at run time (`op run $F -- cmd`) is read as unmasked, so it is refused when its output reaches the tool output.
- An `op read`, `op document get` or `op inject` out-file flag (`-o`, `--out-file`) counts as a file write only when it appears once, the word before it is not a bare dash flag that could take it as its value, and its path does not start with `-`. `op read --account -o REF` and `op read REF --out-file F --out-file=` are now refused; `op read REF -o FILE` is still allowed. The same rule applies to `gcloud secrets … access --out-file`.
