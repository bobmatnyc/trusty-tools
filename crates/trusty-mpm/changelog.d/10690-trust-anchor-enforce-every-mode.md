Changed
- `tm hook --pm-guard-shadow` now refuses a trust-anchor write (rule 1) instead of only logging it, in every session profile, and records the refusal in `~/.trusty-mpm/guard/shadow.jsonl` with `"enforced": true`. A call it cannot judge for rule 1 is refused too: unreadable or oversized stdin, non-JSON, no tool name, no home directory, an edit tool with no target path, a Bash command the parser could not walk in full, a project settings file that exists but cannot be read, or an internal panic. The deny is printed before the log write, and a non-regular file at the log path is skipped, so the log never delays a refusal. Rules 2, 3 and 5 still only log. `cargo install`, `tctl install` and the signed install scripts still install `tm` (#10690, owner ruling D0u).
