Fixed
- The #8928 sandbox settings verify now refuses a launch when any tier sets `sandbox.network.allowAllUnixSockets`, `sandbox.network.allowLocalBinding`, `sandbox.allowAppleEvents` or `sandbox.filesystem.disabled` to anything but `false`, or a non-empty `allowRead`; when tm's user-tier settings carry a `sandbox` key other than `network.strictAllowlist` and `credentials` (so a user-tier `allowUnixSockets` can no longer re-add the sccache socket); and when a `permissions.allow` `Edit(...)`, `Write(...)`, `MultiEdit(...)` or `NotebookEdit(...)` rule names a path outside the workspace and the role's `allowWrite` roots. The project policy now pins those four booleans to `false` (#10107).
- `tm hook --pm-guard` protects a hook program in every `PATH` directory up to and including the first one holding it as an executable, and in every `PATH` directory when none does, so a new file earlier on `PATH` can no longer shadow it. Every bare word of a hook command is a candidate (an argument included), words split at shell operators (`true&&prog`), a relative `PATH` entry joins the project root, and an unplaceable `PATH` entry or an unset `PATH` denies the write (#10107).
- The #8454 project-settings and trust-anchor name checks fold names as APFS does, so `.claude/ſettings.local.json` (U+017F) and `conﬁg.yaml` (U+FB01) are denied like their ASCII spellings, including the Architect's question-table rule (#10107).
