Fixed

- pm-guard no longer refuses a quoted here-document append whose body holds a `(` before an apostrophe when a later line opens a multi-line `"…"` string (the Architect's `cat >> local/actions.md <<'EOF'` then `git commit -qm "…"`); the same here-document aimed at a trust anchor is still judged as an anchor write, and a line whose quotes do not close still abandons the scan when a `<<` sits on or after it or an earlier `<<` opened no body (#8878).
- An Architect `claude` started by `tm connect`, `tm launch`, `tm session start`, the daemon client, the daemon's managed spawn and resume, or the GUI "New Session" spawn is now bound with a launch record, as `tm fleet init` and `tm fleet relaunch` already did, so pm-guard recognises it; one that cannot be bound prints (or, in the daemon, logs) a warning naming `tm fleet relaunch`. A start into a session that was already running binds nothing. Every launch record is written by one function, `bind_architect`. `tm run` does not bind yet: it starts `claude` outside tmux, and a session-less launch record is follow-up work (#8878).
