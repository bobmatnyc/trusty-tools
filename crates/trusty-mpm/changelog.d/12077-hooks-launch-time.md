Changed
- tm no longer writes its hooks into `<workspace>/.claude/settings.json`. Every tm launch builds them into its one `--settings` payload: managed spawn, resume and in-place relaunch, `tm launch`, `tm connect`, `tm fleet init`, `tm run`, `tm session start`, the GUI spawn, client connect, the Architect, and the control-plane worker, which now also gets the launch keys earlier slices moved there. The managed `claude-config/settings.json` keeps its hooks. A bare `claude` started outside tm in the project no longer runs tm's hooks (#12077, #12127).
- Each launch removes tm's old hook entries from `<workspace>/.claude/settings.json` and `settings.local.json`, and only tm's: the `tm hook` lifecycle, pm-guard, egress guard and tm's other hook shapes for any tm binary path, plus tm's two `trusty-memory` commands when the same file also carries a tm entry. A `trusty-memory` hook alone, and every other entry, stays. A file with nothing of tm's is left byte-identical (#12077).
- A launch is refused when its hooks cannot be built or written: when no stable `tm` binary resolves, for every profile and not only the Architect, when the payload cannot be written, or when a project settings file exists and cannot be read or rewritten (#12077).
- pm-guard now denies a PM edit, write or Bash write to `~/.trusty-tools/trusty-mpm/session-settings/`, the directory that holds the launch payloads (#12077).
- `tm doctor` drops the `hooks_missing_tm_group` row, and `tm validate --repair` and the daemon's boot reconcile no longer report a missing `hooks` key or rewrite tm's hook groups into the project file. `hooks_contamination` now reports any tm entry in a project file, and `--fix` removes it. `egress_guard` judges the payload a tm launch would carry and the managed tier, and fails when a project settings file sets `disableAllHooks` (#12077).
