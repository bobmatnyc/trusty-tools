Changed
- `tm hook --pm-guard` now refuses an `Agent` or `Task` dispatch from a main checkout whose `subagent_type` is missing, is not a string, is empty, or names an unknown agent, instead of granting it a worktree on a guess. A name is known when it is an agent this `tm` bundles, an agent deployed in any directory the PM's delegation roster reads (`<project>/.claude/agents`, the managed `claude-config/agents`, and the framework agents directory), or a Claude Code built-in (`general-purpose`, `Explore`, `Plan`, `claude`, `claude-code-guide`, `statusline-setup`); matching is exact and case-sensitive. Known names keep their previous behaviour: a reader runs in place and a writer gets a worktree. `claude-code-guide` now counts as a reader. The refusal names the missing or unknown type and the two fixes: set `subagent_type` to a known agent, or dispatch through the `Agent` tool with `isolation: "worktree"`. An agent directory that cannot be read contributes no names and is named in the refusal. A project with `agent_worktree = false` is unaffected (#8547).
