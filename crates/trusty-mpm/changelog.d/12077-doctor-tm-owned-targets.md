Changed
- `tm doctor --fix` writes `autoMemoryEnabled: false` into tm's launch-settings record (`.trusty-mpm/launch-settings/<hash>.json`), which each launch delivers on its `--settings` payload, and no longer into `<workspace>/.claude/settings.json`. The `auto_memory` row reads that record first, so a delivered key is no longer reported as unset. A `settings.local.json` that sets the key to `true` is refused and left for you to change; an unreadable record fails the row and the repair and is not overwritten (#12077, #12127).
- `tm doctor --fix` no longer merges a missing tm hook group into `<workspace>/.claude/settings.json`. The `hooks_missing_tm_group` row still names the gap and the repair step is refused; both say that the project's next tm launch re-renders the group, which restores the guard (`tm hook --pm-guard`), and give the command, `tm launch <project>` (#12077, #12127).
- `tm doctor --fix` adds the interpreter to a bare hook script only in tm's managed config dir (`claude-config/settings.json`). For any other settings file the rewrite is reported as refused and the file is not written (#12077, #12127).
- `tm doctor --fix` adds an ancestor `CLAUDE.md` exclude to `claudeMdExcludes` on the project's launch-settings record (`.trusty-mpm/launch-settings/<hash>.json`), not to the project's `.claude/settings.local.json`. Each `tm launch` in that project passes the record as `--settings`, and Claude Code adds its entries to the excludes the settings files list, so the exclude applies to that project's tm sessions only. A launch keeps the excludes on the record; a record that cannot be read fails the repair step and refuses the launch, and is left as it is. `tm doctor` and the launch warning count an ancestor listed on the record as excluded (#12077, #12127).
- A launch no longer removes `trusty-memory` hooks from `~/.claude/settings.json`; it removes them only from the config dir it sets as `CLAUDE_CONFIG_DIR`, and only a hook group equal, field for field, to one tm wrote. A group you changed in any field stays. A settings file that exists and cannot be read is now an error (#12077, #12127).
- `tm launch` no longer removes tm's old lifecycle hooks from `~/.claude/settings.json` and `~/.claude/settings.local.json`. It prints a warning for each of those files that still holds an entry equal to one tm wrote, naming each entry's file, event and command, or that cannot be read, and leaves the file as it is. The warning gives the removal: `tm hooks clean --path ~` as a dry run, then with `--force`, which backs up first and removes any plain `tm hook` entry, more than the listed ones; or delete those handlers under `hooks` by hand (#12077, #12127).
- `tm validate`, the managed spawn and resume gate, and the `output_style` doctor row read `outputStyle` from tm's launch-settings record first, where a launch now delivers it, so a session launched by this release is no longer reported as missing the key and `tm validate --repair` no longer repairs it on every spawn. A record that cannot be read or parsed is a gap (`tm validate`) or a `Fail` (`tm doctor`) naming the file, never a pass (#12077, #12127).
