Changed
- The daemon now auto-resumes stopped sessions, with the runtime relauncher it installs, so each resume launches and verifies a runtime or records why it could not. Its first sweep runs at daemon start, so a cold start resumes every eligible session without a manual relaunch. The rules are unchanged: the console toggle (`~/.trusty-mpm/auto_resume`) wins, then `TRUSTY_MPM_AUTO_RESUME` in the daemon's environment, then off; deliberately stopped and parked sessions are skipped. The sweep interval is `TRUSTY_MPM_SUPERVISOR_INTERVAL` (default 30 seconds) (#10356).
- `tm supervisor` no longer auto-resumes sessions. `--auto-resume` and `TRUSTY_MPM_AUTO_RESUME` are accepted there and ignored with a warning. If you enabled auto-resume only through the supervisor's launchd environment, set it on the daemon or use the console toggle. The supervisor's `auto_resumed` and `resume_failures` counters now stay at zero (#10356).
