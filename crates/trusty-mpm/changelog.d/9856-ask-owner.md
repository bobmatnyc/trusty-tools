Added
- New `ask_owner` MCP tool and `POST /api/v1/channels/ask-owner` daemon route send one question as a Slack DM to a user a channel route names, with the daemon-held bot token. Only the live managed Architect session may ask: the daemon proves the caller from the calling process the daemon socket reports, so the HTTP route and any other caller are refused. The recipient must be a Slack user id (`U…`). Every refusal sends nothing, writes one line to the channel audit log and names its rule. The question id is reserved before the send and the question is recorded as open before the tool returns; a send whose outcome is unknown (a timeout, a 5xx, or a Slack `fatal_error` or `internal_error` reply) keeps its id reserved and never reuses it (#9856, #8433).
- `tm serve --stdio` sends an `ask_owner` call over the daemon socket, so the daemon can identify the asker (#9856).
