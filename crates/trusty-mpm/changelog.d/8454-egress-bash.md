Added
- `tm hook --egress-guard` now judges Bash commands too. It denies a command that names a Slack, Notion, Gmail or Google Chat host (`slack.com`, `slack-edge.com`, `notion.so`, `notion.com`, `gmail.googleapis.com`, `mail.google.com`, `smtp.gmail.com`, `chat.googleapis.com`, or a subdomain) in any word, an `smtp://` or `smtps://` URL, or an `smtp.*` host on port 25, 465 or 587. It also denies a mail client (`sendmail`, `mail`, `mailx`, `msmtp`, `mutt`, `swaks`), a channel binary (`slack-mcp`, `gchat-mcp`, `gws`, `gworkspace-mcp`) or `tm slack`/`tm gchat` in command position, and a `python*`, `node`, `ruby`, `perl`, `php`, `deno` or `bun` `-c`/`-e` program or here-document that imports `smtplib`. Wrappers (`env`, `sudo`, `nohup`, `time`, `command`, `xargs`, `sh -c`, `eval`), pipes, `$(…)`, backticks, subshells and decoded `$'…'` quotes do not hide the command. The one carve-out is the exact argv `gchat-mcp doctor --offline`. A family word used as an argument (`grep mail f`) is allowed. A command the guard cannot parse is denied only when its text holds a family token, and a Bash call with no string `command` is denied. The deny uses check `egress-bash`. This is a tripwire for the direct forms: a host built from a variable, an encoded payload or a script run by path is not detected (#8454).
