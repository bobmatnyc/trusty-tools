Fixed

- `tm hook --pm-guard` no longer denies a quoted here-document script whose consumer is one of five interpreters that read stdin as their own program text — `python3`, `python`, `node`, `ruby`, `perl`, invoked bare or with `-` and nothing else on the line. The destructive-deletion guard scans a segment token by token for `rm`/`rmdir`/`unlink`/`find`, and since #6946 a here-document body stays inside its operator line's segment, so Python source was tokenized as shell: `python3 <<'PY'` carrying `print('It\'s time to find it')` was denied because the apostrophe unbalanced the segment's quoting and the bare word `find` then matched. Those bodies are now blanked before the token scan, byte offsets preserved. The allowlist is the whole rule: every other consumer — a shell, `cat`, `tee`, `cp /dev/stdin`, a script path, an unknown binary, a path-qualified interpreter, `python3 -c` — keeps its body scanned, as does an unquoted `<<TAG` body, any operator line carrying a redirect, pipe, or second command, and a here-document whose terminator is never found (#7190).
