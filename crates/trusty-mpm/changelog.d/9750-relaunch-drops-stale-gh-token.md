Fixed
- An in-place relaunch of a managed session (bare `tm` in its pane) in an unpinned project no longer passes the pane shell's stale gh token to `claude` when `gh auth token --hostname <host>` resolves a credential in the bound `github.config_dir`, so the session's `gh` uses the live login. The host is `GH_HOST`, else `github.com`; only that host's token vars are dropped (`GH_TOKEN`, `GITHUB_TOKEN` and `GH_USER`, or the two `*_ENTERPRISE_TOKEN` vars for an Enterprise Server). When the bounded probe fails, times out or prints nothing, the inherited token is kept and a warning names the decision (#9750).
