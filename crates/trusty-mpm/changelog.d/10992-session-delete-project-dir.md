Added

- `tm session delete <id> --project-dir` removes the session's project directory. It shows the plan, then needs `--yes` or the typed directory name, then Touch ID or the login password; `--dry-run` shows the plan and deletes nothing. It deletes only strictly inside the managed workspace root (no symlink or `..` escape) and refuses dirty or unpushed work (tm's own provisioning files do not count, exactly as `tm sessions decommission --force` excuses them), an unpushed commit any local branch or tag reaches, or a stash, in a checkout whose `.git` it would delete, gitignored files that are not build output, a running session or live process in the directory, and the Architect's sessions and directory ([#10992](https://github.com/bobmatnyc/trusty-tools/issues/10992))
