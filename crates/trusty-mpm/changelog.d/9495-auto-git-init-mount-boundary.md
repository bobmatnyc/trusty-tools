Fixed
- `tm` and `tm launch` in a plain directory on its own filesystem (for example a tmpfs `/tmp`) initialize git again instead of failing with "cannot tell whether ... is a git repository". git reports `not a git repository (or any parent up to mount point <dir>)` when discovery stops at a mount boundary, and the auto `git init` only recognised the `(or any of the parent directories)` wording (#9495).
- The auto `git init` no longer creates a nested repository inside a real checkout that git could not see. When git says there is no repository but a `.git` exists at or above the directory (an unreadable `.git`, `GIT_CEILING_DIRECTORIES`, or a mount boundary), `tm` now stops with an error that names that `.git`. This changes the classic `(or any of the parent directories)` case on purpose: it used to run `git init` there (#9495).
