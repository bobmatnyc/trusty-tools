Added
- `tm dbatg` (`init`, `add`, `update`, `close`, `batch`, `prune`, `show`), the `mpm.dbatg.init`, `mpm.dbatg.batch` and `mpm.dbatg.show` daemon methods and the `dbatg` MCP tool write and read a PM session's Intent Ledger with the prototype's stdout and exit codes; `tm dbatg` refuses a write to any store but the caller's own known session (`DBATG_SESSION` or its tmux session) with exit 2 before anything is sent, whether the daemon is up or down; writes through the MCP tool are not yet bound to the calling session ([#10153](https://github.com/bobmatnyc/trusty-tools/issues/10153)); when the daemon is down, `tm dbatg` writes in-process under the same lock and, for `init`, only into the daemon's code registry; exit 3 means the outcome is unknown (the daemon may have committed before the reply was lost), and its message names the request id to retry with, since a batch retried with the same `--request-id` is applied once; a daemon that predates `tm dbatg` exits 3 with a hint to run `tm restart` ([#9758](https://github.com/bobmatnyc/trusty-tools/issues/9758))
