Added
- Text the daemon types into a managed session's pane is now one `tmux` `message` event on the trusty-events bus (#9167). This covers every caller of the session inject path: the idle nudge, managed inbound answers, `sm.sessions.send` and the SM chat agent's inject action (including under `tm sm serve --stdio`, which now records on its own producer and flushes at EOF and on SIGTERM or SIGINT), the MCP session proxy, and Telegram and Slack focus mode. Each event is `from` `trusty-mpm` to the session's tmux name, names the receiving Claude session when it is known, and is a child of that session's root event when one was projected (none is, under `tm sm serve --stdio`). It has the same credential scan, byte count, sha256 and opt-in body as the hook-side `message` events. An `Interrupt` (Ctrl-C) records nothing, and neither does an inject refused for a stopped session, a gone pane or an exited harness. A bus that is down never fails the inject: the event stays buffered for the next flush.
- Two more paths that type into a pane record the same way: the answer to a claimed decision, and `send` on the control-plane tmux backend (which names no Claude session, so its event has no parent).
