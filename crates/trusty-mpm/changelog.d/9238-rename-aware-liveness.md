Fixed
- `tm ls` no longer shows a session renamed with `tmux rename-session` as stopped under its old name. The record now follows its own pane id, on the tmux server it was captured on, to the session that holds the pane: the list, get and attach-cmd routes, the 60-second reaper and the boot reconcile rename the record to the current tmux name first, so the row reads live and `attach_cmd` targets a session that exists. A pane tmux cannot find, a record with no server identity, and a pane id on another tmux server are never followed. The reaper and the boot dedup therefore no longer stop or decommission a renamed live session (#9238).
- `tm doctor` has a `session_names` row that warns about each record whose pane is live under another tmux name, including a decommissioned record whose pane still runs, and names the reactivate route for it (#9238).
