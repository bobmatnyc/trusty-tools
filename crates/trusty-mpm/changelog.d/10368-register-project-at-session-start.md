Fixed
- `tm connect` now registers the checkout it starts a session in as a `projects.json` project, keyed by the checkout's path, so `tm secrets assign --project owner/repo` resolves it instead of refusing with "project not registered" (#10368). A start for a project already in the registry reads the file and writes nothing; when that row names a different clone, a note prints both checkouts and the row is kept. Only the session's own git root is registered, after git confirms it as its own top level: never the home directory, a directory above it (also when reached through a symlink), the filesystem root, a linked worktree, or a directory whose `.git` entry git does not accept. A registration failure prints a warning and leaves the project unregistered; `assign` refuses an unreadable registry with a fixed error.
