Fixed
- `tm connect` now registers the checkout it starts a session in as a `projects.json` project, keyed by the checkout's path, so `tm secrets assign --project owner/repo` resolves it instead of refusing with "project not registered" (#10368). A second start writes nothing and never rewrites an existing row. Only the session's own git root is registered: never the home directory, a directory above it, the filesystem root or a linked worktree. A registration failure prints a warning and leaves the project unregistered; `assign` refuses an unreadable registry with a fixed error.
