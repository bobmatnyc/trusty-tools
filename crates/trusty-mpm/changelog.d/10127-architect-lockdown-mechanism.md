Added
- The Architect launch (`tm fleet init`, and `tm launch` / `tm connect` in an Architect directory) can now carry its own `--settings` deny list and drop named chat-token variables from its environment. Both lists ship empty, so every launch, including a GUI "New Session" in an Architect directory, is unchanged until the owner fills them. Once a list is filled: the deny is merged into the owner policy's `--settings` payload when one applies, because Claude Code keeps only the last `--settings` flag; a lockdown that cannot be built refuses the Architect launch; and the GUI "New Session" spawn refuses an Architect, because its typed line cannot carry the payload (#10127).
