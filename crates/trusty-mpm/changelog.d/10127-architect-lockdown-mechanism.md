Added
- Every Architect launch now carries its own `--settings` deny: the MCP tool families `slack`, `gmail`, `googlemail`, `notion`, `googlechat`, `google-chat` and `gchat`, the Google Workspace `mail`, `chat`, `message` and `draft` tools, and the claude.ai connectors (`disableClaudeAiConnectors`). Each glob is also denied with capitalised words. `ask_owner` and the other trusty-mpm tools stay available. The deny is merged into the owner policy's `--settings` payload when one applies, because Claude Code keeps only the last `--settings` flag (#10127).
- An Architect child no longer inherits `SLACK_BOT_TOKEN`, `SLACK_USER_TOKEN`, `SLACK_APP_TOKEN` or `TELEGRAM_BOT_TOKEN`; the list is every Slack and Telegram credential in the credential registry. PM and agent launches are unchanged (#10127).
- The lockdown applies on every Architect launch path except the config-apply restarter, which relaunches an existing pane with a bare `claude` (#2020): `tm fleet init`, `tm launch`, `tm connect`, `tm session start`, `tm run`, the daemon's managed spawn, resume and attach, the in-place relaunch, the daemon client's launch and connect, and GUI "New Session", whose typed line names the payload in a file beside its prompt. A lockdown that cannot be built or written refuses the launch, and a GUI line over the pane's byte limit is refused instead of being cut short. `tm launch` builds its launch before registering the session, so a refusal leaves no session record (#10127).
