Added
- The Architect launch (`tm fleet init`, and `tm launch` / `tm connect` in an Architect directory) can now carry its own `--settings` deny list and drop named chat-token variables from its environment. The deny list and the variable list both ship empty, so launches are unchanged until the owner fills them. When an owner policy file also applies, the deny is merged into that one `--settings` payload, because Claude Code keeps only the last `--settings` flag. A lockdown that cannot be built refuses the Architect launch, and the GUI "New Session" spawn refuses an Architect, because its typed line cannot carry the payload (#10127).
