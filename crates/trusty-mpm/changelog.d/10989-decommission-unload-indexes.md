Changed
- `tm projects decommission` (and the `project_decommission` MCP tool, `POST /api/v1/projects/{name}/decommission`, `mpm.projects.registry.decommission`) now shuts the project's trusty-search index and trusty-memory palace down after its sessions stop, and keeps their data (#10989). The index is parked with `search.project.park {decommission: true}` (unloaded, watcher stopped, corpus kept); the palace is closed with `memory.palace_unload`. Both go through a new capability that cannot send a delete. A daemon that is not running counts as nothing loaded. If a park or an unload fails, the verb fails with a message naming each item that may still be loaded, the project is not marked decommissioned, and a retry re-runs the shutdown. The report gains `index_shutdown {search, palace}`.
- A new session for a project whose trusty-search index a decommission parked unparks it (#10989): the index reloads, its watcher restarts and the project resolves again. Only a park with reason `decommissioned` is undone. If the unpark fails, the spawn fails with an error that names the running session and the index that is still parked. The palace needs no step: trusty-memory reopens it on its next use.
