Changed
- `tm projects decommission` (and the `project_decommission` MCP tool, `POST /api/v1/projects/{name}/decommission`, `mpm.projects.registry.decommission`) now shuts the project's trusty-search index and trusty-memory palace down after its sessions stop, and keeps their data (#10989). The index is parked with `search.project.park {decommission: true}` (unloaded, watcher stopped, corpus kept); the palace is closed with `memory.palace_unload`. Both go through a new capability that cannot send a delete. A daemon that is not running (no socket, or a refused connect) counts as nothing loaded; any other connect error, or a connect timeout, fails the item. If a park or an unload fails, the verb fails with a message naming each item that may still be loaded, the project is not marked decommissioned, and a retry re-runs the shutdown. The report gains `index_shutdown {search, palace}`.
- A new session, or an operator resume of a stopped one, for a project whose trusty-search index a decommission parked unparks it (#10989): the index reloads, its watcher restarts and the project resolves again. Only a park with reason `decommissioned` is undone. If the unpark fails, the spawn or resume fails with an error that names the running session and the index that is still parked. The palace needs no step: trusty-memory reopens it on its next use.
- A decommission resolves a project whose `repo_url` is a local path by that path, never by an `owner/repo` guessed from the path's last two segments, and retries a resolve miss by the checkout path before it reports the index as not loaded (#10989). A path resolve is accepted only when the index's root is that path or lies under it, or the index carries the project's own identity; an index rooted at an ancestor directory is never parked. A project with no session records takes its checkout from the registry row, so its palace can still be unloaded.
