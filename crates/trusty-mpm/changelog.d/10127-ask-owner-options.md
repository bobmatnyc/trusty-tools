Added
- The `ask_owner` MCP tool takes an optional `options` list of 2 to 6 answer labels, each 1 to 80 bytes with no control character, unique ignoring case and none equal to another option's number; a bad set is refused as `options_invalid` before anything is reserved or posted. The Slack question lists the labels numbered from 1, the stored question keeps them, and the result echoes them. A question without options posts and stores exactly as before, and replies still take today's path (#10127).
- The question table records an `unparsed` annotation (the reply's SHA-256 and length, never its text) for a reply that matched no option; the question stays open. A `questions.jsonl` holding an `unparsed` line cannot be opened by a daemon older than this release, so downgrading after one is written fails the table open. The record format version stays 1 (#10127).
