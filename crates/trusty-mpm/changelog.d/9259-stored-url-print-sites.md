Fixed
- Every error, log line and notice that prints one remote URL now masks its whole userinfo, so a password holding a quote or whitespace (`https://u:pa'ss@host/r`) no longer prints in clear. This covers the daemon's unknown-`repo_url` and non-local-`repo_url` errors, the clone and spawn logs, the `gh` account refusals and notices, and the `tm register` and `tm run` messages, the launch refusal and the session-account notices (#9259).
- An scp-style origin carrying a password (`u:pw@host:o/r`) now prints as `***@host:o/r` in those messages; a bare `git@host:o/r` prints unchanged. git stderr keeps the free-text redaction (#9259).
