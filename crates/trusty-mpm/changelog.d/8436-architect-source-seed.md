- `tm fleet init` seeds the Architect project from the shipped source tree: `AGENTS.md` (a short, marked placeholder that tm composes into the Architect's instructions), a short `CLAUDE.md` with no `@` import and no marker block, the `local/` records (`state.md` with the watch set, `goals.md`, `actions.md`), the `local/` skeleton and empty ledgers, and the scripts, templates, docs and agents. - The Architect receives every skill its operating manual points at: `tm-fleet-restart` and the 16 `architect-*` skills join `tm-fleet-check` and `tm-context-refresh`, deployed at init and at every launch. `tm-fleet-check` and `tm-context-refresh` carry the newer procedures (claim verification, the goal and capacity check, the 250k-token context bar, own-context measurement with `tm architect self-ctx`) (#8436).
- `tm fleet init --guard-lift` sets `TRUSTY_MPM_PM_UNRESTRICTED=1` in the Architect's `.claude/settings.json`, keeping every other key; `--no-guard-lift` removes it. With neither flag a terminal run asks `[y/N]` and any other run leaves the guard as it is. A settings file that is not a JSON object, an `env` that is not an object, or a symlinked file fails the step and is left untouched. `tm fleet status` shows a `guard_lift` row and `tm doctor`'s `session_profile` row names the lift; a lift on a project that is not the Architect warns (#8436).
- The 19 Architect skills (`tm-fleet-check`, `tm-fleet-restart`, `tm-context-refresh` and the 16 `architect-*` skills) are in the owner skill floor: an owner `[skills] off` list can no longer name one, and a file that does is a bad file (#8436, #8992).
- The pm-guard denies `tm fleet init --guard-lift`, `scripts/init.sh --guard-lift` and `ARCHITECT_GUARD_LIFT=1` from any hook-guarded session, the Architect included and under every bypass. The lift stays the owner's choice, made from their own terminal (#8436).
- The guard-lift state is read from `.claude/settings.json` and `.claude/settings.local.json`. A lift in either shows as lifted in `tm fleet status` and `tm doctor`, naming the file; an unreadable file is unknown, never off; `--no-guard-lift` no longer says the guard is on while `settings.local.json` still lifts it (#8436).
- `tm fleet init` seeds `statusLine` with `scripts/statusline-tee.sh`, as `scripts/init.sh` does, so `scripts/doctor.sh` passes and `inbox/statusline-usage.json` is written. An existing different `statusLine` is kept. The `--guard-lift` prompt now says it lifts the pm-guard rules the Architect profile keeps, not pane access (#8436).
