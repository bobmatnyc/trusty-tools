Added
- `tm fleet init` seeds the Architect project from the shipped source tree: `AGENTS.md` (a short, marked placeholder that tm composes into the Architect's instructions), a short `CLAUDE.md` with no `@` import and no marker block, the `local/` records (`state.md` with the watch set, `goals.md`, `actions.md`), the `local/` skeleton and empty ledgers, and the scripts, templates, docs and agents. Every `*.sh` and `scripts/*.py` is executable. `scripts/init.sh` builds the same tree by hand (#8436).
- The Architect receives every skill its operating manual points at: `tm-fleet-restart` and the 16 `architect-*` skills join `tm-fleet-check` and `tm-context-refresh`, deployed at init and at every launch. `tm-fleet-check` and `tm-context-refresh` carry the newer procedures (claim verification, the goal and capacity check, the 250k-token context bar, own-context measurement with `tm architect self-ctx`) (#8436).
- `tm fleet init --guard-lift` sets `TRUSTY_MPM_PM_UNRESTRICTED=1` in the Architect's `.claude/settings.json`, keeping every other key; `--no-guard-lift` removes it. With neither flag a terminal run asks `[y/N]` and any other run leaves the guard as it is. A settings file that is not a JSON object, an `env` that is not an object, or a symlinked file fails the step and is left untouched. `tm fleet status` shows a `guard_lift` row and `tm doctor`'s `session_profile` row names the lift; a lift on a project that is not the Architect warns (#8436).
