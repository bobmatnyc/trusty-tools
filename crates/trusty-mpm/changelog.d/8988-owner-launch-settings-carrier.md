Changed
- The per-owner launch policy now applies at launch: every PM launch path (daemon spawn and resume, the in-place relaunch, `tm launch`, `tm connect`, the Architect, `tm run`, `tm session start`, the daemon client launch/connect and the GUI spawn) passes `--settings <file>`, a file under `~/.trusty-tools/trusty-mpm/session-settings/` named by the hash of its contents carrying `deniedMcpServers` (allow applied, then deny; the trusty-* builtins and `claude-in-chrome` are never named) and `disableClaudeAiConnectors: true` when `claude_ai_connectors = false`. Server names match exactly and case-sensitively, as Claude Code matches them. With no owner policy the launch is unchanged. A settings file that cannot be written launches without the flag and prints that the policy was not applied (Refs #8988).
- Deleting an owner file now retires its last-good record at the next launch, so a later bad file cannot revive the deleted policy (Refs #8988).
