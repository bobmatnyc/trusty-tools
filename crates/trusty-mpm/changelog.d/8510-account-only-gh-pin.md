Fixed
- A project registry record that pins a `gh_account` with no `github.config_dir` no longer refuses every merged-PR lookup when a usable config dir exists (#8510, a regression from #8416). The daemon and the `tm hook --pm-guard` worktree-removal check now borrow the static config's `github.config_dir` for that origin, then tm's own `gh-accounts/<login>` dir, but only when that dir's local `hosts.yml` names the pinned account as its active `user:`. No network call is made, and the repository owner never selects the account. When no candidate verifies, the refusal still fails closed. It names each candidate's failure (missing dir, unreadable or malformed `hosts.yml`, no active user, or a different active user) and the fix command `tm projects register <name> --repo-url <url> --gh-account <login> --gh-config-dir <dir>`.
