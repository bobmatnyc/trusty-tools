Changed
- A live-pane answer without a record-backed pending decision is now refused with a 409 instead of being typed into the pane. This covers `POST /api/v1/sessions/managed/{id}/answer`, `mpm.managed.answer`, `tm session answer`, and the chat and TUI `/approve`, `/deny` and `/answer` commands, which all reach the same check. The 409 text starts `no pending decision on session <id>` when the session never had a decision, and `decision <id> already answered by <X> at <T>` once its decision was answered. To type into a pane, use `tm session send`. `tm session answer`, `/approve` and `/deny` now show the daemon's refusal text instead of a bare HTTP status (Refs #9841).
