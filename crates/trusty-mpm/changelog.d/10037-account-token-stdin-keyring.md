Fixed
- `--account-token-stdin` and every `--account` pin no longer write the proven gh token into tm's per-account `hosts.yml`. tm stores it in the keyring entry gh reads for that login (service `gh:<host>`, account `<login>`), the entry the pinned-session gh shim reads, and the file names the login with no token. A keyring write failure refuses the pin and never falls back to the file. A `hosts.yml` an earlier tm wrote with a token is migrated the next time its login is pinned, and the new `tm doctor` row `gh_account_dir_tokens` warns about each file that still holds one (#10037).
