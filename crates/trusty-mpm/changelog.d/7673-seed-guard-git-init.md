Added
- Seeding a `CLAUDE.md` is now refused outright at the home directory, and at a directory above it that belongs to no git working tree — the root-cause guard for the 2026-09-12 incident where a tm seed template sat at `$HOME` and rode into every turn of every agent in every project beneath it. Every directory inside a git project, at any depth, and every first-touch directory still seeds exactly as before. Seeding into a marker-less, non-git directory that is itself a WORKSPACE PARENT (a child repository lives beneath it, at any depth a bounded scan can reach) is refused, naming the child repository found; seeding into any other non-git directory below home now offers to `git init` first, declining by default for every non-interactive caller. `tm sessions instructions --dir <dir>` — the one entry point that can reach this offer with no git-project guard already in front of it — now asks the question for real when stdin is a TTY, naming the directory that would be initialised ("<dir> is not a git repository; initialise one? [y/N]"), through the same confirm classifier the picker's other yes/no prompts use; every other caller (piped, non-interactive, `session start`'s in-place path, `tm launch`/bare `tm`, which already run their own pre-existing auto-`git init` step before reaching this code at all) keeps the silent-decline default (#7673, folded from #7700).
