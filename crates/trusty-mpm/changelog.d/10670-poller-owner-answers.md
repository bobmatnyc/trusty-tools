Fixed
- The seeded fleet poller now wakes the Architect when the owner answers or cancels a dashboard item. It re-alerts every 30 minutes until the answer is relayed and reads `DASHBOARD_ROOT` and `DASHBOARD_FORMAT` (forwarded by `start-fleet-poll.sh`). A batch of only answers waits out a running turn; other alert kinds keep their earlier timing. A failed read of the answers raises one `owner_answer_error` alert per failure and changes no answer's state. The poller does not type while a draft is in the input box and presses Enter only when the box holds exactly its pointer. tmux cannot read and send atomically, so a key typed in the instant between the read and the send can still land beside the pointer, and a key typed between the confirming read and Enter is submitted with it. On a pane with no plain bottom rule under the input box, every row below the `❯` counts as box text, so the poller sends no keys there in any box state and logs `skipped: no bottom rule under the input box`. The pending wake waits until the rule is drawn, so such a pane stalls delivery for as long as the rule is missing. If the rule vanishes in the 0.5 seconds after typing, the pointer stays in the box, unsubmitted, until a human clears it.
