Fixed
- `session_send` and `tm session send` no longer refuse a live session whose recorded pane id went stale after a relaunch or respawn inside the same tmux session (#10442). When the recorded pane is gone, the send re-resolves the one live pane of the record's own tmux session, on the record's own tmux server and inside its project, writes it to the record under the store lock, and delivers there; `session_list` then reports the live pane. A dead session, a session with two or more panes, and a pane in another session or project still refuse with the same `recorded pane … no longer exists` error, now also logged at ERROR so `list_recent_errors` returns it.
