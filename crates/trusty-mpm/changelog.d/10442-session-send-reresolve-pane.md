Fixed
- `session_send` and `tm session send` no longer refuse a live session whose recorded pane id went stale after a relaunch or respawn inside the same tmux session (#10442). When the recorded pane is gone, the send re-resolves the one live pane of the record's own tmux session, on the record's own tmux server and inside its project, and only into the same tmux session instance the record launched (its stored `$N` session id, or for an older record a session created no later than the record), writes it to the record under the store lock, and delivers there; `session_list` then reports the live pane. A dead session, a session with two or more panes, a pane in another session or project, and a session recreated under the same name still refuse with the same `recorded pane … no longer exists` error, now also logged at ERROR so `list_recent_errors` returns it.
