Added
- The daemon now records a worktree that a Bash tool call creates with `git worktree add` (including `-b`, `git -C <dir>` and `cd <dir> && …`) in the worktree ledger, as one `observed` entry with origin `git_command` at the absolute path, read from the `PostToolUse` relay. A call is recorded only when the directory exists, `git worktree list` names it and its repository is a registered project, so a failed add records nothing; a command that only mentions the words (`echo`, `grep`, a here-document, a comment) records nothing. After `git worktree remove` or `git worktree prune` the daemon appends `removed` only when the directory is gone and git no longer lists it. Nothing is deleted. A call the parser cannot resolve, or a ledger or git failure, never changes the hook verdict: it is logged at warn, recorded in `worktrees.ingest-failure.json`, and keeps the `worktree_registry` doctor row at `Warn` for the rest of the daemon run (#8994).
