Added

- `tm doctor` reports the channel route policy in four read-only rows: `channels_host` (the `channels:` host ceiling, with each channel's state, project count and `bot_ref`/`app_ref` names, never a credential value), `channels_routes` (the Slack and Telegram routes a fresh daemon start would put in effect), `channels_gchat` (one load per gchat-listed project, as gchat-mcp loads them) and `channels_gate` (route files the default-branch gate refused, each with its fix). A missing file or section reads "not configured", the deny state; a host fault is Fail with its reason; a refused route file is Warn. Each load runs under a 30 s budget and reads Unknown if it does not finish, so doctor always completes. Nothing is enforced, refreshed, resolved or sent. trusty-mpm now depends on trusty-channels (`channels` feature, on in `cli`). Refs #8454
