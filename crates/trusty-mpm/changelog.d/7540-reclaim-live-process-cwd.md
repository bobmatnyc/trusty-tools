Fixed
- The merged-PR worktree reclaim (the hourly daemon sweep and `tm session prune-worktrees --merged-prs`) no longer removes a worktree that any live process owned by the daemon's user has its working directory inside — an unmanaged shell or tmux pane, an ad hoc build, or a tool no session or agent registered. It asks the OS process table (`lsof`) immediately before each removal, bounded at 15 seconds; a host where that listing cannot be read, or does not answer in time, keeps the worktree. Known limit: without root, `lsof` does not list other users' processes, so a process another user owns inside the worktree does not block it ([#7540](https://github.com/bobmatnyc/trusty-tools/issues/7540))
