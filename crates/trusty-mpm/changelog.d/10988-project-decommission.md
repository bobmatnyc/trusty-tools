Added
- `tm projects decommission <name>`, the `project_decommission` MCP tool and `POST /api/v1/projects/{name}/decommission` stop a project's running sessions and mark the project decommissioned. Workspaces, session records (still resumable) and the search index are kept. The periodic orphan-index sweep keeps index data too: it deregisters an orphaned worktree index and leaves its data on disk. A session of the Architect refuses the verb, and a session that fails to stop leaves the project unmarked and names the failure (#10988).
- A project record carries `decommissioned_at`; `project_list`, `project_get`, `tm projects list` and the fleet view (`decommissioned`) show it. A new session for the project clears it on every spawn route, and a spawn that cannot clear it returns an error naming the running session; a config seed, a re-register or the boot auto-registration does not (#10988).
- A registry write that fails after every session stopped returns an error that names the stopped sessions, and the project stays unmarked (#10988).
