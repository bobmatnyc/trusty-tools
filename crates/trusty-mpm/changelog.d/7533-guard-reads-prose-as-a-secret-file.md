Fixed
- `tm hook --pm-guard`'s secret-file class no longer reads Markdown emphasis as a glob onto a credential family. The word scan keeps `*` inside a word, so the two asterisks opening a bold span glue onto the next letter and the fragment overlapped the `id_rsa`/`id_ecdsa` cores once case-folded; `**A pipe confirms nothing at all.**` in a here-document body, in an `echo`, or in a `gh` comment body was refused as naming `**A`. A glob carrying exactly one literal character is now exempt only when that character occurs in no denylist entry's literal core, compared case-sensitively — so an upper-case letter is exempt and `*a`, `*e` and `*n`, which reach `id_rsa`, `*.tfstate` and `token*`/`*.ovpn`, still deny through the Bash, `cp` and `Grep`-glob paths alike (#7533).
- The same class no longer reads a sentence's full stop as a file extension: `token.`, `secrets.` and `credentials.` at the end of a sentence are prose, not file shape, in both the read guard and the copy/laundering guard, so a here-document of ordinary text is no longer refused as reproducing a secret file into its destination. A dot with a name after it (`note.md`, `.env`, `secrets.rs`) is untouched (#7533).
- `git worktree add`'s operands are now read as a new tree's path and a commit-ish, so a branch name carrying `secrets`/`credentials`/`token` no longer refuses the call — the same narrowing `git branch`, `git push` and `checkout -b`/`switch -c` already had. `worktree list`/`remove`/`prune` keep the previous answer (#7533).
