Added
- `core::session_launch::write_sandbox_settings` generates the Claude Code sandbox policy for a PM, agent or Architect session (#8928 step 5). The project `.claude/settings.json` gets the `sandbox` block and exact-file `permissions.deny` entries, with `allowUnixSockets` naming `trusty-mpm.sock`, the sccache socket and, for a PM, the workspace tmux socket, and no `allowLocalBinding`. tm's user-level `settings.json` gets `sandbox.network.strictAllowlist` and a credentials deny list. The Architect gets `sandbox.enabled: false`. After writing, `verify_sandbox_settings` reads the files back and refuses the launch when the sandbox is off, `allowUnsandboxedCommands` is not `false`, `strictAllowlist` is missing, `.claude/settings.local.json` sets a `sandbox` key, or a file cannot be read. No launch path calls it yet; that is step 6.
