Fixed
- `tm mcp add -e KEY=VALUE` no longer writes a credential into the MCP `env` block of the managed `.claude.json`. For a trusty server that reads the credential store (slack-mcp, telegram-mcp, tagent, tcode), a key the credential registry maps (for example `SLACK_BOT_TOKEN`) is stored in the trusty credential store, confirmed by read-back, and left out of the file; the server reads it from the store at launch. A mapped credential for any other server (for example an `npx` server given `GITHUB_TOKEN`) is refused, since that server never reads the store. A store slot that already holds a different value is never overwritten unless `--replace` is passed. A store failure aborts the add with nothing written, and a credential-shaped key with no registry entry is refused (#10041).
- New `tm doctor` row `claude_json_secrets` fails when an MCP `env` block in the managed `.claude.json` holds a credential value, or when that file or a `.claude.json*` copy beside it is readable beyond its owner (mode wider than 0600). `tm doctor --fix --yes` moves each registered credential of a store-reading trusty server into the store, removes it from the file in one atomic rewrite with no backup, and tightens the files to 0600; a credential of any other server is reported and left in place. Rotate any credential that sat in the file (#10041).
