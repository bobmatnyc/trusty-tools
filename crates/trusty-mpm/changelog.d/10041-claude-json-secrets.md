Fixed
- `tm mcp add -e KEY=VALUE` no longer writes a credential into the MCP `env` block of the managed `.claude.json`. A key the credential registry maps (for example `SLACK_BOT_TOKEN`) is stored in the trusty credential store, confirmed by read-back, and left out of the file; slack-mcp and the other trusty servers read it from the store at launch. A store failure aborts the add with nothing written, and a credential-shaped key with no registry entry is refused (#10041).
- New `tm doctor` row `claude_json_secrets` fails when an MCP `env` block in the managed `.claude.json` holds a credential value, or when that file or a `.claude.json*` copy beside it is readable beyond its owner (mode wider than 0600). `tm doctor --fix --yes` moves each registered credential into the store, removes it from the file in one atomic rewrite with no backup, and tightens the files to 0600. Rotate any credential that sat in the file (#10041).
