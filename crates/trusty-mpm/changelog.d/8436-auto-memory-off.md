Changed
- Claude Code auto memory (`MEMORY.md`) is now off for every tm session, with no fallback. Every launch writes `autoMemoryEnabled: false` into the project settings and every managed spawn and resume sets `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, also when trusty-memory does not answer; the 2026-09-12 rule that turned auto memory back on while trusty-memory was down is retired. A launch no longer probes trusty-memory at all (Refs #8436).
- `tm doctor`'s `auto_memory` row now fails whenever auto memory is on, whatever trusty-memory's state, and fails when `MEMORY.md` still holds facts. With auto memory off and trusty-memory not answering it warns that sessions have no memory until trusty-memory answers. `tm doctor --fix --yes` writes `autoMemoryEnabled: false` only, never `true`, and names `tm memory import-auto-memory` (Refs #8436).
