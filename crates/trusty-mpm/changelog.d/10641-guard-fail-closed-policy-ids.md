- `tm hook --pm-guard` and `tm hook --egress-guard` end every refusal with the policy it enforces, as `[policy GP-005 destructive-delete; source: #4031]`. The table of policies lives in `trusty_mpm::core::guard_policy` and in `docs/reference/guard-policies.md`; a refusal whose rule has no entry names `GP-000` and still refuses. No verdict changes (#10641).
- The `PreToolUse` hook entry tm writes for PM sessions carries `onFailure: "block"`, so a `tm hook --pm-guard` that times out or crashes blocks the tool call on Claude Code v2.1.295 and later. The guard also decides in-process when it panics or errors (`GP-003`) or has not decided 8 s after it starts (`GP-049`), on any Claude Code version: writes are refused, and a fixed recovery allowlist still runs so a session is never locked out of its repair — read-only tools (Read, Grep, Glob, LS, NotebookRead, never on a secret file) and exactly `tm doctor`, `tm install ...` and `cargo install trusty-mpm --version <v> --locked`, each as one plain command with no shell metacharacter, env prefix or wrapper. Each such refusal says how to clear a stuck session from outside it. The 8 s watchdog runs in release builds only: an unoptimized debug `tm` can need more than 8 s on a megabyte command, so a debug build leaves a stall to Claude Code's 10 s block. A missing `tm` binary still blocks every tool; `docs/reference/guard-policies.md` gives the outside recovery (#10600, #10641).
