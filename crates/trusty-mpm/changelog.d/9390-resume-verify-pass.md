Added
- `session_context_catchup` and `tm session catchup --json` return a new `resume_verify` field. When a snapshot resolves, the daemon reads the `ws:<session>/resume` slot of the session that wrote it and runs the slot's `verify` commands in `project_dir`, then reports per command what the snapshot claimed, what came back, and a verdict: `verified`, `stale` (the PR is merged or closed, or the branch tip moved off the recorded commit) or `unverified:<reason>`. Only `gh pr view <n> --json headRefOid,state` and `git rev-parse <branch>` run, as argv with no shell; any other line reports `unverified:not_allowlisted` with only its byte length and a 12-hex SHA-256 prefix, never its text. The pass reads at most 11 lines; the rest are one `unverified:over_line_cap` entry that counts them. Each command is bounded at 4 seconds and the pass at 10. A failure reports `unverified`, never `verified`, and never fails the catch-up. The pass only reports; it edits no slot. The field is `null` when no snapshot resolved (#9390).
