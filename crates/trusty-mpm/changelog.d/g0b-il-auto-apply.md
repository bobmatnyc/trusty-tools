Added
- `tm hook` applies an IL block to the session's ledger when a PM receives an agent handback (`PostToolUse`), an inbound session or Architect message arrives, or the Architect submits a prompt (`UserPromptSubmit`). Every applied field is covered: a block carrying `new:`, `remind:`, or `pct`/`est`/`remaining`/`decided`/`delta` for a ledger task goes, whole, to `ilio.py apply` (found through `$ILIO_SCRIPT` or the Architect directory, block on stdin, no shell, 20 s timeout); any other block is written in process. A replayed packet is a no-op on both paths. A rejected block, or an ilio run that is missing, exits nonzero or times out, writes nothing, is never reported as applied, and is recorded where `list_recent_errors` reads it as `il-auto-apply:<rule>` (G0b).
- IL auto-apply sends `ilio.py` only the fence, from a thread, so a child that never reads stdin cannot hold the hook past the timeout; holds a store lock and a pending marker across the ilio run, recording `il-auto-apply:PENDING-UNKNOWN` instead of re-running a packet whose earlier run left no result; and records `il-auto-apply:NO-LEDGER` once per packet for a session with no store (G0b).
