Added
- `tm hook` applies an IL block to the session's ledger only from the session's OWN turn: the last assistant message of the `Stop` payload's transcript (path screened against the Claude config directory, tail read only). A block in an agent handback (`PostToolUse` of `Agent`/`Task`) or in a `UserPromptSubmit` (inbound session or Architect message, Architect prompt) is never applied; it is logged once per packet as `il-auto-apply:PROPOSAL` where `list_recent_errors` reads, with the entry point and packet id, and the ledger is unchanged. See G0b IL authority (owner decision pending).
- For an own-turn block, every applied field is covered: a block carrying `new:`, `remind:`, or `pct`/`est`/`remaining`/`decided`/`delta` for a ledger task goes, whole, to `ilio.py apply` (found through `$ILIO_SCRIPT` or the Architect directory, block on stdin, no shell, 20 s timeout); any other block is written in process. A replayed packet is a no-op on both paths. A rejected block, or an ilio run that is missing, exits nonzero or times out, writes nothing, is never reported as applied, and is recorded where `list_recent_errors` reads it as `il-auto-apply:<rule>` (G0b).
- IL auto-apply sends `ilio.py` only the fence, from a thread, so a child that never reads stdin cannot hold the hook past the timeout; holds a store lock and a pending marker across the ilio run, recording `il-auto-apply:PENDING-UNKNOWN` instead of re-running a packet whose earlier run left no result; and records `il-auto-apply:NO-LEDGER` once per packet for a session with no store (G0b).
