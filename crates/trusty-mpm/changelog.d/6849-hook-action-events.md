Added
- The tm daemon now pushes every hook event it records to the trusty-events bus (#6849, DOC-73 §3.4). `PreToolUse`, `PostToolUse` and `PostToolUseFailure` become `Tool` events (`Started`, `Finished`, `Errored`), `SessionStart` and `SessionEnd` become `Session` events, `FileChanged` becomes a `File` event, `WorktreeCreate` and `WorktreeRemove` become `Workflow` events, and every other hook stays an untyped `Hook` event under its own name. Each event carries a `parent_id`: a session's events hang off its `Session` root, and a tool call's or worktree's closing event hangs off its opening one, so one session's events form a tree. A session first seen mid-stream gets one root marked `inferred`.
- The events name things by reference only: a tool name and call id, an agent id and type, and a path shown relative to the session's working directory or `~`. No prompt, tool input or output, transcript path or message text is sent.
- The bus never slows or fails a hook. Recording a hook only buffers its events (bounded at 4096 frames and 8 MiB; overflow drops the oldest and is counted); a background task flushes once a second, and shutdown, a SIGTERM included, runs one final flush bounded at 1 s. An absent, refusing or stalled bus costs one warning per outage. A daemon isolated from the host (a scratch framework root or `$HOME`) that shares the host's data directory pushes nothing.
