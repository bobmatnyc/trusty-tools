Fixed
- `tm hook --pm-guard` denies `tm fleet relaunch` for every hooked session, the Architect included, and `TRUSTY_MPM_PM_UNRESTRICTED` / `TRUSTY_MPM_DISABLE_HOOKS` do not lift the deny. The guard reads the command with the `tm` argument parser after dropping the redirections, background `&` and subshell closers bash strips, so prefixes such as `tm fl rel`, `trusty-mpm`, `cargo run --bin tm` with or without `--`, wrappers, `xargs` and command substitutions are caught. A variable, substitution, brace expansion or glob where the subcommand goes is denied, as is a command naming `tm` that pipes program text into a shell, `xargs` or `parallel`. Run `tm fleet relaunch` from an operator terminal outside any Claude Code session (#10033).
- `tm fleet relaunch` itself refuses to run inside a Claude Code session, so a command that slips past the pm-guard text check still cannot relaunch the Architect. It reads the markers Claude Code sets in every process it starts (`CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_PID`); any one present refuses before anything is stopped, as does a marker whose value is unreadable or is not one Claude Code sets. The error names each variable and its reason, never its value. An operator terminal with none of them relaunches as before (#10033).
