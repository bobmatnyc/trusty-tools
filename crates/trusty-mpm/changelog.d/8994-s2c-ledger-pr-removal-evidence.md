Added
- The worktree ledger now records `removed` when the merged-PR reclaim, the agent-worktree reap or a session decommission removes a tree, but only after re-checking that the directory is gone and `git worktree list` no longer names it. A removal that left the directory behind records nothing and the tree stays listed; a re-check that cannot be answered (a stat error other than not-found, a `git worktree list` that fails or times out) records nothing and is logged at warn with its cause. Nothing new is deleted (#8994).
- `tm worktrees` now lists each tree with its pull request number, kept in the ledger as a new `pr_linked` event, and lists stale candidates — a merged PR, or a branch gone from `origin` with nothing unpushed. A lookup that cannot be answered never makes a candidate, and candidates are only listed, never removed. A ledger written before this version reads exactly as before; a `tm` binary older than this version skips each `pr_linked` line as one malformed line, reads every other line, and its `worktree_registry` doctor row shows `Warn` for the skipped lines (#8994).
