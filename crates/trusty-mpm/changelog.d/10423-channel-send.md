Added
- `POST /api/v1/channels/send` and the `channel_send` MCP tool stage one message to a user configured in `~/.trusty-tools/trusty-mpm/channels/orgs.toml`, through that user's own org channel only. Nothing is posted until the owner approves the exact text; the approval request goes to the owner's Slack DM for every org, with the dashboard as fallback, and only the configured owner identity may approve (#10423).
- Staged sends persist in `channels/staged_sends.json` across a daemon restart. A send that was in flight when the daemon stopped comes back as an unknown outcome and is never posted again. A table that cannot be read refuses every send (#10423).
- Each send step writes one line to `channels/send_audit.jsonl` with no message text and no credential. A send whose audit line or table write fails posts nothing (#10423).
- Each org declares its secret lookup order with `secrets = "<owner>/<repo>"` (project vault, then owner vault) or `secrets = "<owner>"` (owner vault only). Org credentials are trusty-secrets references in the DOC-74 forms `secret://KEY`, `secret://<owner>/KEY` and `secret://<owner>/<repo>/KEY`; a reference naming a vault outside the org's lookup order is refused with `vault_out_of_scope` before any store read, and an org with credentials but no `secrets` is refused at load. New `tm doctor` rows `channel_org:<org>` report each org's channel binding and whether each credential reference is indexed, by name only (#10423).
- Approve rebuilds the recipient's route from the current `orgs.toml` and refuses with `route_changed` when the org, address, `secrets` scope or credential references differ from the staged route. A send still awaiting a decision when the daemon restarts comes back as not sent (`restart_while_staged`) and cannot be approved; a Deny or expiry whose table write fails returns `persist_failed` (#10423).
