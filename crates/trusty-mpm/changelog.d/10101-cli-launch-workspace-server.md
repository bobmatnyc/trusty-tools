- `tm launch`, `tm connect` and the in-place `tm session start` create a fresh PM on its workspace's own tmux server (`tm-ws-…`), the server the daemon picks for that workspace, and register that server's socket; `TM_WORKSPACE_TMUX=0` keeps the default server. The launch's follow-up calls (typing the `claude` line, the `claude` pid lookup, `--detach`'s pane id, the reconnect check and the cleanup on failure) go to that server, and the daemon's pid capture, `DELETE /sessions/{id}` kill and dead-session reaper judge such a session on its own server (#10101).
- A CLI launch whose tmux name is held by a managed session that is not decommissioned or deleted is refused, naming that session, before any tmux session is created or anything is registered. A create or `claude` start that fails after the registration now removes the registration and fails the command; the in-place `tm session start` used to print a hint and succeed (#10101).
