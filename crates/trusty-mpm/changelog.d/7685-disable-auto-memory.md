- Claude Code auto-memory is now a FALLBACK, not a thing tm turns off unconditionally. A managed launch writes `autoMemoryEnabled: false` into the project's `.claude/settings.json` and sets `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` on the spawned and resumed session only when the `trusty-memory` daemon answers a health probe at launch; when it does not, both are skipped and the session keeps auto memory as its fallback, with one INFO line saying so. `tm memory import-auto-memory [--project <dir>]` migrates an existing auto-memory store into the project's palace — each fact stored with the tags `migrated-from-auto-memory`, `name:<name>` and `type:<type>`, its file moved to `memory.archived-<YYYYMMDD>/`, and `MEMORY.md` archived and emptied only once every fact has landed; a fact that fails to store is left exactly where it was. `tm doctor`'s `auto_memory` row is now tri-state: Fail when trusty-memory is healthy and auto memory is on or the index still holds facts, Warn when trusty-memory is down and auto memory is carrying the project, Ok when it is off and the index is empty. `tm doctor --fix` still writes only the settings key and names the migration rather than running it.
