Added
- The tm daemon records inter-session messages on the trusty-events bus as `message` events (#9167). A `SendMessage` call is one `sendmessage` event; a Bash call running `tmux send-keys` that types text is one `tmux` event per call, naming the `-t` target (a follow-up `Enter` adds nothing, and `send-keys` quoted inside another command does not count); a `Notification` that `tm hook` appended to the configured inbox is one `hook_push` event to that inbox. Each event names the sending session, the recipient, and any relay marker (`[<Name> Architect HH:MMZ]`), and is a child of the tool call or hook event that carried it. Only the `PreToolUse` of a call is counted.
- A `message` event carries no message text by default: only its byte count and sha256. Both describe the text after a credential scan, so a token, key or password in a message is never fingerprinted; text with no credential hashes as sent. Setting `TRUSTY_MPM_EVENTS_MESSAGE_BODY=1` in the daemon's environment adds the scanned text as `body`, cut to 4096 bytes.
- These events use the same buffer, flush and failure handling as the hook action events: a down or stalled bus never blocks or fails a hook.
