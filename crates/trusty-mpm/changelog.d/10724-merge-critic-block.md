Fixed
- `tm pr merge` refuses while a code-critic BLOCK is pinned to the PR's head commit and no later APPROVE or WARN is pinned to it. The refusal names the review or comment and the sha. A verdict is a line starting `Verdict: <APPROVE|WARN|BLOCK>`, with optional leading `#` marks and `**` bold, outside a closed code fence; a BLOCK after a code fence that never closes still counts. A review is pinned to the commit it was submitted on, and `, pinned to <sha>` on the line overrides that. A BLOCK that names no commit refuses until a later APPROVE or WARN is pinned to the head. A BLOCK on an older head only warns that no verdict covers the head. If the comments and reviews cannot be read, the merge is refused. The merge passes `--match-head-commit` with the head the verdicts were read against, so a push in between makes GitHub refuse it. A raw `gh pr merge` still bypasses this check.
