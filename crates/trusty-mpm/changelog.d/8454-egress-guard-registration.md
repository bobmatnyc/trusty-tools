Added
- Every tm settings writer — launch, resume, `tm install`, `tm launch` and the managed `claude-config` tier — now registers the `tm hook --egress-guard` `PreToolUse` entry (timeout 10 s) in both the project and the user tier, whatever `[pm_guard] enabled` says. There is no switch to turn it off. A rewrite after an exe-path change replaces the entry rather than adding a second one, and removing the pm-guard, `tm hooks clean` and the hook strips leave the installed entry in place (#8454).
- The egress hook now runs the trust-anchor floor itself, so it holds when `[pm_guard] enabled = false` leaves the pm-guard hook out. New trust anchors: `~/.trusty-tools/trusty-mpm/config.yaml` and the managed `claude-config/settings.json` and `settings.local.json`. Only the Architect session's main thread may write them; both bypass variables and subagents are refused. Anchoring `config.yaml` also denies `rm` or `mv` of `~/.trusty-tools/trusty-mpm` (and of `~/.trusty-tools`): the floor now reads `rm`, `rmdir` and `unlink` operands, a glob or a shell expansion by its parent directory (#8454).
- A project's `.claude/settings.json` and `settings.local.json` are guarded by content, for every session including the Architect: an Edit or Write that drops or weakens the egress entry or sets `disableAllHooks` is denied, a Bash write is denied while the project's settings carry the entry, deleting, moving or copying over the `.claude` directory itself counts as a write to both files, and an unreadable or malformed settings file denies every write to it. Routine edits that keep the entry are allowed (#8454).
- New `tm doctor` row `egress_guard`: `Fail` when a tm-provisioned settings file lacks the egress group, carries it with a timeout under 10 s or a narrowed matcher, or sets `disableAllHooks`; `Unknown` when a file cannot be read or parsed; `Ok` for a foreign project (#8454).
