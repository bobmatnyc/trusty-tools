Added
- The daemon can now resolve an open channel question from its owner's reply and deliver the answer to the asking Architect session. A reply binds to the question posted in the same DM thread, never to `[Q-n]` text, and must come from the question's recipient through a route that carries questions. The first answer wins; a second one is refused with who answered first and when. Before the answer reaches the Architect's pane, the daemon taints the session's Claude id and its managed record, then sends the text as one quoted line marked as untrusted data. If the session's Claude id changes during that, the daemon taints the new id too, and refuses the delivery as `asker_changed` when the id cannot be pinned. Unknown senders, a stale route policy, an unavailable question table, text over 4000 bytes and more than 100 answers a minute on one route are each dropped with one audit line that never holds the text (#9873, #8433).
- Each delivery step is recorded in `delivery.jsonl` in the channel taint directory. The `channel_taint` row of `tm doctor` now fails when an answer was resolved but its delivery failed, never settled, or left no record, or when a trace line is malformed. An unreadable trace or question log is named in the row and never hides a failure (#9873).
- A daemon started with `tm daemon --sandbox` serves `POST /api/v1/channels/inbound-fake`, which feeds one fake reply through this path for live checks. No other daemon serves the route (#9873).
