Security
- `tm hook --egress-guard` now denies a Bash command over 64 KiB (65 536 bytes) before any parser reads it, the trust-anchor floor's included; the deny names the cap. A command at or under the cap is judged as before (#9699).
- When the Bash egress walk gives up on a command (its step budget is spent, nesting is too deep, a segment will not lex, or a `$"…"` quote will not decode), the raw scan now also reads the text with its quotes and backslashes removed, so a name spliced from quoted pieces (`se''ndmail`, `cu""rl hooks.sl''ack.com`) is still denied (#9699).
- The egress walk now has a byte budget beside its 4096-step budget: it reads at most 4608 KiB (4 718 592 bytes) of segment text. A command the walk re-reads many times (`time eval` nesting) ends early and is denied, naming the budget or the channel it had already found, instead of running past the hook timeout or falling back to the raw scan (#9699).
- The raw scan, still used when the walk spends its step budget (for example after thousands of `:;` no-op segments), now joins each backslash-newline as bash does (`hooks.sl\<newline>ack.com`) and reads a `tm` subcommand past `tm`'s global flags (`tm --account work slack send`) (#9699).
- The egress walk reads each byte for about a third of its former cost, so a near-cap `time eval` payload reaches its walk-budget deny well inside the hook timeout: it lowercases only dotted host candidates, reads only a keyword segment's leading words, and the shared shell parser skips its here-document scan on a command with no `<` and its separator checks on bytes that cannot cut, which also speeds `tm hook --pm-guard` (#9699).
- The shared shell parser no longer slows quadratically on an open quote followed by many unclosed `(`, which affected both `tm hook --egress-guard` and `tm hook --pm-guard` (#9699).
