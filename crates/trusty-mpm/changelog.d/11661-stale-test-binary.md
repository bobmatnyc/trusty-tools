Fixed
- `tm build-lease` now fails a `cargo test` that exits 0 while a target ran no test and filtered out every one although the command requested no filter. It names the target and exits 65 instead of reporting a green gate that tested nothing. A `cargo test` wrapped in a shell or `env -S` gets a stderr line saying the check did not run (#11661).
- `tm build-lease` now guards a pinned, non-shared `CARGO_TARGET_DIR` the way it guards a slot: builds of one checkout share the directory as before, while a build of another checkout waits for them and then clears the fingerprints they left (#11661).
- A slot or kept target directory's last-checkout record is now sealed with a digest of its fingerprints when a leased build ends, and the next lease trusts it only while the digest matches. A build run outside the lease in that directory can no longer pass as the checkout the record names; the lease clears instead. This guards gates run through `tm build-lease`; a plain `cargo test` outside the lease is tracked separately (#11661).
