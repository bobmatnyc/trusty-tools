Fixed
- `tm fleet init` no longer grants the supervisor profile over a directory holding a git repository it never looked at. The preflight scan now walks `node_modules`, `build`, `target` and the other dependency and build trees in full (only `.git` keeps its shallow check), both in the directory and in its private `local/` repository. Any symlink whose target leaves the directory now refuses, naming the link: a directory link by its resolved target, and a file link or a dangling link by its target path. A mount point inside the directory, including one at `local/`, also refuses. Links that stay inside the directory, such as a pnpm `node_modules` or `AGENTS.md -> CLAUDE.md`, still pass. Skip-listed trees now count against the 16384-directory scan budget, and a tree past it refuses naming the budget and where the scan stopped. The `CLAUDE.md` seed guard and automatic `git init` keep their existing scan (#10457).
- Semver note for the release decision: the public enum `trusty_mpm::core::child_repo_scan::ScanIncomplete` gains three variants (`BudgetExhaustedAt`, `SymlinkEscapes`, `MountPoint`). It is not `#[non_exhaustive]` and shipped in the v1.9.1 tag, so an exhaustive `match` on it outside this crate stops compiling. (#10355 already changed `BudgetExhausted` from a unit variant to `{ budget }` since that tag.) `scan_for_child_repo_within`, added after the tag, is replaced by `scan_for_child_repo_exhaustive` (#10457).
