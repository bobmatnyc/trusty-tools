Added
- When `build.sccache: true` is set in `~/.trusty-tools/trusty-mpm/config.yaml`, the tm daemon starts an sccache server on the unix socket `~/.trusty-mpm/sccache.sock` at startup (`SCCACHE_SERVER_UDS`, idle timeout off) for unsandboxed cargo builds (#8928 step 3). It first checks `sccache --version`: an sccache older than 0.9.0, or one whose version cannot be read, is refused and no server starts. A server that already answers is left alone, a stale socket file is replaced, and an unreadable config or a missing `sccache` is logged as a warning. Sandboxed sessions never reach this socket, because the server runs whatever compiler a client names outside the sandbox; they build with `RUSTC_WRAPPER=""`. `tm` never writes `~/.cargo/config.toml`.
- New `tm doctor` row `sccache_socket`: not applicable unless `build.sccache` is true; `ok` when a server answers on the socket, `warn` when `sccache` is not on PATH or the socket is missing or stale, `fail` when the installed sccache is older than 0.9.0, and `unknown` when the config, `sccache --version` or the socket path cannot be read (#8928 step 3).
