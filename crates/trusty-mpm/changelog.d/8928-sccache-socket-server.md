Added
- When `build.sccache: true` is set in `~/.trusty-tools/trusty-mpm/config.yaml`, the tm daemon starts an sccache server on the unix socket `~/.trusty-mpm/sccache.sock` at startup (`SCCACHE_SERVER_UDS`, idle timeout off), outside any sandbox, so a sandboxed cargo build with `SCCACHE_SERVER_UDS=<socket> SCCACHE_CLIENT_SIDE=1` can use the cache (#8928 step 3). A server that already answers is left alone, a stale socket file is replaced, and an unreadable config or a missing `sccache` is logged as a warning. `tm` never writes `~/.cargo/config.toml`.
- New `tm doctor` row `sccache_socket`: not applicable unless `build.sccache` is true; `ok` when a server answers on the socket, `warn` when `sccache` is not on PATH or the socket is missing or stale, `fail` when the installed sccache is older than 0.9.0, and `unknown` when the config, `sccache --version` or the socket path cannot be read (#8928 step 3).
