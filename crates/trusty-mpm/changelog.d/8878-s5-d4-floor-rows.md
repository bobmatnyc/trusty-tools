Added
- The `tm hook --pm-guard` D4 hard floor denies more uploads, disk tools and pushes for every session except the Architect's main thread, and `TRUSTY_MPM_PM_UNRESTRICTED` / `TRUSTY_MPM_DISABLE_HOOKS` do not lift it: `curl -H @file`, `-H @-` and `-K` / `--config`; `git push` to a URL, a path, or a name that is not a configured remote of the push's repository (a repository the command itself creates counts as unconfigured); a push, or a git subcommand that is not a git builtin and so may be a `push` alias, with `-c` / `--config-env` or any `GIT_*` variable anywhere in the command (quoted, `+=` and `export`ed names included) except `GIT_TRACE*`, `GIT_PAGER`, `GIT_EDITOR`, `GIT_SEQUENCE_EDITOR`, `GIT_TERMINAL_PROMPT` and the `GIT_AUTHOR_*` / `GIT_COMMITTER_*` identity; a push with `--git-dir` / `--work-tree`, and any `-c alias.*`; python `-c`, here-document and here-string code (also through `uv run`, `pipx run`, `py` and `python3.N`) that names a network module and reads local content, or names one and cannot be inspected; `python -m` of a network module, and `python -m timeit`, `pdb`, `cProfile`, `profile`, `trace` and `runpy`, whose arguments are judged as code or as the module they run; `gpt` write verbs, `wipefs`, and `gdd` under the `dd` rule (#8878).
- The same floor also denies: a push, or a non-builtin git subcommand, in a command that also runs `git remote add` / `set-url` / `rename`, writes any `git config` key except `user.*` (a key-only `git config <key>` is a read and passes), writes a git or ssh config file (`.git/config`, `.gitconfig`, `git/config`, `~/.ssh/config`) however the path is spelled — quoted, escaped, globbed, with `//`, or built from a variable or substitution — or assigns `HOME` or `XDG_CONFIG_HOME`; a push with no remote operand when the guard cannot read the repository that picks the remote; any `git push` that `xargs` or `find -exec` runs, since both append operands; and `git send-pack`, `git http-push` and `git remote-<transport>`. Every `python -m` module's arguments are now judged as code, and a `-m` run fed stdin is judged by the whole command (#8878).
- A push with no remote operand is judged against the remote its configuration picks (`branch.<b>.pushRemote`, then `remote.pushDefault`, then `branch.<b>.remote`), and one with no refspec against the configured `remote.<r>.push` and `remote.<r>.mirror`; a config the guard cannot read denies. A refspec built at run time (`$VAR`, `$(…)`, a backtick) is treated as the default branch when the push is forced or the expansion starts the refspec (#8878).
- No `cd` is followed: any `cd`, `pushd` or `popd` earlier in the command, including one inside a group, subshell or `if`, or a command word built from `$` or a backtick, leaves the directory unknown. So `cd <dir> && git push origin <branch>` is denied, because the remote cannot be checked; use `git -C` with a literal absolute path (#8878).
