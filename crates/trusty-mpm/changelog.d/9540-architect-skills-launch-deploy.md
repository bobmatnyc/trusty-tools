Fixed
- Every Architect launch, resume, in-place relaunch and `tm sessions sync-assets` run now deploys the Architect's shipped skills, `tm-fleet-check` and `tm-context-refresh`, into the Architect project's `.claude/skills`. A deleted copy comes back, and a copy nobody edited follows a framework update. A copy that differs from the last deployed one is the project's own and is never overwritten; tm logs a warning and keeps it. A PM launch, or a supervisor request missing from the `[supervisor] projects` allow-list, writes nothing, and no launch writes these skills to the managed skill tier or `~/.claude/skills`. A deploy error never stops the launch; it is logged and listed with the launch's skill errors (#9540).
- `tm fleet status` has a `skills` row. It shows `WARN` and names each Architect skill that is missing, stale, project-custom or unreadable. Like `binding`, it does not change `complete` (#9540).
