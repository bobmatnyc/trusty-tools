Added

- `tm fleet init` enables the Architect's `Notification` hook: when `~/.trusty-mpm/config.toml` has no `[notification_hook]` section it writes `enabled = true` and `inbox = "<architect>/inbox"`, keeping every other key and comment, creates the inbox directory (`tm hook` appends to `<inbox>/events.jsonl` and creates none), and applies the hook to the tm-managed settings. A section that is already there is never edited; one whose `inbox` points elsewhere (a relative `inbox` counts as elsewhere, since `tm hook` forwards nothing for it), or a managed settings file the hook writer refuses, skips the step with the fix line `edit ~/.trusty-mpm/config.toml, then tm doctor --fix --only notification_hook --yes` and writes nothing. Only a failed `config.toml` write fails `init` (#10885).
- `tm fleet status` shows an informational `notification_hook` row (`on → <inbox>`, `off`, `enabled but not applied`, `points elsewhere: <path>`) that never changes `complete`, and `tm doctor` reports a `notification_hook` row that warns when the hook is enabled but not applied, and reports unknown with no fix when `config.toml` does not parse. Both read the same plan `tm doctor --fix --only notification_hook` applies (#10885).
