Added
- `tm presence local` asks for Touch ID (or the login password) at the Studio and, from the bound Architect session only, writes a presence grant for that session's `claude`: `~/.trusty-mpm/architect-launch/<pid>.presence`, mode 0600, tied to the PID and start time and sealed with an HMAC key kept in the login Keychain, so a grant copied to another process, or written without the key, is refused. Over SSH, with no GUI session, or from any other session it writes nothing (#8878).
- pm-guard denies the bound Architect's trust-anchor writes unless a valid presence grant exists and was used within the last 120 minutes; the deny names `tm presence local` and never asks in the pane. A grant that is missing, idle, forged, symlinked, unreadable or malformed denies. When Remote Control looks active the deny says so; that grants nothing (#8878).
- `tm fleet bind` binds a running Architect `claude` that no tm launch recorded, from its own tmux pane, after the same Touch ID or password prompt, and grants presence in one step. `tm presence` and `tm fleet bind` are trust-anchor writes for PMs, agents and subagents, which pm-guard denies (#8878).
- pm-guard denies every hooked caller, the Architect included, any `security` call whose verb is not a complete literal from a read-only allowlist (`find-generic-password`, `find-internet-password`, `find-identity`, `find-certificate`, `help`), after skipping redirections and `security`'s own options; `-i` and `-p` deny. It reads every `security` word, inline or in a script the command runs; no verb, or a plain word that is no verb nor a verb's prefix (prose such as "harden security for X"), passes because `security` runs nothing for it. It also denies a Keychain API call naming the presence key item (service `trusty-mpm.presence`). Residuals accepted for PR2a (#10865): an interpreter (`python3` `keyring`, `osascript`) or a shell-built command name (`S=security; $S …`) that assembles a name at run time, and through them `security list-keychains -s` shadowing the item. #10865 adds the access-list check (`SecKeychainItemCopyAccess`); until it ships the key is not trusted for any approval decision, and a forged grant only restores pre-PR2a behaviour: the Architect's anchor writes needed no grant on main, and no call denied without a grant is approved because of one. A process outside any hook can still pre-plant or replace the item, or replace `tm` itself (#8878).
- The presence key moves to the sandbox key file only under the full sandbox marker (`TRUSTY_SANDBOX=1`, a `TRUSTY_DATA_DIR_OVERRIDE`, and a `$HOME` that is not the account's); `TRUSTY_SANDBOX=1` alone keeps it in the Keychain (#8878).
