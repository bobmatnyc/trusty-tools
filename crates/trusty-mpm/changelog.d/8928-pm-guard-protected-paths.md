Added
- `tm hook --pm-guard` denies a Write, Edit, MultiEdit or NotebookEdit call that targets a Claude Code settings file (`.claude/settings.json`, `.claude/settings.local.json`, the user-tier `settings.json`, `settings.local.json` and `.claude.json`), an `.mcp.json`, a git `config` or anything under a `.git` `hooks` directory, anything under a user config directory's `plugins/`, or a path a hook or `statusLine` command runs (#8928 step 7). Hook commands are read from the settings files and from skill and agent frontmatter `hooks:`; a bare program name is resolved on `PATH`, and a relative path or a bare argument naming a project file resolves against the project root. It also denies a write that gives skill or agent Markdown under `.claude/skills` or `.claude/agents` a new or changed frontmatter `hooks:` key. Names compare with Unicode case folding, as APFS does, so `.claude/ſettings.local.json` is denied too; the trust-anchor floor's path comparison gains the same folding. The rule binds the PM and every subagent; the Architect's main thread is exempt. A settings file or frontmatter that does not parse, a target that does not resolve and an edit whose result cannot be reproduced each deny. The rule is dormant while `[pm_guard] enabled = false`.
