Breaking
- Decision ids reach the answer API (#9841). `AnswerParams` and `AnswerRequest` gain `decision_id` and `answered_by`, `AnswerResponse` gains `decision_id`, `ActivityResponse` and `managed_routes::session_summary::SessionSummary` gain `pending_decision_id`, and `SessionRecord` gains `pending_decision_id` and `last_answer`, so code that builds any of them with a struct literal must set the new fields (`None` keeps the previous behaviour). `SessionManager::answer_decision` takes a third argument, the `AnswerClaim`, and returns `Result<Option<DecisionId>, ManagedError>` instead of `Result<(), ManagedError>`. `SessionManager::clear_pending_decision` is removed: an answer now clears the decision as part of its claim, so drop calls to it.
