Breaking
- `tm services` finds trusty-search by calling `search.health` on its Unix socket instead of probing `http://localhost:7878/health` ([#9543](https://github.com/bobmatnyc/trusty-tools/issues/9543)). The socket resolves as the trusty-search client resolves it (`TRUSTY_SEARCH_SOCKET`, else the daemon's data directory). trusty-search is running and UP only when the socket answers, and DOWN, with the error, when the dial fails, is refused or times out; a process matched by `pgrep` is shown as the PID but never makes it running. `port` and `url` are `null`, and `tm services port|url trusty-search` exit 1 naming the socket. trusty-search 0.59.0, which binds no TCP port, depends on this change.
- `ServiceDecl` gains a `health_probe` field of the new `HealthProbe` enum (`http`, the default, or `uds_search`), and both `ServiceDecl` and `HealthProbe` are now `#[non_exhaustive]`: a crate outside trusty-mpm can no longer build a `ServiceDecl` struct literal or match `HealthProbe` exhaustively. This is an accepted break shipped as a minor version bump. YAML manifests without the key behave as before; `uds_search` makes `default_port` and `health_url` optional and skips the `{port}` check.
- A `~/.claude-mpm/services.yaml` whose trusty-search entry is the old static port-7878 HTTP probe is read as `health_probe: uds_search`, with one `WARN` line on stderr naming the file. The file is never rewritten; `tm services init --force` replaces it. Any other trusty-search entry, and every other service, is used as written.
- The default manifest matches the trusty-search process with `trusty-search start`, so a `trusty-search serve` MCP bridge is never reported as the daemon's PID.
- The default manifest starts and restarts trusty-search with `trusty-search start --no-http`, which binds no TCP port and also disables the daemon's auto-discovery scan of `scan_paths`.
