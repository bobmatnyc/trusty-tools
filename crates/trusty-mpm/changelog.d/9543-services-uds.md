Breaking
- `tm services` finds trusty-search by calling `search.health` on its Unix socket instead of probing `http://localhost:7878/health` ([#9543](https://github.com/bobmatnyc/trusty-tools/issues/9543)). The socket resolves as the trusty-search client resolves it (`TRUSTY_SEARCH_SOCKET`, else the daemon's data directory). trusty-search is UP when the socket answers and DOWN, with the error, when the dial fails, is refused or times out; `port` and `url` are `null`, and `tm services port|url trusty-search` exit 1 naming the socket. trusty-search 0.59.0, which binds no TCP port, depends on this change.
- `ServiceDecl` gains a `health_probe` field (`http`, the default, or `uds_search`). A struct literal of `ServiceDecl` must now set it; YAML manifests without the key behave as before. `uds_search` makes `default_port` and `health_url` optional and skips the `{port}` check.
- A `~/.claude-mpm/services.yaml` whose trusty-search entry is the old static port-7878 HTTP probe is read as `health_probe: uds_search`, with one `WARN` line on stderr naming the file. The file is never rewritten; `tm services init --force` replaces it. Any other trusty-search entry, and every other service, is used as written.
- The default manifest starts and restarts trusty-search with `trusty-search start --no-http`.
