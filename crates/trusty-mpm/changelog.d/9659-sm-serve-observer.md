Fixed
- `tm sm serve --stdio` no longer locks the live Session Manager or portfolio palace files. It always reads them read-only through a snapshot copy taken at startup, whether or not the daemon runs, so a daemon started after it opens both palaces as writer, migrates a format-0 palace, and accepts SM `remember` and portfolio writes. With no daemon running, `tm sm serve` reads that snapshot copy; it cannot create a palace or read a format-0 one until the daemon has run once (#9659).
- A daemon that cannot open the SM or portfolio palace as writer (another process holds `kg.redb`) now logs an ERROR, and the portfolio palace reports `palace writer open failed` as its unavailable reason in `GET /manager/version`; it no longer comes up on a read-only snapshot that refuses every write (#9659).
