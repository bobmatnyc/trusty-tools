Fixed
- `tm project init` now writes the project to the persistent registry, so `tm project list` shows it afterwards. Init keeps an existing record with the same name or the same `owner/repo` (an ssh `origin` matches a record stored under the https URL) and never overwrites it; the check and the write share one registry lock. A directory with no `origin` remote is refused with a 400 that names the fix (`git remote add origin <url>` or `tm projects register <name> --repo-url <url>`), and nothing is registered. A registry write failure answers a 500 that carries the store's own error text.
- The Telegram `/projects` "Set Active" button calls the same `POST /projects`, so it now also refuses a directory with no `origin` remote. The bot shows the daemon's message instead of "daemon unreachable" with a bare status.
