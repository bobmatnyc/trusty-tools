Fixed

- `sld-lint`'s scan floor now counts the references it RESOLVED, not just the files it walked. `spec_docs` and `code_files` are walkdir discovery counts, so renaming the `# Spec References` block marker in `trusty_common::sld::inline` — a plausible refactor slip — left the summary byte-identical (`scanned 57 spec doc(s) + 3205 code file(s)`) while the gate flipped from exit 1 to exit 0 with every reference silently unparsed. `LintReport` gains `spec_refs_checked` and `code_refs_checked`, floored independently (26 / 24, set from the measured tree's 40 frontmatter and 37 inline references) because the frontmatter reader and the inline block scanner are separate code paths and either can break alone. Both counts are printed in the summary, so a CI log now distinguishes a real run from one whose grammar matches nothing. `tests/scan_floor_cli.rs` covers the case the existing test could not: its empty root drops the file counts and the reference counts together, so a new fixture keeps discovery at full strength (25 specs, 210 code files) while every reference block uses a marker the parser misses — that tree exits 0 pre-fix.
