Added
- Linux only: `trusty-console start`, `stop` and `restart`, on `trusty_common::linux_lifecycle` (#11085). `start` spawns `serve` from the install dir and returns once it serves the console socket. `stop` exits 1 when no console runs. `restart` stops, confirms the stop, then starts, and starts a console that is not running. A console whose socket bind failed is found through the listener its `http_addr` file names, and is signalled only after the lifecycle module confirms it is this console. `start` and `restart` pass `TRUSTY_CONSOLE_TOKEN_FILE` (the token file's path) to the spawned console, so it keeps its TCP token gate, and `GITHUB_WEBHOOK_SECRET`, so it keeps accepting webhooks. They also pass every non-credential setting of the daemons the console's stdio bridges auto-start (trusty-memory, trusty-search, trusty-analyze, trusty-mpm), so a daemon a bridge starts keeps multi-tenant mode, its embedder model and device, its loader paths, and the analyze facts store path (`TRUSTY_ANALYZER_FACTS`). Other credentials are not passed. macOS is unchanged.
- Limit: `restart` respawns plain `serve`, so `--http`, `--tailscale` and `--poll-interval` given to the original `serve` are not carried over. Set `TRUSTY_CONSOLE_BIND` to keep tailnet exposure across a restart.
- Limit: a restart through `http_addr` of an HTTP-only console whose socket bind keeps failing stops that console; the new child then fails readiness after 60 s, the console stays down, and `restart` exits non-zero (`NotReady`).
