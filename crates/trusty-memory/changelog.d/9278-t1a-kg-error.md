Breaking
- `engine::store::kg_redb::KgStoreRedb::{open, assert, query_active, count_active_triples, upsert_drawer, load_drawer_ids, list_rooms, import_all, apply_batch}` and `engine::store::rooms::resolve_or_create_room_sync` return `Result<_, engine::store::kg::KgError>` instead of `anyhow::Result`, and a `kg_redb::copy_swap::CompactFaultHook` closure returns `Result<(), KgError>`. A caller that uses `?` into `anyhow` or `.context()` is unaffected, and `{e}` and `{e:#}` print the same text, except that a deadline or palace-format error prints only its typed message. `{e:?}` (Debug) now prints the `KgError` enum shape instead of anyhow's `Caused by:` list. `downcast_ref::<WriteTxnError>()` or `<PalaceStoreError>()` on the returned error no longer matches: use `KgError::as_write_deadline()` or `as_palace_store()`. A read-only snapshot store now raises `KgError::ReadOnly`, whose text is `READ_ONLY_ERROR_MSG` as before. `KgError` is `#[non_exhaustive]`; `Closed` and `Other` are message-only and not a stable match target. The struct-like variants `kg::AdjacencyDesync::{CommittedButStale, HandleStale}` and `write_deadline::WriteTxnError::DeadlineExceeded` are `#[non_exhaustive]`, so outside trusty-memory a literal of one no longer compiles and a pattern needs `..` ([#9278](https://github.com/bobmatnyc/trusty-tools/issues/9278))
