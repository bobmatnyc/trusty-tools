Breaking
- `engine::share::{export_palace_jsonl, export_palace_records, write_jsonl, import_palace_jsonl, import_palace_records, supersede_drawer}` (and their `engine` re-exports) return `Result<_, engine::share::ShareError>` instead of `anyhow::Result`. `ShareError` has `ReadOnly`, `Hnsw(HnswStoreError)`, `Palace(PalaceStoreError)` and an opaque `Other`. A caller that uses `?` into `anyhow` or `.context()` is unaffected. An import or supersede into a read-only palace now fails with `ShareError::ReadOnly` before any work, and its text is `READ_ONLY_ERROR_MSG` without the palace id. A vector-store error from `supersede_drawer` comes back as `ShareError::Hnsw` and prints only its own message, without the context prefix. The struct-like variants of `SnapshotError`, `PalaceRenameError` and `RecordError` are `#[non_exhaustive]`, so a pattern outside the crate needs `..` and cannot build them ([#9278](https://github.com/bobmatnyc/trusty-tools/issues/9278))
- `git2` moved from `[dependencies]` to `[dev-dependencies]`; `cargo tree -e normal` no longer lists it, because its only user, `engine::git`, is `cfg(test)` ([#9278](https://github.com/bobmatnyc/trusty-tools/issues/9278))
