Added

- `palace_verify_embedded` answers whether a caller's own drawer ids are vector-findable. A migration or deletion workflow had no way to ask about exactly its ids: `palace_reembed` reports a palace's entire missing set, so the caller had to fetch that dump and diff it, and `memory_recall` is no substitute because it can hit lexically and pass on a drawer no vector search will ever return. Gate on the single `verified` boolean — true only when every requested id is embedded and the alias audit is clean, so a drawer lost to an id collision cannot pass it. `unknown` separates "not a drawer here" from "here but unfindable", and a malformed id is refused rather than skipped ([#5000](https://github.com/bobmatnyc/trusty-tools/issues/5000))
- `palace_embed_sweep` reports vector coverage for every palace on disk, uncapped. `console_metrics` could not serve as a health sweep: it caps at 20 palaces and reads an uncached palace as 0/0, which looks healthy — a fully unembedded palace was invisible to it, and three palaces reporting zero drawers went unexplained. The sweep enumerates from disk rather than the handle cache and opens each palace, reporting the missing-vector set plus the alias audit's key-rows-versus-distinct-ids pair. It never compares `drawer_count` to `vector_count`, which #5005 disproved in both directions ([#5000](https://github.com/bobmatnyc/trusty-tools/issues/5000), [#4786](https://github.com/bobmatnyc/trusty-tools/issues/4786))
