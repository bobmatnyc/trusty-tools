Fixed
- A format-0 palace (0.32.x or older) is no longer refused `FormatTooOld` after an upgrade that skipped a format bump. The first writer-intent open, the daemon's startup, migrates it 0 -> 1 -> 2 behind one verified backup taken before the first step; drawers and facts are unchanged. A read-only or observer open of an older palace is still refused until the daemon migrates it. An interrupted chain resumes from its last committed step, and the record of a 0 -> 1 migration that 0.33.x left interrupted is resumed instead of refused ([#9918](https://github.com/bobmatnyc/trusty-tools/issues/9918))
