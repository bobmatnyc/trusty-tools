Added
- `palace_backup` MCP tool: a consistent backup of a palace while the daemon serves it, under the palace's backup root, `<data root>/.trusty-memory/backups/manual/` (flat layout) or `<data root>/backups/manual/` (legacy `palaces/` layout), at `<palace>/<UTC>/` or at the relative name given as `dest`. `dest` takes plain names only: an absolute path, `..`, `.`, an empty segment and a symlinked segment are refused and no backup is written. It reuses the daemon's cached chat store, returns the backup directory, the manifest counts and the file list, and leaves the vector index out (#9282).
- `trusty-memory palace backup <id> [--dest NAME]`: backs up through the running daemon, or opens the palace directly when no daemon serves the data root; that open takes the exclusive redb lock on `kg.redb` for the length of the backup. `--dest` is a name under the backup root, never resolved against the current directory; a refused name exits 1 on both paths. A failed daemon call is an error, never a fallback (#9282).
- `trusty-memory palace restore <snapshot-dir> [--palace <id>]`: offline restore into an empty palace root, `<data root>/palaces/<id>` in the legacy layout or `<data root>/<id>` in the flat one. It refuses a backup of another palace, a daemon serving the data root, and a probe that cannot tell, before writing anything, and prints the `palace_reembed` step that rebuilds the vector index (#9282).
