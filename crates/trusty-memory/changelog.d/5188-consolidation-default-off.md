Fixed

- **The daemon no longer uses Ollama unless asked to.** `~/.trusty-memory/config.toml` gains a `[semantic_consolidation]` table (`enabled`, `model`) — the dream cycle's LLM phase had no config key at all, so `dream_config_from_user_config` hardcoded it on and a `[semantic_consolidation]` block in the file was parsed and discarded. `[local_model] enabled` now defaults to `false`, and so does the value `load_user_config` returns when the file is absent; it was `true`, which is how a daemon with no config file decided a local model was available and drove a 45 GB `qwen3:30b` into a crash loop the scheduler retried every ~2 minutes. `[local_model] model` no longer leaks into `semantic.model`: name a local server explicitly with `model = "ollama/llama3.2"`. `dream_consolidate_room` / `palace_dream` report zero counts rather than calling a model the operator never configured ([#5188](https://github.com/bobmatnyc/trusty-tools/issues/5188))
- **Integration tests no longer orphan the daemons they spawn.** `serve_stdio_concurrent_e2e`, `serve_stdio_e2e` and `codex_stdio_e2e_5265` each returned a raw `std::process::Child` and killed it at the end of the test body, so any assertion in between — including the readiness-poll assert inside the spawn helper — left a `serve --foreground` behind. An orphan re-parents to PID 1 and keeps its dream loop running against the temp data dir; six accumulated from one `cargo test` run and went on calling a local model. The new `tests/common::DaemonGuard` kills and reaps on `Drop`, which runs on the panic unwind ([#5188](https://github.com/bobmatnyc/trusty-tools/issues/5188))
