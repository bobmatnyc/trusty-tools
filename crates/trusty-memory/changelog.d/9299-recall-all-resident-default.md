Changed
- `memory_recall_all` now searches only the palaces already loaded in memory by default and opens none (ADR-0071, #9299). This reverses the #4637 rule: a drawer in an idle palace is found only with the new optional `scope: "all"`, which keeps the old full search over every non-empty palace on disk, with no time budget. An unknown `scope` is an error.
- Every `memory_recall_all` response, on the MCP tool, the chat tool and `MemoryService::recall_all`, reports `scope`, `coverage` (`"complete"` or `"partial"`), `palaces_total`, `palaces_searched`, `palaces_skipped`, `palaces_not_searched`, `not_searched_by_reason`, `open_failed` and `search_failed` (#9299). `palaces_total` always equals searched plus skipped plus not searched. The chat tool and `MemoryService::recall_all` move from a bare array to an object with `results`; `MemoryService::recall_all_scoped` takes the scope.
- A palace that fails to open during `scope: "all"` is listed in `open_failed` and no longer counted in `palaces_searched`, which used to count attempted opens (#9299).
- A palace whose recall errors after it opened, in either scope, is listed in `search_failed` and no longer counted in `palaces_searched`, so `coverage` reads `"partial"` instead of `"complete"` while its results are missing (#9299).
- A recall_all search no longer resets the idle clock of the palaces it searches, so it no longer keeps the resident set from idle eviction (#9299).
- `not_searched_by_reason` names `not_resident`, `open_failed`, `filter_failed` (the default scope's empty-palace check failed, so its cold palaces stay unclassified), `search_failed` (the palace opened but its recall errored) and `top_k_zero` (`top_k: 0` searches nothing). Only non-zero reasons appear (#9299).
- Both scopes demote a drawer superseded through a `superseded_by` edge below its replacement before the cut, as every other recall surface does (#9299, #9421).
