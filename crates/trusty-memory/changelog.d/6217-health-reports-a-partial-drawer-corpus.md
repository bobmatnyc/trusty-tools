Added

- `GET /health` carries `drawer_degraded_palaces`, naming every open palace whose drawer table loaded only partially. `PalaceHandle::open_with_intent` fails open on drawer-load trouble — a corrupt `DRAWERS` table or an unreadable row does not stop the palace opening, it just yields fewer drawers than the palace holds — and #6201 recorded that on the handle without wiring it to a reader, so the only trace an operator got was a `warn!` line at open time while recall kept answering from a corpus with holes. `status` deliberately stays `"ok"`: a partial corpus is durable state an operator must repair, not an outage a restart can clear, and `status: "degraded"` already means the round-trip probe just failed. The check reads the handle cache via `PalaceRegistry::peek`, so `/health` still does no I/O; the cost is that an idle-evicted palace drops out of the report until it is next opened. The key is omitted entirely when nothing is degraded ([#6217](https://github.com/bobmatnyc/trusty-tools/issues/6217))
