Fixed

- `build.rs` no longer writes `ui/dist/ui-source-hash.txt` when no UI build ran. The #5078 freshness guard called `restamp_bundle` unconditionally, so on a checkout whose committed bundle was already stale, a plain `SKIP_UI_BUILD=1 cargo check -p trusty-memory` rewrote the stamp with the current source digest — turning `check-ui-bundle-freshness.sh`'s `BUNDLE-STALE` finding green while the stale bundle stayed on disk. `build_svelte_ui` now reports whether the package manager's build actually ran, and the stamp is written only then. The guard itself moved into the canonical block `scripts/check_buildrs_sync.sh` polices, so trusty-analyze, trusty-console, and trusty-search share it byte-for-byte instead of carrying three copies that can drift ([#6060](https://github.com/bobmatnyc/trusty-tools/pull/6060))
- `ui/package-lock.json` is untracked and ignored. Nothing read it — CI and every `build.rs` install run pnpm against `pnpm-lock.yaml` — and its only writer was the pnpm-absent `npm install` fallback, which rewrote it with the host platform's optional-dependency set ([#5936](https://github.com/bobmatnyc/trusty-tools/issues/5936))
