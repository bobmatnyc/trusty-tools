Breaking
- `engine::store::ChatSessionStore::{open, create_session}` return `Result<_, engine::store::chat_sessions::ChatSessionStoreError>`, now public, with a new `Palace(PalaceStoreError)` variant for a palace-format refusal at open. `HnswStore::run_bounded` (its closure too) and `UsearchStore::{new, chunk_shapes, upsert_chunks}` return `HnswStoreError`, which gains `Palace(PalaceStoreError)` and an opaque `Other`. A caller that uses `?` into `anyhow` or `.context()` is unaffected; a root `downcast_ref::<PalaceStoreError>()` on a chat-store open error no longer matches, so match `ChatSessionStoreError::Palace`. A typed `HnswStoreError` from `new` or `upsert_chunks` prints only its own message, without the internal context prefix. `op_budget::op_budget_error` takes `&(dyn Error + 'static)`: pass an `anyhow::Error` as `&*err`. The struct-like variants of `ChatSessionStoreError`, `HnswStoreError`, `OpBudgetError` and `PalaceStoreError` are `#[non_exhaustive]`, so a pattern outside the crate needs `..` and cannot build them ([#9278](https://github.com/bobmatnyc/trusty-tools/issues/9278))
