Fixed

- `trusty-memory prompt-context` now emits nothing when nothing is relevant, instead of a paragraph explaining that nothing cleared the relevance floor. The `EMPTY_PLACEHOLDER` fallback and the all-withheld notice are both gone; the partial "N further memories withheld" line stays, appended only to a drawer section that already has content.
- The injected "Relevant KG facts" section admits hot predicates only (ADR-0028 D7) and is capped at 256 bytes. Storage plumbing — `tag:creator:client=… **tags** drawer:…`, `room:General **contains** drawer:…`, `topic:<commit-sha> **mentioned-in** drawer:…` — is no longer rendered to the model as knowledge. Measured against the live `trusty-tools` palace, 54 of 54 stored triples carry a structural or extraction predicate, so that section was 100% noise by count.
- Recalled drawers whose `creator:cwd` provenance tag places them in a different repository are dropped before composition. The filter fails open on an absent tag, an absent session root, or an empty path.
- That filter resolves the session's project root through `trusty_common::palace_resolve::main_worktree_root`, the same probe `resolve_palace` uses to name the palace it is filtering. It previously used a project-marker walk that counts `Cargo.toml` and stops at the first hit, so in a Cargo workspace a session working inside `crates/trusty-memory` resolved its root to that crate while recall ran against the workspace palace — and every drawer written from the repo root or a sibling crate was discarded, uncounted and unlogged. Because `--git-common-dir` names the main repo from inside a linked worktree, an agent worktree under `.claude/worktrees/<name>` and the main checkout resolve to one root without any path-string special-casing. A recorded cwd that lands outside that root is canonicalised and retested before the drop, so a symlinked path is no longer read as another project.
- Inside a submodule, or any repo created with `--separate-git-dir`, that resolver used to answer `<outer>/.git/modules` — the parent of the common dir, which is git internals rather than a checkout. No drawer's recorded cwd can sit under it, so every provenance-tagged drawer failed the containment test and was dropped while the untagged ones survived, degrading recall instead of emptying it. `main_worktree_root` now declines that answer (see the trusty-common fragment for the same issue number), which disables the filter rather than pointing it at an unreachable root.
- `filter_drawers_by_project_scope` now returns what it kept alongside how much it dropped, and logs both numbers plus the resolved session root at `debug`. Two fail-closed defects shipped through this function unobserved because it dropped silently while the relevance floor beside it reported `withheld`; a drop count alone would not have helped either, since it says nothing about the denominator.
