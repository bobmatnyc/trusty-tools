Added
- `trusty-memory palace migrate [<palace> | --all] [--dry-run | --verify] [--yes]` migrates a palace to this binary's format through the daemon's own migration chain: a verified backup under `<data root>/backups/format-migration/<palace>/`, each format step, then a check that the format is current, the `kg.redb` marker and the `palace.json` mirror agree, no `format_migration.json` remains and the drawer and triple counts are unchanged. A failed check exits non-zero and names the backup; nothing is deleted. An interrupted migration resumes; a current palace is left alone with no backup ([#10094](https://github.com/bobmatnyc/trusty-tools/issues/10094))
- `--dry-run` prints each palace's found and target format, the planned backup, its size and the free space, and writes nothing; `--verify` reports each marker as present, missing or mismatched and whether a backup exists, to check a palace converted by hand; `--all` prints the dry-run table first, checks the total free space, and refuses without `--yes` when more than one palace would change ([#10094](https://github.com/bobmatnyc/trusty-tools/issues/10094))
- The `palace_migrate` MCP/RPC tool (`palace`, `all`, `mode`, `yes`); the CLI calls it when a daemon serves the data root and runs in-process when none does ([#10094](https://github.com/bobmatnyc/trusty-tools/issues/10094))
- The `FormatNeedsMigration` and `FormatTooOld` errors and the `trusty-memory doctor` needs-migration line name `trusty-memory palace migrate <palace>` and `--dry-run`; the doctor line also shows the backup root ([#10094](https://github.com/bobmatnyc/trusty-tools/issues/10094))
