Fixed
- `memory_recall`, `memory_recall_deep` and `memory_recall_all` (MCP and HTTP JSON-RPC) now record an access on each drawer a retrieval lane served (layer 2 or deeper, plus user-scope rulings), in the palace that owns it. The count rises in memory at once and is written in one redb transaction 5 s later, before a dream cycle, and when the palace handle drops; a read-only handle records nothing, and a failed write is logged and retried without failing the recall. Recalled drawers now carry the access boost into rank, dream prune and fading. The counts live in a new `drawer_access` table in `kg.redb`; an older binary reads its drawers as before but its KG compaction refuses the unknown table ([#9881](https://github.com/bobmatnyc/trusty-tools/issues/9881))
