Fixed

- A corrupt BM25 snapshot is now renamed to `bm25_index.json.corrupt-<millis>` before `PalaceBm25Index::load_or_create` hands back an empty index. It used to log one warning and leave the unparseable file where it was, so the first write after the failed load marked the index dirty and the next `flush` renamed a one-document snapshot over the palace's last-known corpus — silent, permanent, and reported nowhere. Serving empty stays the behaviour, because the corpus is rebuilt from redb by the startup backfill; what changes is that the bytes survive long enough for that to matter. A quarantine rename that fails now fails the load instead of proceeding to an index whose first flush would destroy the file ([#5909](https://github.com/bobmatnyc/trusty-tools/issues/5909))
