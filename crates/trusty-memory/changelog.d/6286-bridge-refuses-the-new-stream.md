Fixed
- **The MCP stdio bridge would have hung on `memory.activity_stream`.** Its `STREAMING_METHODS` list is a second copy of the daemon's `STREAM_METHODS` — the bridge refuses a streaming method before it dials, so it cannot ask the router what was registered — and the new method was added to the daemon and not to the list. A method the daemon streams and the bridge does not know is forwarded as an ordinary call, leaving the client waiting for a single response frame that never arrives. `bridge_streaming_methods_match_the_daemon` now pins the two equal ([#6286](https://github.com/bobmatnyc/trusty-tools/issues/6286))
