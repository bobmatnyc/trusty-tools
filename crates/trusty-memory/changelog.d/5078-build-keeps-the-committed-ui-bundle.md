Fixed

- `build.rs` no longer rebuilds the Svelte UI when the committed `ui/dist/` bundle already matches the UI source, so a plain `cargo build` or `cargo test -p trusty-memory` leaves the working tree clean. It used to run the package manager's install and a full `vite build` on every cold build: the install rewrote the tracked `ui/package-lock.json` with the host platform's optional-dependency set (39 deletions on macOS), and `vite build` emptied `ui/dist/`, deleting the tracked `ui-source-hash.txt` the publish-time freshness gate reads. Freshness is decided by `scripts/check-ui-bundle-freshness.sh`, the same check `preflight-publish.sh` runs, and an unreadable answer keeps the committed bundle rather than rebuilding it. `FORCE_UI_BUILD=1` rebuilds unconditionally and re-stamps the bundle afterwards, which is what a UI change now needs ([#5078](https://github.com/bobmatnyc/trusty-tools/issues/5078))
