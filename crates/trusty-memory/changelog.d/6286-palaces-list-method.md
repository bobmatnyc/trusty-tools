Added
- **`memory.palaces_list`** — one row per palace with REAL counts, and a per-palace error field. It is the contract the retired `GET /api/v1/palaces` carried, with the counts that route could not supply: it used `PalaceRegistry::peek` since #4640, so it reported `cached: false` and placeholder zeros for any palace not already resident. Neither that nor `palace_list` (bare ids) is a roster with counts, which is why consumers were fanning out one `memory.palace_get` per id ([#6286](https://github.com/bobmatnyc/trusty-tools/issues/6286))
  - a row carries `id` always, and exactly one of `palace` and `error`. A palace the daemon could not open is a row saying so — never an omission, and never a row of zeros a reader would take for a measurement. That is the shape the fan-out could not express: it dropped a failed palace at `debug!`, so a panel could report more palaces than it had rows for
  - it opens every palace, which is the same cost as the fan-out it replaces (the same opens, one round trip instead of N) rather than a new one. `MemoryService::list_palaces` stays the cheap approximate roster
