Added
- **`memory.activity_stream`** — every daemon event as it happens, streamed. It is what `/sse` was: the first pass at this migration retired that listener with nothing in its place, leaving the monitor TUI polling `memory.activity` on a 2-second tick, so an event showed up to two seconds late and one evicted from the activity log between two ticks was never shown at all. This subscribes to the same `broadcast::Sender<DaemonEvent>` the SSE handler used and forwards each event as one stream item carrying the same `type`-tagged body the `data:` lines carried ([#6286](https://github.com/bobmatnyc/trusty-tools/issues/6286))
  - history is NOT replayed. The stream begins at the subscription, exactly as `/sse` did; a reader that wants what came before asks `memory.activity`
  - a reader that falls behind gets a `{"type":"lagged","lagged":N}` frame rather than a silent gap. A `broadcast` receiver drops what it missed, and a feed with an invisible hole reads as a continuous one
