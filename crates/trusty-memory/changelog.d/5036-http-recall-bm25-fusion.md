Fixed

- The daemon's recall route and `memory_recall_deep` now run the lexical lane alongside the vector lane, reusing the RRF fusion `memory_recall` has had since #156. The path the `UserPromptSubmit` hook actually takes — `prompt_context` → the recall route → `MemoryService::recall` → `memory_core::retrieval::layers` — had no BM25 anywhere on it, so a prompt was answered by vector centroid with no lexical counterweight: a one-word prompt returned unrelated drawers at full confidence, and short keyword-bearing curated facts retrieved poorly. Both paths key the lane on the resolved palace id, so an aliased palace reads the corpus the backfill wrote. The fusion only boosts drawers the vector lane already returned, so it has no scaling constant that can degenerate when the surviving set is empty ([#5036](https://github.com/bobmatnyc/trusty-tools/issues/5036))
