Breaking
- `engine::store::kg::KnowledgeGraph::{open, assert, retract, query_active, list_subjects, count_active_triples, neighbors, shortest_path, reachable, incoming, connected_components, astar_path, upsert_drawer, upsert_drawer_sync}` return `Result<_, engine::store::kg::KgError>` instead of `anyhow::Result`. A caller that uses `?` into `anyhow` or `.context()` is unaffected, and `{e}` and `{e:#}` print the same text, except that a deadline, adjacency-desync or palace-format error prints only its typed message. `{e:?}` (Debug) now prints the `KgError` enum shape instead of anyhow's `Caused by:` list. Any downcast of the root of an error from these paths now meets `KgError`, so a root `downcast_ref` to `WriteTxnError`, `AdjacencyDesync`, `PalaceStoreError`, `io::Error` or a redb error no longer matches: use `KgError::as_write_deadline()`, `as_adjacency_desync()` or `as_palace_store()`. A write on a read-only graph raises `KgError::ReadOnly`, whose text is the full `READ_ONLY_ERROR_MSG` with its routing advice, not the shorter text the coalescing writer used to return ([#9278](https://github.com/bobmatnyc/trusty-tools/issues/9278))
