Breaking
- `engine::retrieval::{shared_embedder, embed_chunks, recall_with_default_embedder, recall_deep_with_default_embedder}`, `PalaceHandle::backfill_missing_vectors` and `engine::dream::Dreamer::dream_cycle` return `Result<_, engine::EngineError>` instead of `anyhow::Result`. `EngineError` gains the variant `Embed`, which carries an embedder that could not be built or failed to embed; like `Other`, its payload is message-only and `{e:#}` prints the whole cause. A failed embedder init in the two recall functions and in the backfill is `Embed` and no longer starts with `acquire shared embedder for ...`. A recall, backfill or dream-cycle fault that is not an embedder failure maps as the write paths do (`Palace`, `Kg`, `Hnsw` or `Other`). `?` into `anyhow` still compiles, but a `downcast_ref` to a trusty-memory store error on the resulting error returns `None`: downcast to `EngineError` and match the variant ([#9278](https://github.com/bobmatnyc/trusty-tools/issues/9278))
