Breaking
- `engine::retrieval::PalaceHandle::{open, open_with_intent}` return `Result<_, engine::EngineError>` instead of `anyhow::Result`. `EngineError` is `#[non_exhaustive]` with `Palace(PalaceStoreError)` and an opaque `Other`; a later release may move a case out of `Other` into a new variant. A format refusal from the open gate (a newer, unmigrated or too-old palace) is `EngineError::Palace`. `?` into `anyhow` still compiles, but `downcast_ref::<PalaceStoreError>()` on the resulting error now returns `None`: downcast to `EngineError` and match `EngineError::Palace` ([#9278](https://github.com/bobmatnyc/trusty-tools/issues/9278))
- A palace-store error that the open path wraps in a context message is `EngineError::Palace` and prints only its own text; the context prefix is dropped, as for `HnswStoreError` and `ShareError`. Provisional (#9278 Q7): reverting this one change keeps such an error in `EngineError::Other` with its prefix ([#9278](https://github.com/bobmatnyc/trusty-tools/issues/9278))
