Added
- `trusty-memory palace reclaim [--dry-run] [--json]` lists what a reclaim would remove, with path, size, mtime, palace and reason: `*.v2-incompatible` files, `kg.redb.*.bak` backups, empty palaces idle 30+ days, directories without `palace.json`, a stale `uds_addr`, and trusty-code e2e fixture turn drawers. The dry run is read-only: drawer tables are read from private copies (#9140).
- `trusty-memory palace reclaim --apply --manifest <FILE>` acts only on the items in a reviewed `--json` dry run that a fresh scan still lists unchanged (same path, size and mtime, or same palace and drawer id). Each item moves by rename to `<palace-root>/.trash/<UTC-date>-reclaim/` at its relative path, recorded in that dir's `manifest.json`. A palace whose store the live daemon holds open is skipped; fixture drawers are exported to the trash as JSON and then removed through the daemon's `memory.drawer_delete`. Any item left in place makes the exit non-zero. The command help documents a manual restore from `manifest.json` (#9140).
- `trusty-memory palace reclaim --purge-trash` deletes reclaim trash dirs more than 7 days old. It removes only real directories directly under `<palace-root>/.trash/` that are named `<YYYY-MM-DD>-reclaim` and hold a `manifest.json`, and refuses a root that is `/`, the home directory, or an ancestor of it (#9140).
