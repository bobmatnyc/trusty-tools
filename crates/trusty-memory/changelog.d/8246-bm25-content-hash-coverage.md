Fixed

- **BM25 backfill coverage is content-aware, so an edited drawer stops matching its old text.** Coverage was established by asking the index which drawer ids it held. An in-place edit keeps the id, so a corpus holding the pre-edit text answered "present", the pre-flight probe short-circuited to `AlreadyIndexed`, and neither the repair sweep nor a restart ever re-indexed the drawer — the lexical lane answered for text the palace no longer had and not for the text it did. The probe now asks by `(drawer id, text)`: an id held at different text counts as missing and is re-fed. The retained document text is the revision, so pre-existing snapshots are read and served unchanged, with no migration and no mandatory rebuild ([#8246](https://github.com/bobmatnyc/trusty-tools/issues/8246))
