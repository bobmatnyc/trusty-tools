Fixed

- The BM25 lane no longer loses a palace's writes when the eviction flush fails. Both eviction sites removed the index from the LRU first and only then flushed it, logging a failure and dropping the owned index at the end of the arm — so an unwritable snapshot directory took the palace's unflushed documents with it, invisibly beyond one `warn!` line. Eviction now flushes in place and removes an index only once its snapshot is on disk; a palace that cannot be persisted stays resident and the next-coldest is evicted instead. When nothing can be flushed, the budget sweep stays over budget and retries on the next tick, and a cold load fails rather than buying its slot with another palace's writes ([#5887](https://github.com/bobmatnyc/trusty-tools/issues/5887))
- The budget sweep no longer re-flushes a palace it has already failed to flush. An unflushable palace stays resident and therefore stays coldest, so every later eviction in the same sweep retried it from the top — and the flush clones the whole corpus and serialises it before the write that fails, so each retry was O(corpus) wasted while holding the lane lock. The sweep now carries the failures across its evictions and skips them; the set is per-sweep, so the next tick still retries a directory that has since become writable ([#5887](https://github.com/bobmatnyc/trusty-tools/issues/5887))
- `Bm25Lane::loaded_count` no longer counts a load that was discarded because no slot could be freed, so the diagnostic stops over-reporting in exactly the degraded state an operator reads it in ([#5887](https://github.com/bobmatnyc/trusty-tools/issues/5887))
