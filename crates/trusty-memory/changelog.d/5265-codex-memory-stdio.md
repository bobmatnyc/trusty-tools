Fixed

- `trusty-memory setup` now registers the Codex CLI as well as Claude Code, writing `[mcp_servers.trusty-memory]` into `~/.codex/config.toml` with the real argument vector `["serve"]`. Codex previously had no registration written by trusty-memory at all, so whatever an operator had hand-edited — an empty vector, a joined `"serve --stdio"` string, or a whole vector serialized as one JSON-looking string — stayed in place while Codex listed the connection as enabled and exposed no tools. Re-running setup repairs each of those shapes, and every other table and comment in the config survives byte-for-byte (#5265).
- Both registrations now carry bare `serve` instead of `serve --stdio`. Bare `serve` has spoken MCP over stdio since #5267, so the flag selects nothing; a legacy `["serve", "--stdio"]` entry in a Claude settings file or a Codex config is rewritten on the next setup run (#5265).
- `trusty-memory doctor` reports one verdict per MCP client: the registered executable and its own `--version`, the effective argument vector, the stdio transport contract, and the palace and data directory the session will bind to. A vector that never reaches `serve` fails the check, a legacy `--stdio` vector warns, and a missing global Claude settings file says which project-local files were not scanned rather than reporting nothing (#5265).
