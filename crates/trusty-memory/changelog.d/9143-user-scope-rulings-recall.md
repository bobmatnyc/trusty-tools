Added
- `TRUSTY_MEMORY_RULINGS_PALACES` (optional, comma-separated palace ids, e.g. `<palace>,<palace>`) names user-scope palaces whose ruling-tagged drawers (`bob-ruling`, `owner-ruling`, `ruling`, `bob-decision`, `decision`, `standing-rule`, exact match) join `memory_recall` and `memory_recall_deep` at layer 1. Only those two MCP tools, on their ready path, get this leg; the warming path, `memory_recall_all`, the `MemoryService` methods and the chat surfaces do not. The leg runs only for an unscoped recall (no `room` or `wing`) and never in multi-tenant mode. Each palace is searched on the blocking pool under a 2 s bound, with the same BM25 fusion as the project hits; a failed palace is skipped for 60 s. Rulings are de-duplicated by drawer id and content hash and contribute at most `ceil(top_k / 3)` hits. A palace that is absent, unreadable, failing or slow is reported in a `rulings_degraded` list of `{palace, reason}` in the recall response, and the project hits are still returned; the field is absent when nothing failed. Unset or blank, the variable changes nothing: no extra palace is opened and the response has no new field (Refs [#9143](https://github.com/bobmatnyc/trusty-tools/issues/9143))
