Fixed
- **`trusty-memory note` wrote nothing and exited 0.** It still resolved `read_daemon_addr` and POSTed `/api/v1/remember`, a route ADR-0032 retired — and every failure arm printed a warning and returned `Ok(())`, so an agent that lost its memory saw a clean exit and had no way to learn it. It calls `memory.remember_async` over the socket now, and a write the daemon did not accept exits non-zero. Fire-and-forget describes what the daemon does after it accepts the write, not what the CLI reports about whether it was accepted ([#6286](https://github.com/bobmatnyc/trusty-tools/issues/6286))
- **Hook activity rows stopped being recorded.** `hook_emit::post_hook_event` POSTed `/api/v1/activity/hook` and returned silently on a miss, so `prompt-context` and `inbox-check` — the only daemon traffic in a normal Claude Code session — populated nothing and the activity feed stayed empty. It calls the `hook_fired` dispatcher method over the socket now. The emit stays best-effort, deliberately unlike `note`: an activity row is telemetry alongside output the user is waiting for
- **`trusty-memory port` reported "no daemon running" whether or not one was.** There is no TCP port and nothing writes `http_addr`, so its resolver answered `None` on every machine forever. It reports the Unix socket the daemon binds, and exits non-zero only when nothing is serving it — the `$(trusty-memory port)` contract is unchanged
