Changed
- The Channels view has a scope toggle. **Assistant** is the per-assistant bindings it always showed, unchanged. **Global** lists the host-wide channels from `GET /api/channels` — provider, destination (empty means account-wide), the enabled/send/receive switches, and `route_to` as a multi-select over the assistants on this host — and saves them through `PUT /api/channels` with the channel-write credential attached.
- The Assistant scope now names, read-only, the global channels that also route to that assistant, with a control that switches to the Global scope. A global channel can wake an assistant without appearing in the assistant's own list, so that list no longer reads as the complete picture.
- A failed channel write says the same thing in both scopes: a missing write credential is reported as "Channel writes need the daemon's write credential; restart the daemon or start it with --api-token" rather than the daemon's own wording, a lost compare-and-swap in the Global scope reloads the list and says another writer changed it, and a validation refusal shows the server's own `error` field.
- A global channel may route to a name `GET /api/agents` does not list — `pm`, `ctrl`, or a hidden assistant — because the server validates `route_to` against the unfiltered dispatch roster. The Global scope offers those names alongside the catalog and keeps them selected, so editing one channel's routes never drops another route the catalog cannot see. A failed catalog read says so instead of reading as "no assistants configured".
