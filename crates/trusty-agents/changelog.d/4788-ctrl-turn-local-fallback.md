Fixed

- the standalone ctrl REPL route (`ctrl_turn::dispatch::run_ctrl_turn_via_rest`) no longer surfaces a raw `Connection refused` from an unreachable local model as the assistant's reply. It carried the same defect [#4779](https://github.com/bobmatnyc/trusty-tools/pull/4779) fixed on the PM route — an error arm gated `local_qualifies && fallback_on_error`, where `local_qualifies` ANDs in `local_inference.enabled`, so the setting meaning "avoid Ollama" was exactly what guaranteed an Ollama transport error was unrecoverable. Both conversational surfaces now share one decision function that gates on the FAILURE (a transport-level failure of a model that resolved to a local adapter) and takes no preference flag as an input; genuine API errors (429/401/500) from either a local or a remote model still propagate unchanged (closes [#4788](https://github.com/bobmatnyc/trusty-tools/issues/4788))
