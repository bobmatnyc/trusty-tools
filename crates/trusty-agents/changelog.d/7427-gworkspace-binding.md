- gworkspace (Gmail) is a two-way channel binding. A binding's target is a correspondent (`from:alice@example.com`, globs included) or a label (`label:INBOX`); incoming mail arrives on the existing Gmail history-poll listener and a message a binding addresses dispatches through that binding instead of the generic `[[listeners]]` wake, never both. One Gmail poll cycle spends at most one assistant turn across both paths, so a burst from one bound correspondent no longer buys one model dispatch per message — the rest are stored, shown in the Events pane, and counted per binding as `rate_limited` in the channel view. Outgoing messages go through `trusty-gworkspace`'s Gmail compose: a turn woken by an inbound message replies in its thread, any other turn opens a fresh message to the bound address; a glob or label target has no single address, so opening a fresh message on one is refused with a 400 rather than composing a literal `*@example.com` recipient. A gworkspace binding names no `credential_ref` — Gmail authenticates with its own account token store, and routing that through the credential authority is deferred (#7427).
