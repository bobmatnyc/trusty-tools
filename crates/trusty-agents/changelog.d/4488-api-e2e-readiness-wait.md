Fixed

- The `api_e2e` test harness no longer decides readiness on a 5s latency budget. `ApiServer::spawn` polled `/api/health` — condition-based already — under a ceiling small enough to be a bet on the machine being idle, so the suite was green on CI's single-tenant runner and red 3/3 locally at load 22–38. The ceiling is now a genuine "something is wrong" bound rather than an expected-latency one, a child that exits fails immediately with its status instead of sitting out the ceiling, each probe is individually bounded so one stalled request cannot consume the whole wait, and the child's stdout/stderr are drained continuously — which both removes a full-pipe-buffer hang and puts the child's own output in the failure message. `wait_for_task` likewise retries a failed poll instead of treating one transport hiccup as a terminal failure (#4488).
