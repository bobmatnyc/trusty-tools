Fixed

- The system-status UDS probe applies its budget once. `probe_uds` wrapped `send_framed_request_capped` — which already bounds the whole dial-write-read exchange with the same `PROBE_TIMEOUT` — in a second `tokio::time::timeout`, so the outer layer could only ever lose the race and reported nothing the inner one did not ([#6286](https://github.com/bobmatnyc/trusty-tools/issues/6286))
- `uds_daemon_with_no_socket_reports_up_false` no longer races its siblings. It set `TRUSTY_DATA_DIR_OVERRIDE` across two `.await` points without holding `test_env::ENV_LOCK`, while `daemons::tests::unresponsive_daemon_times_out_rather_than_hanging` sets the same variable under that lock — so the two could interleave in one test binary. It now takes the lock and restores the prior value from a `Drop` guard, which also survives a failing assertion ([#6286](https://github.com/bobmatnyc/trusty-tools/issues/6286))
- The `agent_stores` memory mock answers only `memory.drawers_list`. It ignored the method name, so rewiring the palace probe onto `palace_create` — which a status probe must never call, because it creates the palace it is asking about — would have left these tests green ([#6286](https://github.com/bobmatnyc/trusty-tools/issues/6286))
