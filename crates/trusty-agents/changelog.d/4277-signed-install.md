Added

- **Developer-ID-signed local installs** — `scripts/install-trusty-agents-signed.sh` (`make install-agents-signed`) builds `tagent` from local source and signs it via `tctl sign trusty-agents` (a new `AGENTS_SET` in `trusty-installer`'s Developer-ID codesign single source of truth), and best-effort (re-)signs an already-built `Trusty Agents.app` desktop bundle, fixing macOS re-prompting for permissions on every rebuild ([#4277](https://github.com/bobmatnyc/trusty-tools/issues/4277)) — `cargo install`/`cargo tauri build` previously produced ad-hoc-signed artifacts with a new identity every time, so TCC revoked the grant each time.
  - `Trusty Agents.app`'s `tauri.conf.json` deliberately carries no hardcoded `signingIdentity` (unlike `trusty-mpm-gui`/`trusty-code-gui`, where that hardcoding hard-fails `cargo tauri build` on a machine without the exact certificate) — the install script instead exports `APPLE_SIGNING_IDENTITY` (Tauri's own build-time override) only when a certificate is found, so a machine with no Developer ID cert still gets a working, ad-hoc-signed build rather than a failure.
  - Every signing step is fail-soft: no certificate present leaves both artifacts ad-hoc signed with a clear warning and the script still exits 0, matching `install-trusty-search-signed.sh` / `install-trusty-mpm-signed.sh`.
