Fixed

- A parallel phase that asked for worktree isolation no longer runs without it. `WorktreeManager::create` used to answer any git failure — an unreadable `rev-parse HEAD`, a refused `git worktree add`, a path it could not hand to git — with a plain `mkdir -p` in the shared tree and a `warn!`, so the caller received a directory it believed was isolated and wrote into the base checkout instead. That is the write-clobbering scenario the module exists to prevent. Every one of those failures is now an `Err`, git's own stderr is carried in the message, and `run_parallel_phase` fails the phase rather than substituting a shared-tree subdir when `worktree_protection` is set. The signature is unchanged; an `Ok` from `create` is now always a real worktree ([#4734](https://github.com/bobmatnyc/trusty-tools/issues/4734))
