Changed
- Channel providers now sit behind one `ChannelAdapter` trait and a registry (`crates/trusty-agents/src/channels/`), with Slack as the reference implementation and Telegram declaring `can_receive: false` instead of a hard-coded rejection. `agent_channels::send`, `messages`, `Binding::validate` and the providers listing dispatch through the registry, so a provider with no adapter — Notion, gworkspace — is refused at save time rather than stored and left inert.
- A channel binding can name the credential it sends as: `credential_ref` holds `env:<NAME>`, never a token value, and resolves at send time into a non-serialisable `Secret`. An unknown scheme is an error, not a fallback to the process-global bot token; a binding with no reference keeps the previous behaviour.
- A failed inbound wake dispatch is now observable. `receive_slack` used to spawn the dispatch and discard its result, so a failing assistant turn produced no log line and left the binding reading as healthy; it now logs at error level with the binding id and increments a per-binding failure counter published as `status` in the channel view.
