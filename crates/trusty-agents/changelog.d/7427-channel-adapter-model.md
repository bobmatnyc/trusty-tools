Changed
- Channel providers now sit behind one `ChannelAdapter` trait and a registry (`crates/trusty-agents/src/channels/`), with Slack as the reference implementation and Telegram declaring `can_receive: false` instead of a hard-coded rejection. `agent_channels::send`, `messages`, `Binding::validate` and the providers listing dispatch through the registry, so a provider with no adapter — Notion, gworkspace — is refused at save time rather than stored and left inert.
- A channel binding can name the credential it sends as. `credential_ref` holds a `trusty_common::credentials::CredentialRef` (`slack`, `slack-app`, `telegram`, or a qualified `slack/second-workspace`) and resolves at send time through `trusty_common::credentials::authority::resolve`, inheriting the env → `.env.local` → secure-store precedence and returning a non-serialisable `Secret`. The reference is confined to the adapter's own provider family and to that provider's environment-variable prefix, so a Slack binding cannot name `github` or forward an unrelated credential. A binding with no reference resolves the provider's default key, which is the credential it used before.
- A failed inbound wake dispatch is now observable. `receive_slack` used to spawn the dispatch and discard its result, so a failing assistant turn produced no log line and left the binding reading as healthy; it now logs at error level with the binding id and increments a per-binding failure counter published as `status` in the channel view.
- A send whose credential cannot be resolved now answers `502` with a message naming the binding's credential reference, instead of the generic provider-request failure.
