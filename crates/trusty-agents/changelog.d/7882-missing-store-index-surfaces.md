Fixed
- A bound OKG store naming a trusty-search index that does not exist now reports an explicit error instead of the same soft "not connected" state a stopped daemon produces (#7882). `StoreStatus` gains `fault` (`invalid_binding` / `daemon_unreachable` / `missing_index` / `index_unhealthy`) and `error`, the operator-actionable message naming the assistant, the store and the index id; `error` is set only for the standing-misconfiguration class, so a down daemon stays distinguishable. Each probe that hits the case logs a WARN to stderr, and `tagent system status` gained an "OKG stores" section that renders it.
