Added

- Telegram now delivers incoming messages to an assistant through a channel binding, not only outgoing ones. A binding whose target is a Telegram chat id may enable `receive_enabled`, and the `--telegram` long-poll gateway routes a plain-text update for that chat into `agent_channels::receive_inbound` — the same function, wake envelope, filters, binding instructions and per-binding dispatch-failure counter Slack has used since #7427 PR 1. An update from a chat no binding names is logged at debug and falls through to the gateway's own session, so a host with no bindings behaves exactly as before. The gateway's bot token now resolves through the credential authority under the binding's `credential_ref` rather than a direct `TELEGRAM_BOT_TOKEN` read, and a token that will not resolve fails startup instead of polling without one. A reply still reaches the chat only when the persona calls the `channel` tool, which goes through `TelegramAdapter::send` ([#7427](https://github.com/bobmatnyc/trusty-tools/issues/7427))
