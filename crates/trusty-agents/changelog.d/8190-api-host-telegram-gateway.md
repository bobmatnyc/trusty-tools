Fixed

- `tagent --api` now runs the Telegram long-poll gateway in-process, so a channel-bound Telegram chat can reach an assistant on the API host. The `--api`/`--serve` branch previously returned straight into the HTTP server and started the gateway nowhere, which left Telegram receive dead on the production host (`tagent --api --port 8765`) even with a configured bot token and an enabled binding. The gateway starts only when an enabled receiving Telegram channel exists — an assistant binding, or a global `[[channels]]` telegram entry with `route_to` — AND the bot token resolves AND no other poller holds the machine-wide PID lock; each of those three refusals logs one line saying why, and the API host otherwise starts exactly as before. A second concurrent poller is refused rather than started, because Telegram terminates the older `getUpdates` when a second one begins. A poller that fails or returns while the server is still up is logged and restarted with exponential backoff (5s doubling to a 5-minute cap) and never fails the HTTP server, and API shutdown stops the poller and releases the PID lock ([#8190](https://github.com/bobmatnyc/trusty-tools/issues/8190))
