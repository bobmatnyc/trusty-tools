Fixed
- **`system_status` reported trusty-memory and trusty-analyze permanently down.** Both probes resolved `resolve_daemon_base_url` and issued `GET /health` against an address neither daemon publishes any more — ADR-0032 moved memory onto a Unix socket ([#6286](https://github.com/bobmatnyc/trusty-tools/issues/6286)) and [#6287](https://github.com/bobmatnyc/trusty-tools/issues/6287) did the same for analyze — so the resolver answered `None` on every machine and the pane reported both down whether or not they were running. They dial `memory.health` and `analyze.health` over their sockets now, keeping the `version` and `search_reachable` fields the pane renders. trusty-search and trusty-mpm are unchanged: they still serve HTTP
