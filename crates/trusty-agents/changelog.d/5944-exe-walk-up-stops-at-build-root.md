Fixed

- Self-project detection no longer climbs from the running executable to the filesystem root. It now requires a `target/` ancestor and resolves that directory's parent, so `cargo run`, a `cargo test` binary and a release binary invoked from an unrelated cwd still find the checkout they were built from, while an installed `~/.cargo/bin/tagent` stops resolving `$HOME` as the project. The old climb read the executable's real location and consulted no environment, so a run with `$HOME` pinned to a tempdir still matched the developer's real `~/.trusty-agents/agents/pm.toml` and wrote `.trusty-agents/state/build.json` into the real home ([#5944](https://github.com/bobmatnyc/trusty-tools/issues/5944), residual of [#4826](https://github.com/bobmatnyc/trusty-tools/issues/4826))
