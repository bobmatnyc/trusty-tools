Changed

- MCP connections now come from the shared `trusty-mcp` config with per-assistant overrides (#7454, ADR-0060). The three per-agent server schemas — `mcp::config::McpService`, `tools::registry::config::EndpointConfig` and `mcp::mcp_json::McpJsonServer` — collapse onto `trusty_mcp::config::McpServerConfig`, with their consumer-specific knobs (`tools`, `discover`, `scopes`, `discovery_ttl_secs`, `eager_discovery`, `auth`) moved into `extensions` behind typed accessors.
- The global server list loads from `~/.trusty-tools/mcp/servers.toml`, the file shared with `trusty-code`, seeded once from the retired `[[mcp.services]]` and `[[tool_registry.endpoints]]` tables. A malformed shared file starts the assistant with zero MCP servers and a visible warning rather than the stale tables.
- Each assistant's `<home>/config.toml` gains an `[mcp]` table that adds, replaces or disables a server for that assistant alone, resolved through `trusty_mcp::config::resolve`. A malformed override table falls back to the global set with a status naming the file, and a server whose credential does not resolve is skipped with a per-server status instead of failing the registry.
- `GET`/`PUT /api/assistants/{id}/mcp`, an MCP-connections section in the assistant Knowledge pane, and `tagent mcp list [--assistant <id>]` show the global tier, this assistant's overrides and the effective set together.
- `PUT /api/assistants/{id}/mcp` treats `servers` as optional: omitting it keeps this assistant's own servers, while sending it — an empty list included — still replaces them wholesale. `disabled` is unchanged and always replaces wholesale.
