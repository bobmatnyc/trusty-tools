Fixed
- The native memory tools (`store_memory`, `retrieve_memory`, `list_memory_keys`, `memory_recall`) no longer address a process-global palace (#7443). `Segment::AgentMemory` used to resolve to one `trusty-agents-mem` drawer for every caller, so two assistants served by one process would have read and written each other's memories the moment a backend was wired in. `MemoryScope` now folds the calling assistant into the palace key, and it is #7428's own palace resolution that supplies the identity rather than a new setting. `TrustyBackedMemoryStore::new_for_assistant` and `TrustyMemoryClient::new_for_assistant` key their palaces by that scope, and the file-backed store also roots its durable payload sidecar under it, because the sidecar is what a `get` actually reads. `open_assistant_memory_backend` is the only way production code obtains a backend for the native tools, and it refuses outright when an assistant resolves to no palace — never a fall-through to the shared one. Unscoped stores keep their existing palace ids, so the single-tenant seeders and CLI paths read the palaces they already wrote.
