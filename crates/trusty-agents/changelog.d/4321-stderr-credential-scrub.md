Security

- Credentials no longer reach the subprocess-failure narrative. A workflow subprocess inherits every provider credential the API server holds, and the same change that started surfacing the child's stderr to the user routes that text into the task narrative, `.trusty-agents/state/tasks.json`, and the GUI chat view — so a child that echoed a key into its own error message would have published it. Each captured stderr line, and the assembled narrative, now pass through `trusty_common::credentials::scrub_secrets` against the credentials this process resolves. The scrub runs before the per-line truncation, so a key straddling the length limit cannot leave a fragment behind. It catches only values this process holds; a secret it never resolved is still passed through unchanged ([#4321](https://github.com/bobmatnyc/trusty-tools/issues/4321))
