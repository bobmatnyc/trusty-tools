Breaking
- Channel writes now require a bearer credential, even from loopback. `PUT /api/channels`, `PUT /api/agents/{name}/channels`, the deprecated `PUT /api/agents/{name}/listeners` alias, the `channel` tool's `set` actions and the turn-originated `settings.patch/channels` and `settings.patch/listeners` ops all answer 401 without one. A daemon started with `--api-token` (or `TAGENT_API_TOKEN`) uses that token; a tokenless loopback daemon mints an ephemeral per-boot credential instead and publishes it to the UI it serves via `GET /api/config` (same-origin callers only) and to local non-browser clients via a `0600` file beside the `http_addr` discovery file, so the served Channels tab keeps working. A tokenless non-loopback bind is still refused at startup. Reads are unaffected and the same-origin write guard is unchanged. Every accepted write emits one `channel-write` audit line naming route, scope, assistant, the stored count either side, and the caller's address.
