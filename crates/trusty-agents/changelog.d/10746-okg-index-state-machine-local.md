Changed
- The OKG index feed runs through `trusty_okf::feed`, and its index state lives in this machine's data area (`<data dir>/trusty-agents/okf-index-state`), never in the synced KB tree (#10746 S12, SPEC-OKF-01 §4.9.1). Two machines that share one tree no longer read each other's indexed state. `kb::okg::index_journal` and `stores::index_feed` are removed.
- The first feed after upgrade migrates each `_sources/<id>.index.jsonl` once into this machine's state as pending paths: live files are re-pushed and probed by this machine's daemon, vanished or tombstoned ones are withdrawn. The legacy files stay in place, unchanged.
- A feed pass now covers every concept in the tree, not only the ingesting source's, and a put counts only when the daemon replies `indexed: true`. The `index` report gains a `status` field (`unconfirmed` until search indexes report an identity). `pending` counts an entity until a retrieval probe confirms it, and a tombstone until its withdrawal is confirmed.
