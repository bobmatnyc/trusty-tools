Fixed

- the shared LLM HTTP client now carries a 10s connect timeout and a 300s read timeout. It had neither, so a live-but-unresponsive endpoint — a half-open local `ollama` listener, in the reported case — blocked an agent turn with no ceiling at all; the only bound anywhere was a caller-supplied wrapper in one test, and that test threw its result away. `read_timeout` rather than a total `timeout` is what keeps a long completion working: it resets after every successful read, so only a connection that goes silent for the whole budget is abandoned ([#5943](https://github.com/bobmatnyc/trusty-tools/issues/5943))
- a timeout is no longer retried by the LLM backoff wrapper. Four attempts against a wedged endpoint spent the read budget four times over — twenty minutes rather than five — and an endpoint that produced no byte for five minutes does not produce one on the retry. Connection-refused and DNS failures stay retryable ([#5943](https://github.com/bobmatnyc/trusty-tools/issues/5943))
