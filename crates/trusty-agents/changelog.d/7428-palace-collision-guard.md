Fixed
- `PUT /api/assistants/{id}/memory` refuses a `palace` that another assistant already owns, and `ensure_palace` asks `memory.palace_get` before it creates (#7428). Without the first, an assistant that binds no palace could claim another's by name and then recall from and persist into it; without the second, the create ran on every turn and trusty-memory's `palace_create` rewrites an existing palace's metadata rather than refusing the name. `POST /api/agents` now writes `extends = "assistant"` on an assistant-role agent, so an agent created through the UI is discovered as an Assistant instance instead of 404ing on every per-assistant route.
