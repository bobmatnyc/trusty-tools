Fixed

- An assistant can no longer widen its own permissions through `ask_concierge` (#7396). The tool is registered on every attended turn and reaches `settings.patch`, whose grant fields (`[permissions].scopes`, `[tools].allow`, `[skills].allow`, `[subagents].delegate_allowed`) are the same lists every later permission check reads — so a turn steered by ingested document text, an attached table cell, or a listener excerpt could grant itself scopes and then pass every `scope_granted` check. A turn-originated patch is now bounded by the assistant's resolved manifest grants and may only narrow them; a widening request is refused whole with the offending entries named, and the manifest is left untouched. The `permissions` and `memory` sections are `settings.get` only from a turn: permission grants and the cross-palace memory read switch change through the operator-authenticated Settings routes. The operator route (`PATCH /api/agents/{name}`) is unchanged and still grants.
- An unreadable `filters.json` no longer drops an inbound listener event (#7396). `is_event_type_included_at` had flipped to excluded-on-error, and `included == false` makes the poll loop skip both knowledge intake and the agent wake — in the same pass that has already recorded the event id for dedup and advanced the provider's cursor, so the message was lost permanently with only a warning. A filter-file failure now resolves to the documented default (included), and the Events history endpoint renders its rows instead of failing outright.
- `GET /api/agents/{name}` no longer rewrites the agent manifest (#7396). The read called the legacy memory-grant migration, which takes the cross-process manifest lock and writes the file, so every read serialized behind that lock and a lock or I/O failure became a 500 on a plain read. The repair now applies to the served view only; the dispatch, knowledge-pipeline and subagent entry points still persist it.
- Memory tool calls no longer block a runtime worker while resolving their grants (#7396). `operation_granted` reads the manifest and walks the skill sources synchronously; it now runs under `spawn_blocking`, matching the policy resolution beside it.
- One per-turn attachment budget now covers both pathways (#7396). `attachments` (manifest ids) and `inline_attachments` (prepared bodies) were capped independently, so a request setting both collected the sum of two budgets; every attachment on either list is rendered into the turn and replayed as history on every later turn, which is the cost the cap was chosen against. The combined count is now checked against `MAX_ATTACHMENTS_PER_TURN`.
