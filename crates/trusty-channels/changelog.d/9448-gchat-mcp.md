Added
- New `gchat-mcp` binary: a stdio MCP server for one project's Google Chat channel, with exactly four tools. `gchat_ask {to, text}` posts a question through a reviewed route and returns its id and message name; `gchat_notify_review {to, text, url}` posts a review notice with an https link and opens no question; `gchat_answer {question_id}` (read-only) returns `open`, or `answered` with only that question's answer text and time, and its description marks the answer as untrusted text from an external person; `gchat_doctor` (read-only) returns the doctor rows from the server's own channel plus the poller's last error. Every send goes through the route gate. A refused send is a tool error naming the refusal reason, never the message text, and a question that was posted but not recorded is its own `sent_not_recorded` error with the id, never retried. The project dir comes from `--project-dir`, else `TRUSTY_CHANNELS_PROJECT_DIR`, else the current directory. The server holds the project's single channel and is the only Pub/Sub poller (`--poll-interval-secs`, default 5); a second server on the same project exits with a message naming the held state lock. A batch in the Workspace add-on event format is logged as an error naming that setting. stdout carries JSON-RPC only; logs go to stderr. `gchat-mcp doctor [--project-dir D] [--offline]` prints one row per route (recipient, kinds, load gate, key file and mode 0600, token mint unless `--offline`, DM space, open questions, subscription) and exits non-zero when the load or any check fails; while a running server holds the state lock, the state columns read "in use by a running gchat-mcp" and do not fail. The `state` module (ledger, spaces file, audit log) is now crate-private, so only a lock-holding channel writes it (refs [#9448](https://github.com/bobmatnyc/trusty-tools/issues/9448))
