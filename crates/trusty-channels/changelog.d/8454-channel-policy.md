Added

- New `policy` module: a channel-neutral, deny-by-default route table for gchat, Slack and Telegram, built from already-parsed data (no file loading yet). `ChannelPolicy::build` fails, never trims, on a name or (channel, recipient) shared by two routes (both entries named), an empty kind list, `review_notice` on a Slack or Telegram route, a malformed name or recipient (Slack takes a user ID, Telegram a positive chat id), and a rate limit that is zero, negative, NaN, out of range or above the default. `check_egress` allows only a route naming the exact recipient with the kind listed; `check_inbound` accepts only a routed sender's answer to exactly one open, unanswered question its route owns. `RateLimiter` keeps an in-memory token bucket per (channel, route), 100 tokens refilled at 100 per 60 s by default, plus a separate bucket for unknown senders, on an injected monotonic clock. gchat behaviour is unchanged (refs [#8454](https://github.com/bobmatnyc/trusty-tools/issues/8454))
