Added

- New `policy` module: a channel-neutral, deny-by-default route table for gchat, Slack and Telegram, built from already-parsed data (no file loading yet). `ChannelPolicy::build` fails, never trims, on a name or (channel, recipient) shared by two routes (both entries named), an empty kind list, `review_notice` on a Slack or Telegram route, a malformed name or recipient (Slack takes a user ID, Telegram a positive chat id), and a rate limit that is zero, negative, out of range or looser than the default (a higher limit or a shorter window). `check_egress` allows only a route naming the exact recipient with the kind listed; `check_inbound` accepts only a routed sender's answer to exactly one open, unanswered question its route owns. `RateLimiter` keeps an in-memory sliding-window admit log per (channel, route) that admits at most `limit` messages in any `window_secs` (default 100 per 60 s), plus a separate window for unknown senders, on an injected monotonic clock; a clock reading that goes backwards is refused. gchat behaviour is unchanged (refs [#8454](https://github.com/bobmatnyc/trusty-tools/issues/8454))
