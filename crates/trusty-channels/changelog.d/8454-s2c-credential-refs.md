Changed

- The host `channels:` section names a Slack or Telegram credential by role: `connection: { bot_ref: slack, app_ref: slack-app }`. `bot_ref` is the token that posts and is required in any `connection`; `app_ref` is Slack's Socket Mode token and is optional. Both hold a trusty-common provider key, never a value. `credential_ref` is no longer read: a file that still names it is refused with an error naming `bot_ref` and `app_ref`. The host is also refused, denying every route, for a `bot_ref` naming `slack-app` or `slack-user`, an `app_ref` on Telegram, a `secret://` reference, or a value outside the slot's provider keys; the error never repeats the value. `HostChannel::credential_ref()` is replaced by `bot_ref()` and `app_ref()`, and `HostError::CredentialRef` now carries the key and a `RefFault` (refs [#8454](https://github.com/bobmatnyc/trusty-tools/issues/8454))
