# Changelog

All notable changes are documented in this file.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

---

## [0.2.0] — 2026-10-30

### Added

- The host ceiling accepts `channels.slack_read_allowlist`, a list of `{project, name, tools}` entries read strictly (#10387). `tools` may hold only `slack_read_channel` and `slack_read_thread`; a wildcard, another tool, a relative or `..` project, a project listed twice, or an unsafe `name` refuses the whole host. `read_host_ceiling` reads and parses the host file alone, under the same symlink and canonical-path rules as the full load.

## [0.1.1] — 2026-10-26

### Added

- `LoadReport` has a new public `fingerprint: u64` field. A report from a `PolicyLoader` whose load settled carries a nonzero digest of the sources it was loaded from, and the digest changes whenever the loader reloads. A load that did not settle (#9808), a one-shot load and the placeholder report carry 0, which means a cache must never key on that report (#8454).
- A new `trusty_channels::audit` module exposes the channel audit record and log that gchat already writes: `AuditRecord`, `AuditEvent`, `AuditLog`, `clip` and `StateError`. `AuditRecord` gains `channel`, `project`, `commit`, `author`, `committed_at` and `routes` fields and `AuditEvent` gains `RouteChanged`; both are `#[non_exhaustive]`. `AuditLog::record_all` appends a batch with one write and one fsync, and `AuditLog::owner_only` creates its file 0600 and narrows an existing one; when an owner-only append fails partway, the file is cut back to its length before the write, so every line stays a complete record. gchat's own state files keep their mode (Refs #9832, #8433).
- `FileStatus` has a new `verified_commit` field: the default-branch commit the load gate verified an `Effective` file's bytes against, `None` for any other state. `policy::commit_author` returns the author and commit time of the last commit at or before a given commit that changed `.trusty-channels/routes.toml`; it accepts only a 40 or 64 character lowercase-hex object id (Refs #9832).

### Fixed

- An owner-only `AuditLog` append now holds an exclusive file lock from the length read through the write, the fsync and any cut-back. A failed append no longer truncates away a record another writer appended to the same file in between. When the file ends in a torn line, the next owner-only append starts on a line of its own instead of joining the fragment (Refs #8433).
- `PolicyLoader` now samples its fingerprint after a load reads the files, and keeps it only when it equals the sample taken before the read and matches the host text, the canonical-path verdict and every project file the load read. Otherwise it keeps none, so the next `refresh` reloads. Before, a route or host change that was reverted before the next `refresh` left the changed policy published until the files changed again (#9808).
- `slack_read_canvas` and `slack_read_file` work again. The Slack client now sends `files.info` and the other read methods it calls (`conversations.info`, `conversations.history`, `conversations.replies`, `conversations.members`, `users.info`, `reactions.get`, `emoji.list`) as a GET with URL-query parameters. Slack ignored the POST JSON arguments on these methods and answered `invalid_arguments`. A `files.info` failure now names the method, e.g. `invalid_arguments (from files.info)` (Refs #9919).

## [0.1.0] — 2026-10-11

First release. Refs [#8454](https://github.com/bobmatnyc/trusty-tools/issues/8454).

### Added

- Three MCP server binaries. `gchat-mcp` (four tools) and `telegram-mcp` (three tools) build by default. `slack-mcp` (22 `slack_*` tools) sends with no route check, so it builds only with the non-default `unrouted-slack-mcp` feature: `cargo install trusty-channels --features unrouted-slack-mcp`. A plain `cargo install trusty-channels` installs `gchat-mcp` and `telegram-mcp` only. The `slack::server` and `slack::handlers` modules also need that feature; `slack::api`, `slack::tools` and `slack::canvas_markdown` are in the default build.
- Slack tools (`slack-mcp`, `unrouted-slack-mcp` feature only): send, read, list, search, reactions, scheduled messages, conversation creation, channel members, file reads, emoji and user search, and canvases (`slack_create_canvas`, `slack_update_canvas`, `slack_read_canvas`, plus the `slack_canvas_*` tools below). `slack_search_messages` takes an optional `scope` (`"public"` | `"public_and_private"`, default `"public_and_private"`) and caps `count` at Slack's documented 100 (a larger value is reduced, not rejected). `slack_read_channel` and `slack_read_thread` take an opaque `cursor` plus `oldest`/`latest` bounds and return `next_cursor`/`has_more`; `thread_ts`, `oldest` and `latest` are validated as Slack `seconds.microseconds` timestamps before any network call, and `conversations.*` `limit` is clamped to Slack's 999. Channel and user listing parameters are sent as GET queries so Slack honors the requested limits and types. Required OAuth scopes are in the README. `slack_send_message_draft` is not implemented: Slack has no public draft API (#3616).
- Slack canvas tools (`slack_canvas_create`, `slack_canvas_lookup_sections`, `slack_canvas_push`; epic #3744). `slack_canvas_create` and `slack_create_canvas` given a `channel_id` create a channel canvas via `conversations.canvases.create`, so every channel member can edit it; without `channel_id` they call `canvases.create`. When the channel already has a canvas, the error names it and points to `slack_canvas_push` (a failed lookup degrades to the bare Slack error). `slack_canvas_lookup_sections` returns section ids and anchors only. `slack_canvas_push {canvas_id, markdown, mode}` translates CommonMark with `slack::canvas_markdown` and applies it: `append` is one `insert_at_end` edit; `replace_all` deletes each header-delimited section, then appends, as sequential single-operation `canvases.edit` calls (not atomic; a canvas with no header sections is appended to, with a warning). `canvas_editing_locked` is retried with bounded backoff. The response is `{ok, canvas_id, operations_applied, warnings}`. The translator records every downgrade (h4-h6 to h3, HTML stripped, footnotes flattened) as a warning, fails a table over Slack's 300-cell cap with `TranslationError`, and passes Slack mention syntax through unchanged. The canvas scopes `canvases:read` and `canvases:write` may need an app reinstall before a live token carries them.
- `policy`: a channel-neutral, deny-by-default route table for gchat, Slack and Telegram. `ChannelPolicy::build` fails, never trims, on a name or (channel, recipient) shared by two routes, an empty kind list, `review_notice` on a Slack or Telegram route, a malformed name or recipient, and a rate limit that is zero, negative, out of range or looser than the default. `check_egress` allows only a route naming the exact recipient with the kind listed; `check_inbound` accepts only a routed sender's answer to exactly one open question its route owns.
- `policy::RateLimiter`: an in-memory sliding-window admit log per (channel, route), at most `limit` admits in any `window_secs` (default 100 per 60 s), plus one window for unknown senders, on an injected monotonic clock; a backwards clock reading is refused. `take_binding` takes a window by (channel, name) without a `Route`. A restart resets the windows.
- `policy` two-file route model: `parse_host` strictly parses the `channels:` section of trusty-mpm's `config.yaml` (unknown keys denied at every level; per-channel `enabled`, `projects`, optional `kinds` ceiling and connection refs), `parse_project_file` parses a project's `routes.toml` v1 (gchat) or v2 (adds Slack and Telegram routes and per-route rate limits), and `merge` returns a `LoadReport` that always carries a policy, empty on a deny. A host-ceiling fault or a route overlap across two files denies every route of the consumer whose channels it touches; a broken or widening project file refuses only that file; a disabled channel or unlisted project drops its routes with a named finding. An error never repeats a value from a file.
- Host credentials: a Slack or Telegram connection names `connection: { bot_ref: slack, app_ref: slack-app }`. `bot_ref` is the token that posts and is required; `app_ref` is Slack's Socket Mode token and optional. Both hold a trusty-common provider key, never a value, exposed as `HostChannel::bot_ref()` and `app_ref()`. A legacy `credential_ref` is refused with an error naming `bot_ref` and `app_ref`. The host is also refused, denying every route, for a `bot_ref` naming `slack-app` or `slack-user`, an `app_ref` on Telegram, a `secret://` reference, or a value outside the slot's provider keys; the error never repeats the value.
- `policy::load_effective` and `PolicyLoader`: `load_effective` reads `config.yaml` and each project listed for the consumer's channels and returns a `LoadReport`; `PolicyLoader` reloads it when a file, a repo's `HEAD` or its default-branch commit changes. A project's `routes.toml` takes effect only when the project dir is the top level of its own git repo, `HEAD` is on the default branch (`origin/HEAD`, else the one of `main`/`master` that exists; a detached `HEAD` is refused), and the bytes read equal the file at that branch's commit, read locally with no fetch. A git step running longer than 10 s is killed with its process group and refused as `GitTimedOut`. `load_effective_until(req, deadline)` bounds git by the caller's deadline: each step runs for at most the lesser of 10 s and the time left, and every project not yet loaded is refused as `GitTimedOut`. A missing home directory, a missing or symlinked host file or config directory, a host file whose real path is not `~/.trusty-tools/trusty-mpm/config.yaml` under the real home, a symlinked `projects` entry, or an oversized host file denies every route. Host and route files are opened without following a symlink or waiting on a FIFO; a symlinked, oversized, malformed, non-UTF-8 or unreviewed project file refuses only that project. On reload a refused project keeps its last reviewed routes, marked `Stale`; a host fault denies all at once; a reviewed narrowing applies at once; rate-limit windows are kept.
- `gchat::api`: a Google Chat API layer for a Chat app reached over Cloud Pub/Sub. `GchatClient` loads a service-account JSON key (refused unless its mode is exactly 0600, before any network call), mints RS256 JWT-bearer tokens for the `chat.bot` and `pubsub` scopes, caches them until five minutes before expiry, and pulls and acknowledges a subscription. Posting and token minting are crate-private, so a message reaches Chat only through `gchat::GchatChannel` and its route check. A malformed pulled message is a per-message error that keeps its ackId. No `Debug`, `Display` or error text carries key material or a token.
- `gchat::GchatChannel`: per-project Google Chat routes, an egress gate and a question ledger. Routes load from `<project>/.trusty-channels/routes.toml` (schema version 1; an unknown key, an empty or unknown kind, a non-email recipient, or a duplicate name or recipient fails the load). `routes.toml` takes effect only on the project's default branch, under the same gate as `policy::load_effective` (the project dir is its repo's top level, `HEAD` is on the default branch, and the bytes read equal the file at that branch's commit, compared by git object id); a refused load refuses every send, and the refusal is `RouteError::Gate { path, reason }` carrying a typed `policy::GateError`. `send_question` and `send_review_notice` check the route, the kind, a review notice's https URL and the route's learned DM space before any token or Chat request; each refusal is written to `state/audit.jsonl` without the message text. A question carries a visible `[Q-<n>]` token and a thread key; `process_batch` and `poll_once` bind a reply from the route's recipient in its DM by thread name, else by token, resolve exactly that question once, and drop and audit everything else, including any `BOT` sender. An unparseable pulled message is audited before it is acknowledged; a batch in the Workspace add-on event format is a distinct error. A question posted but not recorded returns `SendError::SentNotRecorded` with its id and message name, so the caller does not resend it. Only one `GchatChannel` may hold a state directory (`StateError::Locked`). A torn final ledger line from a crash is moved to `questions.jsonl.torn` and audit-logged. `health` reports one row per route. `RouteError`, `SendError`, `StateError` and `InboundError` are `#[non_exhaustive]`.
- A `[[gchat.routes]]` entry accepts an optional `space = "spaces/<id>"`; several routes may share one space. A space route posts to that space with no learned DM binding, accepts a reply only from its recipient in a `SPACE` or `GROUP_CHAT` space, and never touches `state/gchat-spaces.json`. Refusals are audited as `direct_message_on_space_route`, `space_type_not_allowed`, `configured_space_mismatch` and `space_not_configured`.
- Google Chat inbound rate limit: each route admits at most 100 messages in any 60 s, and all senders with no route (no email, no route match, or a `BOT` sender) share one more window of the same size. The take runs after the route lookup and before any space or ledger entry is touched, so a limited message resolves no question and learns no space. It is dropped and acknowledged once its `rate_limited` audit line is written (a failed audit write withholds the ack); one audit line is written per bucket per window, and later drops are counted. A backwards clock drops the message. `BatchReport` and `PollStatus` carry a `rate_limited` count, a limited drop never fails a poller tick, and `gchat-mcp doctor` prints a `limiter:` line.
- `gchat-mcp`: a stdio MCP server for one project's Google Chat channel with four tools. `gchat_ask {to, text}` posts a question through a reviewed route; `gchat_notify_review {to, text, url}` posts a review notice with an https link and opens no question; `gchat_answer {question_id}` (read-only) returns `open`, or `answered` with only that question's answer text and time, marked as untrusted text from an external person; `gchat_doctor` (read-only) returns the doctor rows plus the poller's last error. A refused send is a tool error naming the reason, never the message text; `sent_not_recorded` is its own error with the id. The project dir comes from `--project-dir`, else `TRUSTY_CHANNELS_PROJECT_DIR`, else the current directory. The server is the only Pub/Sub poller (`--poll-interval-secs`, default 5); a second server on the same project, or for the same subscription from any project dir, exits naming the held lock (state lock; per-user subscription lock under `trusty-channels/gchat-locks/`). A tick that leaves a pulled message unacknowledged counts as a poller failure shown by `gchat_doctor` with a `withheld` count. stdout carries JSON-RPC only; logs go to stderr. `gchat-mcp doctor [--project-dir D] [--offline]` prints one row per route (recipient, kinds, load gate, key file and mode, token mint unless `--offline`, DM space or `configured` space, open questions, subscription) and exits non-zero when the load or any check fails; while a running server holds the state lock, the state columns read "in use by a running gchat-mcp" and do not fail. The `state` module is crate-private.
- The manifest carries the crates.io metadata for a first publish (rust-version, repository, readme, keywords, categories, homepage), and the package ships `src/`, `README.md` and `CHANGELOG.md` only. The README describes what 0.1.x does and does not enforce.

### Changed

- MCP protocol primitives come from the `trusty-mcp` crate (`trusty_mcp::…`), and credentials from `trusty_common::credentials` (ADR-0040, [#5803](https://github.com/bobmatnyc/trusty-tools/issues/5803), [#4564](https://github.com/bobmatnyc/trusty-tools/issues/4564)).
- `slack::handlers` is a module tree to stay under the 500-SLOC cap; `dispatch` is its public entry point.

### Documentation

- Every rustdoc intra-doc link resolves, and the crate root has `#![deny(rustdoc::broken_intra_doc_links)]` (#5744).
