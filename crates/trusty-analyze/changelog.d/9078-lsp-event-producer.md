Added

- With `ANALYZE_LSP=1`, every `analyze.lsp_*` call pushes two events to the trusty-events bus as source `analyze` (DOC-72 §4): `ActionEvent::Tool` with phase `started`, then `finished` or `errored`, sharing one `call_id`. The tool names are `lsp.textDocument/references`, `lsp.publishDiagnostics` and `lsp.analysed_at`. The Started event's `parent_id` is the call's `parent_event_id`; the terminal event's `parent_id` is the Started event. Events carry metadata only, in `attrs`: language, position, workspace, document version, snapshot, `result_count`, `duration_ms` and `outcome` (`ok` or the `lsp_*` error code). They carry no source text, no diagnostic messages and no absolute path under `$HOME` (shown as `~/...`). Pushes only buffer, bounded and counted, so a missing or slow bus never delays or fails a call; a flush runs every second and once, bounded to 1 s, on idle exit, on SIGTERM and when `serve --mcp` ends on stdin EOF (the daemon task is now stopped through its exit path instead of aborted). With the flag off nothing is pushed and the bus socket is not resolved (Refs #9078).
