Added

- `analyze.lsp_diagnostics`, `analyze.lsp_references` and `analyze.lsp_analysed_at` on the analyze socket, with the MCP tools `lsp_diagnostics`, `lsp_references` and `lsp_analysed_at` (DOC-72 §5). Positions are `path` plus zero-based `line` and `column`; every answer carries `document_version` and a `<git head>+<dirty hash>` `snapshot`, computed under a 10 s deadline and a 2,000-file / 64 MiB budget and refused as `lsp_snapshot_failed` past either; a `version` other than the file's current one is refused as `lsp_stale`; a file's diagnostics, and the `lsp_analysed_at` barrier, come from a pull (`textDocument/diagnostic`) after the server has loaded, because rust-analyzer pushes a set only when it changes; the pull is merged with the `cargo check` push (rust-analyzer's pull omits check findings such as E0382), counted only for the opening version because `cargo check` runs only at startup and rust-analyzer stamps a push with the version current when it publishes; without it the answer is `complete: false` with `reason: "check_not_run"`; a newer sync landing while the pull is in flight is refused as `lsp_stale`; pushed sets for other files that arrive without a version are marked `unversioned`; untracked files inside new directories are part of the snapshot; `scope: workspace` takes a file and answers `complete: false` (a directory is refused); `lsp_analysed_at` blocks until a version is analysed and answers `ready` or `timed_out` with `version_seen`, capped at the MCP client timeout minus 30 s. Every read waits for rust-analyzer's `experimental/serverStatus` to report quiescent, so a loading server's empty answer is never returned; past the request timeout the call is refused as `lsp_not_ready`, and a server that reports `health: "error"` (it could not load the workspace, for example a broken `Cargo.toml`) is refused as `lsp_workspace_failed` without echoing its message. An optional `parent_event_id` is accepted. Off unless `ANALYZE_LSP=1`; every refusal is error code `-32006` with `data.kind` (`lsp_disabled`, `lsp_not_ready`, `lsp_file_not_found`, `lsp_outside_workspace`, `lsp_unsupported_language`, `lsp_timeout`, `lsp_hung`, …), which the MCP tools keep in their error text. A server answering "content modified" (-32801) while it loads is retried with backoff inside the request timeout (Refs #9078).
