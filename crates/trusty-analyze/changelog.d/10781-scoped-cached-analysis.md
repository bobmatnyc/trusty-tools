Added

- `analyze.complexity_hotspots`, `analyze.smells` and `analyze.quality` accept an optional scope: `paths` (changed files) and/or `path_prefix` (one directory). A scoped call walks only `search.chunks.list` pages filtered by each entry, never the whole corpus, and answers with `scoped: true` and `scope: {paths, path_prefix, unmatched}`, where `unmatched` names each entry that selected no chunks. A trusty-search that ignores `path_prefix` is refused rather than allowed to page the corpus. An entry naming the index root is `invalid_params`: `.`, `/`, `a/..`, and any absolute spelling that resolves to the index `root_path` — `/repo`, `/repo/`, `/repo/.`, or a symlink to it. An absolute entry containing `..` is also `invalid_params`, because trusty-search resolves a symlink before `..` and `/elsewhere/link/..` can land on the root. A scoped walk whose first page reports as many chunks as the whole index is also refused as `invalid_params`, before it pages the corpus; omit the scope for the corpus-wide result. More than 500 entries is `invalid_params`; `paths: []` selects nothing (Refs #10781).
- Unscoped calls to the same three methods are served from a per-index cache instead of walking the corpus in the request. An entry is current while `search.index.status` reports the same `last_indexed`, `chunk_count` and `status` it was computed against, and for at most 15 minutes. Otherwise it is served with `cache.status: "stale"` and a `stale_reason` while one background refresh runs. On a cold cache a request of the pre-#10781 shape waits for the corpus walk and returns its result, as before, and the walk fills the cache; concurrent cold callers share one walk. A caller that passes the new optional field `allow_warming: true` instead waits up to 5 s, then gets the new retryable error code `-32007` with `data: {"kind": "analysis_warming", "retryable": true}`. A warm or stale cache answers at once either way. A failed refresh is an upstream error, and no new refresh starts for 30 s. An index trusty-search reports as not found answers `not_found` and its cache slot is dropped; a failed status read creates no slot. Every unscoped response adds `scoped: false` and a `cache` object; the existing fields are unchanged. The cache keeps the top 1000 hotspots, so a `top_n` above 1000 also returns `hotspots_capped_at: 1000` (Refs #10781).
- A chunk page that fails in transport (for example a timeout) is retried up to 4 times, halving the page limit down to 100, and the smaller limit is kept for the rest of the walk. A walk that still fails names the cursor, the attempt count and the last limit. A page that trusty-search answers with an error is not retried, and the #6043 short-export refusal still applies (Refs #10781).
