Added
- `dashboard::pyupdates` and the `trusty-architect-dashboard-updates` binary port the frozen `dashboard_updates.py`: `note <task-id> "<text>" [--by <who>]` and the ingest pass that appends `{at, by, text}` update entries from the relays, PM handbacks, task notes and the items' own answer, relay and done state onto the one `kind: task` item of each IL task. Every write is a `dashboard_store.py`-port update with `if_version` under the shared `flock`; the pass is idempotent on `(at, text)`; a failed listing is an `errors` entry with exit 0 and a version conflict a `conflicts` entry. `TAG`, `BARE` and `HANDBACK` are matched by hand with Python `re` semantics (lookarounds, `\b`, Unicode `\d` and `\s`). Not wired into the poller. (#12029 P2h)
- `dashboard::pyattach` ports the frozen `dashboard_attach.py` as a library: `clean_name` (with Python's NFC, from generated tables), `attach_dir` (with `dashboard_il`'s schedule read and session-name rule; a missing or broken schedule falls back to the Architect's IL), the symlink-refusing item directory, `save` (temp file hashed as it streams, fsync, `link`, `-2` to `-999`), `record` (five conflict retries, at most 20 attachments, the saved file removed when the record fails), `handle_upload` and `serve_file`; a bad `DASH_ATTACH_MAX_MB` falls back to 25 MiB. (#12029 P2h)
- The recordings of both frozen modules replay clean through `examples/replay_port.rs dashboard_updates` and `dashboard_attach` in both store formats. Intended divergences, each with its test: the owner-answer update text reads `Owner answered <id>: ...` where the frozen script names the owner; an exception the update script does not catch prints its last traceback line and exits 1; a `DASH_ATTACH_MAX_MB` past `u64` bytes saturates. `check_item` is not ported. (#12029 P2h)
