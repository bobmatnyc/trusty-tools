Added
- `dashboard::store::py`, the port of the Architect's `dashboard_store.py` on Python-typed values: `get`, `list_docs`, `collections`, all-or-nothing `batch` and the one-op forms, `add` and `seed_meta`, in both the `dir` and `jsonl` formats, with the prototype's bytes, versions, request refusals, prune log, change log, schema warn and enforce modes, rollback and error text. It takes the same `flock` on `<root>/.lock`; a lock or replace failure is returned as an error. Five recordings of the frozen module replay clean (#12029).
- One writer class per dashboard collection: the Python-class writer (the prototype's port) claims each collection it writes in `<root>/.lock`, and a batch from the other class on a claimed collection, or on a letter-case variant of one, is refused with `DashError::WriterClass` before anything is written, the change log included. A collection name outside `[A-Za-z0-9_.-]` is refused before its claim; a torn last claim line is ignored and cut by the next claim, and a failed claim append is cut back. The daemon's Rust `Store` writes no claim to a live root until the P2g cutover (#12029).
