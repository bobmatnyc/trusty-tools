Added
- The dashboard store appends one `changes.jsonl` line per changed document after each commit, in both formats: `{by, collection, id, keys, op, seq, sha256, ts, version}` with a strictly increasing `seq` and the SHA-256 of the bytes written; it rotates by month into `changes-YYYY-MM.jsonl` without ever overwriting a rotated file, and a batch whose log append fails returns `Unlogged` (the documents stay committed) instead of succeeding silently ([#10063](https://github.com/bobmatnyc/trusty-tools/issues/10063))
- `PruneLog`, the dashboard's delete archive at a configurable path outside the served root: each deleted document's full record `{by, collection, data, deleted_at, id, version}` is appended and fsynced before the delete, a failed append leaves the document in place, and `lines(id, collection)` returns the raw records, prototype lines included ([#10063](https://github.com/bobmatnyc/trusty-tools/issues/10063))
- `Store::fsck` (corrupt or non-canonical files, change-log gaps, reversals and torn lines, a document whose version or bytes differ from its last change line, a deleted document still present) and `Store::validate` (every document against its schema plus the prototype's goal and item cross references); a missing store root is an error, never clean ([#10063](https://github.com/bobmatnyc/trusty-tools/issues/10063))
- The dashboard store refuses an op holding a secret-shaped value, naming the op and the shape but never the value, and refuses every write when no secret scan is configured; the scan walk is shared with the PM ledger writer ([#10063](https://github.com/bobmatnyc/trusty-tools/issues/10063))
- The dashboard store refuses a write of an id or collection that differs from an existing one only in letter case, in both formats, and a read never answers one id with another id's file (on APFS `A01.json` and `a01.json` are one file); `media` ids share the per-prefix id space ([#10063](https://github.com/bobmatnyc/trusty-tools/issues/10063))
