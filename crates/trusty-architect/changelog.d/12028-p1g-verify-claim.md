Added
- `trusty-architect-verify-claim`, the Rust port of the Architect's `verify-claim.py` and `verify_claim_input.py`, in the library module `verify_claim`: it checks the claims of one PM-message event (PR head, base, merge commit, state, merge time, file and commit counts, check buckets, CI run, issue states, local-checkout commits, crates.io max version) and prints one `MATCH`, `MISMATCH` or `UNCHECKED` line per claim. A GraphQL rate limit falls back to REST; `VERIFY_CLAIM_OFFLINE=1` leaves every gh and curl claim unchecked. Every command passes a read-only guard, and a gh child runs without `GH_TOKEN` or `GITHUB_TOKEN`, with `GH_CONFIG_DIR` taken from the owner's `repos` entry. Sixty-six recordings of the frozen scripts replay clean against it, CONFIG errors, bad input, empty input and the guard refusal included (#12028). `local/architect.json` is read under the nearest directory at or above the working directory holding `ARCHITECT.md`, or from `ARCHITECT_CONFIG`; with neither the run exits 1 before any command starts (#12073).
