Added

- `agents::quarantine`: renames untracked project-tier agent files that shadow a bundled agent name to `<file>.md.disabled`, so a claude-mpm-era copy stops winning agent resolution over the canonical tier. `retract_framework_agents` can only see ledger entries and since #4437 nothing deploys into a workspace tier either, leaving those files unreachable by every tm operation — observed live in 4 of 16 sessions on 2026-07-30 and swept by hand on 2026-07-31. It moves ONLY files that are both `ShadowsBundled` and `Untracked`, never writes the ownership ledger, never deletes, and leaves a `TRUSTY-MPM-QUARANTINE.txt` receipt with the `mv` that undoes each rename. Every indeterminate state is a refusal that moves nothing: an empty bundled roster, a corrupt ledger, an unstattable destination, or a destination name already taken ([#4448](https://github.com/bobmatnyc/trusty-tools/issues/4448)).
- `agents::tier_audit`: `MisplacedAgent` now carries the `TierOwnership` its verdict was reached from, and `audit_agent_tier_with_manifest` runs the same scan against a ledger the caller loaded — the seam that lets the quarantine refuse on a corrupt ledger where the read-only probe degrades, without either side forking the scan ([#4448](https://github.com/bobmatnyc/trusty-tools/issues/4448)).

Documentation

- `agents::tier_audit`: corrected a module-doc claim that `retract_framework_agents` "never touches an untracked or user-owned file; this module matches that". The parity holds for user-owned files only — `classify_tier_resident("qa", Untracked, {"qa"})` returns `ShadowsBundled`, which is the intended behaviour and is exactly what #4448 quarantines. The old wording read as a guarantee that untracked files were safe from the sweep ([#4448](https://github.com/bobmatnyc/trusty-tools/issues/4448)).
