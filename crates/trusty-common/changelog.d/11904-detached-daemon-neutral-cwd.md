Fixed
- A daemon started through `daemon_guard::spawn_detached`, `spawn_current_exe` or their `_forwarding_parent_link` forms now starts with its cwd set to `$HOME` (or `/` when `HOME` is unset or missing), not the spawning CLI's cwd. A `trusty-memory serve --foreground` auto-started by a stdio bridge inside an agent worktree held that worktree as its cwd after the agent finished, so `tm pr cleanup` refused to reclaim it (#11904). Consequence: such a daemon's `.env.local` lookup, which walks up from cwd, no longer finds a project-tier `.env.local`; `$HOME/.env.local`, the secure store and the process environment still apply. Per-request caller cwd sent by the stdio bridge is unchanged.
