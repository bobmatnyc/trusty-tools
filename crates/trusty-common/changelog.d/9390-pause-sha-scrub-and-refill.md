Fixed
- `catchup::pause::write_pause_snapshot` flags commit-SHA-like tokens in the PM's free text (Summary, Completed, In Progress, Next Steps) as `<sha?>`, so a snapshot no longer records a PR head the next session would trust. A token is SHA-like when it is a whole word of 7-40 hex characters with at least one digit and one letter; words, dates, branch names, issue numbers and UUIDs are kept. The code-generated `Last commit:` line is unchanged. The rule is public as `catchup::sha_scrub` (#9390).
- L2 and L3 recall fetch more candidates when expired Tier C slots fill the vector window, until they have `top_k` live candidates, the index is exhausted, or 1024 candidates were fetched. Before, a pile of expired slots matching the query better than the live slot hid the live slot. Nothing is deleted; `retrieval::next_refill_window` is the shared stop rule (#9390).
