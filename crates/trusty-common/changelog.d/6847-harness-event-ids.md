Added

- `control_bus::HarnessEvent` now carries `id: EventId` (a UUIDv7 minted by the emitting process) and `parent_id: Option<EventId>` (the call-graph edge; `None` for a root), per DOC-73 §3.1. Both fields carry `#[serde(default)]`, so an event serialized before this change still deserializes: a missing `id` mints a fresh one, a missing `parent_id` becomes `None`. `uuid` is now a mandatory dependency of this crate rather than optional (it was previously gated behind `rpc`/`daemon-token`/`session-naming`/`symgraph-parser`/`memory-core`/`tickets`); those features no longer need a `dep:uuid` entry since the dependency compiles unconditionally now. This is a public API change to an existing struct's field set — adding two required public fields to `HarnessEvent` — which is a MINOR-level break under Cargo's 0.x rule; the crate version is not bumped in this PR (#6847).
