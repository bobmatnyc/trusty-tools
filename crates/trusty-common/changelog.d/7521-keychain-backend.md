Added
- `credentials::KeychainBackend` (#7521, feature `keyring-store`): a group-namespaced OS-keychain vault for `tm secrets`, composing the keychain entry as service `trusty/<owner>/<repo>` with the bare KEY as the account (DOC-74 §6.3), plus the `0600` names-only index at `~/.trusty-tools/trusty-mpm/secrets-index/<group>.json` that gives `list` something to enumerate — `KeyringStore::list` cannot, because the `keyring` crate exposes no portable enumeration API. The backing store is the existing `KeyStore` trait, so a caller can inject `MemoryKeyStore` and no unit test touches a real keychain. `Debug` carries no field capable of holding a value; an invalid group, an invalid key, an unreachable keychain, and an unparsable index are all errors, never a silent fall-back. This feature is now enabled by the `tm` binary (#4570), which had left it compiled nowhere.
