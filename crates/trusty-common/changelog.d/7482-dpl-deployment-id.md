Fixed

- The memory secret heuristic no longer rejects a bare Vercel deployment id. `dpl_` plus exactly 28 alphanumeric characters is a public identifier — it is the `uid` Vercel's REST API returns and what `vercel` CLI output carries — but it has a credential's upper+lower+digit profile and offers `is_structural_token` nothing to decompose, so the mixed-case fallback of `looks_like_secret` flagged it and no memory could mention a deployment. The new `is_public_resource_id` allowlist exempts that whole-token shape and nothing else: `PUBLIC_ID_PREFIXES` holds the one prefix #7482 produced evidence for, the prefix match is case-sensitive, and `PUBLIC_ID_TAIL_LEN` is a single exact length taken from the two id samples in Vercel's API reference rather than a range. The exemption's cost is documented rather than overstated — a credential body of exactly 28 alphanumeric characters written flush behind `dpl_` is exempted too, because it is character-for-character indistinguishable from a real id; pinning one exact length is what reduces that blind spot to the single shape no predicate can separate. Two forms are explicitly NOT covered and are pinned as such: an id inside a dashboard URL (the whole URL is one token, so the id is never seen as a token) and any other tail length. Refs #7482
