Fixed

- The memory secret heuristic no longer rejects a Vercel deployment id. `dpl_` plus a 20-to-40-character alphanumeric tail is a public identifier — it is in the dashboard URL and in `vercel` CLI output — but it carries a credential's upper+lower+digit profile and nothing for `is_structural_token` to decompose, so the mixed-case fallback of `looks_like_secret` flagged it and no memory could mention a deployment. The new `is_public_resource_id` allowlist exempts that exact whole-token shape and nothing else: `PUBLIC_ID_PREFIXES` holds the one prefix #7482 produced evidence for, the tail must be a bare alphanumeric run inside `PUBLIC_ID_TAIL_LEN`, and the prefix match is case-sensitive. A token that merely opens with `dpl_` — a base64 blob, a second underscore in the tail, a tail past the window, an uppercase `DPL_` — breaks the tail contract, so the exemption never sees it and the heuristics decide it exactly as before. Refs #7482
