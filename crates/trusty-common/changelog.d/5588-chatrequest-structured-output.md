- `ChatRequest` carries `response_schema: Option<StructuredOutput>`, so a caller can constrain a response to a JSON Schema instead of describing the schema in prose and hoping the model complies. `StructuredOutput` is dialect-free; the adapter renders it — the OpenAI-compatible family (openrouter, fireworks, openai, together, atlascloud, and the local wrapper) sends `response_format: {type: json_schema, json_schema: {name, strict, schema}}`, translated once in `OpenAiCompatAdapter::wire_body` so the buffered and streaming paths cannot disagree, and Anthropic-direct sends `output_config.format`, which carries the schema alone. Bedrock's registry `structured_output` flips to `false`: the Converse API has no equivalent parameter. A schema sent to a provider whose registry flag is `false` is the new `InferenceError::UnsupportedCapability{provider, capability}`, raised before any network call — including before the Local adapter's liveness probe — rather than dropped in silence. The field is `#[serde(default, skip_serializing_if = "Option::is_none")]`, so a request serialised before this change round-trips byte-identically. Refs #5588
