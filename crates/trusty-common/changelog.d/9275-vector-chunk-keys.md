Added
- The memory vector store holds several vectors per drawer: chunk 0 under the bare `{uuid}` key (every existing row) and chunk `n` under `{uuid}#n`. `UsearchStore::upsert_chunks` writes a drawer's chunks in one transaction, replacing its earlier rows, and refuses an empty list, more than 4096 chunks, or a wrong dimension without writing anything (`HnswStoreError::ChunkCount`). `UsearchStore::drawer_count` counts distinct drawers. Search returns each drawer once, scored by its best chunk, with `top_k` counting drawers; `remove`, orphan compaction, alias repair (`unalias` frees the whole drawer) and the dream rebuild check treat a drawer's rows as one. No production writer uses chunk keys yet, and existing palaces need no migration (#9275).
