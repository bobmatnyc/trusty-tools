Added
- The memory vector store holds several vectors per drawer: chunk 0 under the bare `{uuid}` key (every existing row) and chunk `n` under `{uuid}#n`. `UsearchStore::upsert_chunks` writes a drawer's chunks in one transaction, replacing its earlier rows, and refuses an empty list, more than 4096 chunks, or a wrong dimension without writing anything (`HnswStoreError::ChunkCount`). `HnswStore::replace_group` and `HnswStore::delete_group` refuse an empty drawer key or one holding `#` (`HnswStoreError::DrawerKey`). Search returns each drawer once, scored by its best chunk, with `top_k` counting drawers and a malformed key taking no slot; `remove`, orphan compaction, alias repair (`unalias` frees the whole drawer), the dream rebuild check and the open-time orphan warning treat a drawer's rows as one, and the last two still count rows that name no drawer. No production writer uses chunk keys yet, and existing palaces need no migration (#9275).
