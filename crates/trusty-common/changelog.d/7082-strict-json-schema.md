Fixed

- `StructuredOutput::openai_response_format` normalizes a strict schema before it reaches the wire, so an OpenAI-family provider no longer rejects the call with `Invalid schema for response_format '<name>': ... 'additionalProperties' is required to be supplied and to be false`. The new `trusty_common::inference::strict_json_schema` returns a copy of a JSON Schema with `additionalProperties: false` and a complete `required` list on every object node, recursing through `properties`, `items` in both the single-schema and tuple forms, `$defs`, `definitions`, `anyOf`/`oneOf`/`allOf`, and an object-valued `additionalProperties` — a map-style object keeps its value schema rather than being closed. The caller's own schema value is never mutated. Normalization runs only for a strict directive: with `StructuredOutput::lenient` no provider requires the rules, and forcing every optional property into `required` would narrow a schema whose author asked for best-effort JSON. This is now the workspace's one implementation of strict-mode compliance — `trusty-review`'s `enforce_strict_mode` delegates to it. Refs #7082
