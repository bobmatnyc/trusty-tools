Fixed

- Every intra-doc link in `parent_death` and `redb_cache` now resolves under `cargo doc`'s default rustdoc pass. A module declared as `pub mod x;` with both an outer doc comment at the declaration site and its own inner `//!` doc gets both merged onto one rustdoc page, but links written bare in the inner doc resolve against the DECLARING module's scope, not `x`'s own — so `[`exit_with_parent`]` written inside `parent_death.rs` itself failed to resolve even though the item lives right there. Fixed with `[`name`]: crate::path::to::name` link-reference definitions, the same pattern already used for `GitBackend`/`FakeGitBackend` in `trusty-mpm`'s `provisioner` module. The three genuinely private items `parent_death` referenced this way (`ParentIdentity`, `wait_for_term_handler`, `HANDLER_WAIT`) are now plain code spans, since a private item has no public doc page to link to. `sys_metrics::physical_footprint_bytes` — macOS-only — is also now a plain code span rather than a link that breaks the docs build on every other target (#7157).
