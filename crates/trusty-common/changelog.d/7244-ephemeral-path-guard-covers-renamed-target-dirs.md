Fixed

- `bin_resolve::is_ephemeral_build_path` now rejects any path running through a Cargo build tree, not only the literal substrings `target/debug` and `target/release`: it matches the layout Cargo produces — a `target` or `target-<anything>` component immediately followed by `debug`/`release`, and a `deps`/`build` component under a profile directory or a `target*` ancestor — as well as anything under the directory `CARGO_TARGET_DIR` names (compared canonically). This repo builds each agent worktree into its own `target-<issue>` directory, whose artifact paths contain neither old literal, so a running `cargo test` binary at `…/target-7224/debug/deps/test_session_lifecycle-<hash>` read as a stable installed path and was persisted into a real project's `.claude/settings.json` as the command for every hook (#7244). Matching is component-wise AND position-aware, so an ordinary directory that merely shares one of those names — `/Users/target/.cargo/bin/tm`, `/Users/x/build/tools/tm`, `/Users/x/deps/vendor/tm`, `/opt/deps-tool/bin/tm` — stays accepted; misclassifying one stops hooks being written at all, which is the same end-state as the bug, reached from the other direction. Third root cause in the same family as #2229 and #4485.
