Fixed

- `bin_resolve::is_ephemeral_build_path` now rejects any path running through a Cargo build tree, not only the literal substrings `target/debug` and `target/release`: a path component that is `deps`, `build`, `target`, or starts with `target-` is flagged, as is anything under the directory `CARGO_TARGET_DIR` names (compared canonically). This repo builds each agent worktree into its own `target-<issue>` directory, whose artifact paths contain neither old literal, so a running `cargo test` binary at `…/target-7224/debug/deps/test_session_lifecycle-<hash>` read as a stable installed path and was persisted into a real project's `.claude/settings.json` as the command for every hook (#7244). Matching is component-wise, so `/opt/deps-tool/bin/tm` and `/Users/x/rebuild/bin/tm` stay accepted. Third root cause in the same family as #2229 and #4485.
