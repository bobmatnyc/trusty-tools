Fixed
- `PalaceHandle::snapshot` refuses a destination directly inside the palace registry directory (`<data root>` in the flat layout, `<data root>/palaces` in the legacy one), resolved through symlinks and `..`, before it writes anything. A backup there was listed as a palace, and after a restart the live handle could point at it. It also refuses a destination anywhere under `<registry>/palaces`, in any letter case: in the flat layout, creating `<data root>/palaces` made the next start switch the registry to it, and every palace vanished from the daemon (`SnapshotError::DestinationSwitchesRegistry`). A destination it cannot resolve, a destination with `..` after a component that does not exist yet (`<data root>/palaces/../l/bk` passed as `<data root>/l/bk`, then the create made `<data root>/palaces`), and a palace directory with no parent are errors, never a pass. The new public `check_snapshot_dest` runs the same rules for callers that do I/O before the snapshot (#9282).
