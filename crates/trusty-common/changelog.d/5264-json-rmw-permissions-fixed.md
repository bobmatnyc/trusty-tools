Fixed
- `json_rmw` publishes now preserve an existing document's file mode, apply a codec-declared mode when they CREATE one, and resolve a symlink chain to its end. `File::create` applied 0644 minus umask, so a Codex config born with a provider credential in it was world-readable from the start and republishing a `chmod 600` document silently widened it. Resolving only one symlink hop was worse than resolving none: with `config.toml -> mid.toml -> real.toml` the write landed on `mid.toml`, converting a link to a regular file while the copy in the operator's dotfiles repo kept the stale content and the outer link still looked healthy ([#5264](https://github.com/bobmatnyc/trusty-tools/issues/5264))
- The `json_rmw` advisory lock is now keyed on the RESOLVED file rather than the caller's path. Following symlinks made it newly possible for two writers reaching one document by different names to take different `.lock` sidecars and lose each other's updates — the lost update the module exists to prevent
