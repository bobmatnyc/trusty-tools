Added
- `codex_config` module (behind the new `codex-config` feature): `codex_config_path` and `patch_mcp_server`, the single writer for Codex CLI stdio MCP registrations in `~/.codex/config.toml`. Takes a `#[non_exhaustive] McpServerSpec` (command, args, env, cwd, startup_timeout_sec) and returns a `#[non_exhaustive] PatchOutcome` (`Created` / `Repaired` / `Unchanged`); `McpServerSpec::stdio(command)` covers the no-arguments case. Repairs empty, joined, and nested-JSON-string argument vectors, all of which launch a process that exits before MCP initialization while the client still lists the connection as enabled. Both TOML table spellings are accepted wherever a table is expected and only the keys the spec owns are written, so an inline `mcp_servers` keeps its other servers and a per-server `env` keeps the operator's credentials. A config this module creates is mode 0600 in a 0700 directory. Shared entry point for trusty-search ([#5264](https://github.com/bobmatnyc/trusty-tools/issues/5264)) and trusty-memory ([#5265](https://github.com/bobmatnyc/trusty-tools/issues/5265))
- `json_rmw::DocumentCodec` (sealed) plus `update_with` / `update_with_decision`, `JsonCodec` and `TextCodec`: the locked read-modify-write cycle is no longer JSON-only, so a TOML or plain-text document can reuse the same critical section instead of growing another hand-rolled atomic writer. `update` is unchanged for existing callers. `update_with_decision` lets an idempotent caller skip the publish entirely when the document already agrees, instead of republishing identical bytes and churning the mtime
