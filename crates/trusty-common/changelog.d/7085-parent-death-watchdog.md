Added

- `parent_death` links a spawned process to its spawner's lifetime: `exit_with_parent` stamps `TRUSTY_EXIT_WITH_PARENT` on a `Command`, and `arm_from_env` inside the spawned program starts a watchdog thread that raises SIGTERM on itself once that parent is gone, forcing the exit only if graceful shutdown has not completed within five seconds. `Drop` on a `Child` handle only reaps while the parent is still executing, so a SIGKILL of the parent leaves the child running forever — the mechanism has to live inside the child. The stamp carries the spawner's pid AND its own process start time, read before the fork, so a pid the OS recycles between the spawn and the child's arming reads as death rather than making the watchdog adopt an unrelated process and wait on it indefinitely. The watchdog holds its SIGTERM until the process has installed a handler for it, up to ten seconds, because arming happens before a daemon registers one and raising into the default disposition would kill the process outright instead of running its shutdown path. `arm_for_named_parent` is the `--parent-pid` variant `trusty-agents` had carried as a private copy, now the same implementation. `daemon_guard::spawn_detached` scrubs the stamp so an inherited value cannot silently arm a detached daemon; `spawn_detached_forwarding_parent_link` and `spawn_current_exe_forwarding_parent_link` are the explicit opt-in for a daemon that must die with whoever started the CLI that forked it (#7085).
