Fixed

- The log-drain manifest cache directory (`<state_dir>/log-drain/<destination>/<cache_key>/`, under `~/.trusty-code/log-drain` and `~/.trusty-agents/log-drain`) is now created at `0700`, atomically (ancestors included), with a pre-existing symlink or non-directory refused rather than followed, via the new shared `private_dir::ensure_private_dir`. The directory records filenames and hashes of what has already left the machine, and gets the same tightening PR #7155 gave the sibling log directories in #6537. `webhook_relay::inbox::Inbox::open` moves onto the same shared helper, closing the gap between its own create-then-chmod and `uds::dir::prepare_socket_dir`'s atomic, symlink-safe pattern. `trusty-code::paths::private_state` and `trusty-agents`' own directory-hardening call sites are unchanged — `trusty-common` cannot depend on either crate — and migrate onto this helper in a follow-up. Refs #7158
