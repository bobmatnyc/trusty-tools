# Changelog — trusty-tui

All notable changes to trusty-tui are documented in this file.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]

### Added

- Full line-editor keymap + Ctrl-C daemon cancel (Slice 5, closes #3417, part of epic #3411, DOC-50 §5 Slice 5): `crate::run::run` now drains `ReplApp::pending_submit`/`pending_cancel` after every `apply` call and dispatches them to `TuiEngine::handle_input`/`cancel_session` on spawned background tasks (`crate::run::dispatch_pending`, private), so the reducer state Slice 4 staged actually reaches the engine — nothing did this before. `TuiModel` gained three defaulted methods (`take_pending_submit`, `take_pending_cancel`, `on_cancelled`) so `event_loop` itself stays engine-agnostic and `TestBackend`-testable; only `run`'s wrapper needs them. Ctrl-C now provably reaches `engine.cancel_session()` — the acceptance criterion this slice exists for — verified by a `MockEngine`-backed test driving the real reducer end-to-end. A new `ReplEvent::Quit` variant relays an engine's `handle_input` `Ok(false)` back into `ReplApp::quit`, since the spawned dispatch task can't reach `&mut ReplApp` directly. Also fixed a keymap parity gap the audit caught: Ctrl-D now only quits on an EMPTY input buffer (tagent's real `crates/trusty-agents/src/repl/tui/keys.rs` behavior — an earlier revision quit unconditionally, silently discarding unsaved input on a stray Ctrl-D). Every other binding (Ctrl-a/e/u, Up/Down, Home/End, Backspace, PageUp/PageDown, Enter) was already at full tagent parity as of Slice 4; this slice only completed the audit and wired the dispatch, it didn't invent line-editing features tagent itself lacks (no Ctrl-w word-delete, no kill-ring, no word-motion — full parity means matching tagent, not exceeding it). `crate::run` split into `run/mod.rs` + `run/tests.rs` (mirroring the existing `app/reduce.rs` + `app/reduce/tests.rs` precedent) to stay under the 500-SLOC production-file cap after the new dispatch code and tests landed.

### Fixed

- **`ReplEvent::WorkstreamActivationChanged.new_active_id` is now `Option<String>` (closes #3452, part of epic #3411).** The field was non-optional `String`, but the daemon legitimately publishes a `None` activation target when the active workstream is deactivated with no replacement (DOC-48 §4.2/§4.3) — mirroring `crate::events::Event::WorkstreamActivationChanged` in `trusty-code`, which already declares this field as `Option<String>`. The non-optional shape forced `trusty-code`'s Slice 3 consumer to fall back to a free-text `StatusMessage` for that case (PR #3436); this closes the gap found in that review, while `trusty-tui` still has essentially one consumer.

### Added

- Slash-command framework with mixed routing (Slice 7, closes #3420, part of epic #3411, DOC-50 §5 Slice 7 / §6 Q4): new `commands` module. `commands::route` classifies a submitted line as `Route::BuiltIn` (`/help`, `/clear`, `/quit`/`/exit` — never reach `TuiEngine::handle_input`) or `Route::Forward` (everything else — domain commands, plain chat, and unrecognized slash commands alike, per the thin-client axiom: the shared crate never rejects a command, only the engine can). `ReplApp::submit_line` calls it directly (no engine handle needed — the built-in table is fixed) so both the Enter-key path and a synthesized `ReplEvent::Submit` (e.g. a picker confirmation) get built-in short-circuiting for free; a built-in never sets `busy`/`pending_submit` since nothing is forwarded. `commands::resolve_forward`/`dispatch_forward` add the DOC-50 §3.2/§6 Q6 inline-picker half: a bare `/name` (no args) matching `TuiEngine::picker(name)` opens `ReplApp::active_picker` instead of forwarding; `commands::compose_selection` composes the `"{dispatch_command} {selected.id}"` resubmission on confirmation, and `ReplApp::confirm_picker_selection` applies it. The picker WIDGET (visual navigation/rendering) is intentionally minimal — a follow-up slice owns the overlay; this slice's scope is routing correctness. Coverage: 137 tests in this crate (23 new).
- App state + widgets (Slice 4, closes #3416, part of epic #3411, DOC-50 §5): the `app` module ships `ReplApp` (the render/reducer model `run::event_loop` drives — chat scrollback, input editor, history, scroll, banner/statusline/command data) plus `app::apply`, a reducer wiring every `ReplEvent` variant to a state transition so the widgets are drivable end-to-end, not just paintable. `widgets::scrollback`, `widgets::banner`, and `widgets::input_composer` are generalized ports of tagent's `repl/tui/{chat,banner}.rs` (`crates/trusty-agents/src/repl/tui/`). `widgets::status_line` is new: it renders `crate::model::StatuslineSegment` (plus the new `StatuslineEmphasis` style hook, see below) instead of tagent's `status.rs`, which was NOT migrated because it hardcodes an OpenRouter pricing formula. `render::markdown` is a verbatim, already-engine-agnostic move of tagent's `markdown.rs`. `layout::draw` composes the widgets into one frame. `text` holds the two pure blank-line-trimming helpers shared by `ReplApp::push_assistant` and the streaming reducer. Coverage: 32 → 116 tests in this crate (tagent's own `repl/tui` test suite — 101 tests — is untouched; this slice does not delete or modify anything under `crates/trusty-agents/`, per DOC-50's atomic-cutover requirement, Slice 10).

  **Disclosed behavioral differences from tagent** (the full list this slice's review round required — Slice 10 plans against it; see `crate::app`'s module doc comment for the authoritative, longer version):
  - **Ported faithfully** (verified against tagent's real `keys.rs`, not its doc comments): Up-arrow recalls `ReplApp::last_prompt` and, while `ReplApp::busy`, also signals `pending_cancel` (NOT the multi-level `history_prev`/`history_next` dead-code browser tagent's own doc comment misattributes to production); Down-arrow calls `history_next()` exactly as tagent's real handler does, even though this is a no-op in both crates today; Ctrl-E pastes only the first non-blank line of the last cached shell block into an empty buffer; the input composer's right-aligned `[thinking...]` label renders whenever `busy` is true regardless of buffer contents, and `busy` is now set `true` at Submit (not on the first streamed chunk), closing the pre-first-token latency gap.
  - **Deliberately NOT ported**: the three-row animated activity panel (spinner/elapsed-timer/rainbow shimmer) — `busy: bool` is this crate's entire generalization of tagent's `thinking`/`busy_since` pair, with no elapsed-time derivation available; inline token counters and all cost/usage tracking (tokens, daily-cost persistence, the pricing formula — DOC-50 Q9); model/provider pickers and the inline LLM-offered/slash-completion choice list (Phase 2, DOC-50 §5 Slice 7+); `AgentScope`'s User/Project color semantic, replaced by a plain `accent_color` field; the shared `trusty_common::banner` splash art and tagent's fixed banner title/command list, replaced by engine-supplied `banner_art`/`banner_title`/`commands`/`recent_activity` fields; the literal `"[trusty-agents] "` status prefix and idle-hint copy, replaced by a generic `status_prefix` field and hint string.
  - `model::StatuslineSegment::Custom` gained an `emphasis: StatuslineEmphasis` field (breaking change to a Slice-1.5 type with zero consumers outside this crate) and a new `Chrome{text, emphasis}` variant was added, both so a future `AgentEngine` can reproduce tagent's bold-cyan bracket prefix, green success framing, and bold/dim `TM:`/`MPM:` distinction — none of which the original segment set could express.

- Initial crate scaffold (Slice 1, closes #3412, part of epic #3411, DOC-50 §3/§5): the `TuiEngine` trait (`setup`, `handle_input`, `cancel_session`, `subscribe_workstream_events`, `shutdown`) and the `ReplEvent` enum (terminal input, submit/cancel, streamed assistant output, tool invocation, statusline/workstream updates, connection loss, clear-scrollback), generalized from tagent's existing `crates/trusty-agents/src/repl/tui/` REPL event model. Also ships the small shared payload stubs (`StatuslineSegment`, `PickerItem`, `CommandDescriptor`, `WorkstreamSummary`) that Slice 1.5 (#3413) will flesh out. No ratatui/crossterm dependency yet — the terminal layer lands in Slice 2 (#3414).
- `ReplEvent::ToolInvocation` carries an `id: String` correlation field (start/complete pairing for Slice 8 tool cards); `ReplEvent::ClearScrollback` covers `/clear` (DOC-50 §5 Slice 7); `WorkstreamActivationChanged`'s field is named `new_active_id` to match the DOC-48 §5.3 SSE wire event exactly.
- Generalization layer (Slice 1.5, closes #3413, part of epic #3411, DOC-50 §3.2): new `model` module replacing Slice 1's provisional stubs with the spec-shaped, engine-supplied data types. `StatuslineSegment` is now an enum (`SessionId`, `Model{provider,name}`, `Project`, `Workstream{id,name}`, `Cost`, `Custom{label,value}`) instead of a flat `{label,value}` struct. `PickerItem` gained an optional `description`; the new `PickerRequest{title, items, dispatch_command}` generalizes tagent's hardcoded `PickerKind::{Model,Provider}` so an engine can name a picker, supply its items, and supply the command dispatched on selection. `CommandDescriptor` gained `routing: CommandRouting` (`BuiltIn` | `Engine`, DOC-50 Q4's mixed slash-command routing) and an optional `args_hint` for autocomplete. `TuiEngine` gained two defaulted accessors, `commands()` and `picker(name)`, so engines can supply a domain command registry and named pickers without breaking existing/future implementors that don't override them. No product-specific logic (e.g. tagent's OpenRouter cost formula) lives in the shared crate — `StatuslineSegment::Cost` carries a pre-formatted string the engine computes.
- The terminal layer (Slice 2, closes #3414, part of epic #3411, DOC-50 §5): `terminal::TerminalGuard`, a panic-safe RAII guard (alt-screen + raw mode + mouse capture) whose `Drop` restores the terminal on both normal return AND panic unwind — fixing a real bug in tagent's current `run_tui` (`crates/trusty-agents/src/repl/tui/run.rs`), which only restores after the event loop returns normally and so leaves the terminal in raw/alt-screen mode if it panics. Unwind-safety is proven by a `catch_unwind` test against an injectable `TerminalOps` seam (no real TTY required). `run::event_loop` is the terminal-generic (any `ratatui::backend::Backend`, unit-tested against `TestBackend`) 100ms-tick / `mpsc::UnboundedReceiver<ReplEvent>` select loop, generalized from `crates/trusty-agents/src/repl/tui/run.rs::event_loop`; `run::spawn_key_reader` is the dedicated OS thread that blocks on `crossterm::event::read()` so it never parks the tokio runtime, forwarding key/resize/mouse-wheel-scroll events; `run::run` is the opinionated top-level entry point tying `TerminalGuard`, the key reader, and an `E: TuiEngine` + `M: TuiModel` pair together. `keys::translate_key_event` is the `crossterm::event::KeyEvent` → Slice 1's crossterm-free `KeyInput` translation boundary, unit-tested for every mapped `KeyCode` variant plus the `Other` fallback and ctrl/alt/shift modifier decoding.
- Adopted ratatui 0.30 + crossterm 0.29 for this crate only (DOC-50 Q2), clearing a vulnerable transitive `lru` (#2886). This is a deliberate, crate-scoped divergence from the rest of the workspace's ratatui 0.29/crossterm 0.28 pin — see the dependency comment in `Cargo.toml`. A compile-check spike against `crates/trusty-agents/src/repl/tui/{chat.rs,layout.rs,markdown.rs,banner.rs}`'s actual API surface (widgets, `Frame`/`Terminal`/`CrosstermBackend` construction, cursor positioning, crossterm event matching) found **zero 0.29→0.30 breakage** — every pattern those files use compiles unchanged against 0.30, so Slice 4/10's migration of that code is not expected to hit ratatui API churn.
