Changed
- `trusty-review` no longer compiles in its reviewer system prompts. The stock and coverage-gating prompts are read from content `instructions/trusty-review/prompts/` through the resolver `tm` uses: the trusty-tools checkout above the cwd, else the installed content bundle. `run`, `compare` and `calibrate` refuse to start without them, exiting non-zero with the error and its remedy (`tm content update`, or the offline `tm content install --from`) on stderr, whatever `RUST_LOG` says. `mcp` and `webhook-listen` print the same line on stderr and start; each review then ends `Skipped`/UNKNOWN with `error` set and `isError: true` on the MCP envelope, before any PR fetch, dedup claim or model call. A content release that lacks a prompt, or carries an empty one, fails the same way naming the file. Content released before this change does not carry the prompts: run `tm content update` (#9015).
- Release order: a content release carrying `instructions/trusty-review/prompts/` (content-v2.2.2) publishes before this `trusty-review` (#9015).
