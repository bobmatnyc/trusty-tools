Added
- MCP `review_pr` accepts an optional `fetch_linked_issues` boolean, and `run` takes `--fetch-linked-issues`. The review fetches the issues the raw PR body links with a keyword (`Fixes #12`, `Refs owner/repo#12`) from the reviewed repository, with the token that read the diff, and shows them under `## Linked issues` after any `issue_docs`, fenced as data, for the reviewer and the `[gh:]` citation corpus only; the verifier never sees them. Off by default; a review without it is unchanged. `review_diff` does not list the flag. A mistyped MCP value is an invalid-params error (#9197).
- At most 5 issues are fetched, in body order, 10 seconds each. The PR's own number is skipped; a number a supplied doc carries is never fetched; refs to another repository and refs past the 5 are each folded into one ledger item and take no fetch. Supplied docs are kept first; a fetched doc that does not fit the 48,000-character section is left out whole, with every fetched doc after it, and nothing is fetched when supplied docs fill the section (#9197).
- Every failure is recorded and the review runs: a 404, a rate limit, a server error or a timeout is an `unavailable` item with its error text (one line, credentials redacted); a blank token is refused before any request, never replaced by the host `gh` login; a local diff or a failed PR metadata read makes the `issues` row `unavailable`. GitHub answers `/issues/N` for a pull request too; it is shown as `### Issue #N` (#9197).
