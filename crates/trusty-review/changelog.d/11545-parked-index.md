Fixed
- A trusty-search index listed under `parked` (cold-parked, `index_not_resident`) now counts as present: `review_pr` and the checkout index resolver pick it instead of reporting "no trusty-search index". `review_pr` accepts only a parked row the daemon files under the PR repo's identity, so another owner's parked index with the same id is refused. This parked-row filter needs a trusty-search that honours `repo_identity` on its parked rows; an older daemon that ignores the filter returns unscoped rows that the client cannot check. The context gate wakes a parked index with one search, then re-reads its status once: a degraded index labels the review DEGRADED, and a failed wake makes it DEGRADED with a reason that names the wake.
