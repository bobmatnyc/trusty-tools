Added
- The verifier asks an exploitability question for security findings: can the flaw be reached and abused given the diff and context? The answer and its rationale come back as `reachability` and `reachability_reason`. A security finding the verifier confirms but judges unreachable is not confirmed; it is recorded `Unverifiable` with the rationale and withheld. A reachable one stays confirmed and carries the rationale in its consequence. Each security finding is verified in its own request; other findings keep the existing prompt, schema and batching, and the per-review call cap still cuts the lowest-impact findings when security requests are in the plan.
