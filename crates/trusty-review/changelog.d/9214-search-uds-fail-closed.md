Fixed
- A missing trusty-search socket file no longer falls back to TCP. With no `TRUSTY_SEARCH_URL` set, the review pipeline and the report pass always use the socket leg; a missing socket reports trusty-search as unavailable, naming the socket path, through the same gate branch as a dead daemon: the review is skipped when search is required and marked degraded (non-authoritative) when it is opted out. A socket path that cannot be derived (for example a relative `TRUSTY_DATA_DIR`) fails the same way, with the reason. `ReviewConfig::search_url` no longer defaults to a localhost URL; it is empty unless `TRUSTY_SEARCH_URL` sets it (#9214).
- An explicit `TRUSTY_SEARCH_URL` keeps the HTTP leg. The report pass now calls that URL itself instead of resolving the discovery-file or default-port address (#9214).
