Added
- `GET /indexes/:id/status` (and the MCP `index_status` tool) and every search response's `meta` block now report BM25 corpus-cap truncation: `bm25_truncated`, `bm25_docs_dropped` (resident chunks absent from the lexical lane) and `bm25_corpus_cap`. The chunk cap exceeds the BM25 cap at the top of every memory tier, so a large index could hold chunks that only the vector lane can find, with no field saying so. This is separate from `bm25_lane_degraded`, which means the lane has not converged yet (#9235).
