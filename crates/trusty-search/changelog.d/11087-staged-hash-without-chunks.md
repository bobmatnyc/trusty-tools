Fixed
- A changed file is no longer lost from search when the daemon stops in the middle of a staged reindex batch (#11087). Before, the batch deleted the file's old chunks in one write and its content hash in a later one, so a SIGTERM between them left a hash with no chunks; the resumed reindex treated the file as unchanged, skipped it, and the file stayed out of search results until its content changed. Now a file's chunks, symbol list and content hash leave the corpus in one write, in the batch and in the prune pass, so a resumed reindex indexes the file again. A failed delete keeps all three, and the batch still skips that file's insert.
