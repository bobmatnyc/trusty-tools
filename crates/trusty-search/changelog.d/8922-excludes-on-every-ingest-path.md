Fixed
- Every ingest path now applies the walker's own admission decision: `index_file` (HTTP, socket, MCP), the file watcher, the dropped-event rescan and boot reconcile no longer index a file the reindex walk excludes (`exclude_globs`, `extensions`, include paths, ignore files, skip dirs, size caps). `index_file` on an excluded path answers `403 index_file_excluded` with `indexed: false` instead of `200`, and drops any chunks an earlier write left for it (#8922).
- sops-encrypted files are never indexed, whatever their extension: content carrying a sops encrypted value plus a sops metadata block (YAML `sops:`, JSON `"sops": {`, dotenv `sops_version=`/`sops_mac=`, INI `[sops]`) produces no chunks, and a file that becomes encrypted loses its old plaintext chunks on its next write, reindex or rescan (#8922).
- A file still on disk that the index now excludes is purged by the next non-force reindex and by the dropped-event rescan, instead of being served from the stale index (#8922).
- A pushed write or boot-reconcile file whose admission the filesystem cannot decide is refused or left untouched, never indexed (#8922).
- Every purge of an excluded or sops-encrypted file also drops the file's content hash, in memory and in the durable corpus, so a file that is admitted again unchanged is re-indexed instead of hash-skipped. Purges no longer rebuild the symbol graph once per file (#8922).
- An incremental reindex whose only changed files never reach the embedder (an empty file, over-ceiling JSON, sops content) no longer fails the zero-vector gate as an embedder crash (#8922).
- A walk error along a path (`EACCES`, `ESTALE`) during admission now leaves the file untouched instead of purging it as excluded (#8922).
- Known limit: the sops content check also matches a Markdown or other text file that quotes a complete sops document (an encrypted value plus a metadata block), so such a file is not indexed. It fails toward excluding (#8922).
