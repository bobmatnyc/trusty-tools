Added

- The daemon now pulls trusty-mpm's active-project set (`mpm.residency.active`) every `TRUSTY_RESIDENCY_PULL_SECS` (default 30 s). An index named in the set is never parked by the resident cap, and a cold-parked one is loaded before its first query. A resident index outside the set parks once it has been out of the set and unqueried for `TRUSTY_RESIDENCY_GRACE_SECS` (default 120 s). A set that is stale (`TRUSTY_RESIDENCY_STALE_SECS`, default 600 s), never fetched or empty changes nothing. An id the set names that this daemon has not registered is ignored, and a set naming none is untrusted. Grep, chunk pages and the all-index fan-out count as use, as a query or reindex does. Pre-wake leaves one resident slot for an index outside the set, and when the set fills the cap the most recently active other index stays resident; `/health` reports `residency_active_set` (`trusted`, `pinned_members`). `TRUSTY_RESIDENCY=off` turns the pull off. `lazy_loader::ids_to_park` takes the pinned ids as a third argument (Refs #10533).
