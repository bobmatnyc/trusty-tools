Changed
- A query that arrives while an idle-evicted index rehydrates no longer waits for the BM25 rebuild. The rebuild now runs on the blocking pool beside the redb scan, and the live index is replaced in one short swap. A query waits at most 500 ms for the rehydrate (less when `TRUSTY_REHYDRATE_WAIT_MS` is lower), shared by all its lanes, then answers from the vector lane with `meta.bm25_lane_degraded: true`. A `stage: lexical` query in that window answers empty with the same flag, because the grep-fallback and exact-match lanes read the in-memory chunk map. The flag clears when the rehydrate commits. Writers keep the full `TRUSTY_REHYDRATE_WAIT_MS` wait, and a write that reaches BM25 during the rebuild is kept (#10193).
