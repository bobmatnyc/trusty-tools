Fixed
- A per-index query whose embed misses `TRUSTY_QUERY_EMBED_DEADLINE_MS` (default 5000 ms), because the embedder sidecar is cold or warm but busy, now answers from the lexical lane with `meta.vector_unavailable: true` and an `embedder_error` naming the deadline, instead of waiting out the embed and answering `408 query_timeout`. A query pinned to `stage: semantic` takes no deadline and skips the gate: it waits for the embed up to the query budget (`TRUSTY_QUERY_TIMEOUT_SECS`), so it answers once a cold sidecar is ready instead of `503 vector_unavailable`. The embed runs on a detached task, so the sidecar spawn finishes and later queries are hybrid; concurrent cold queries share one spawn, and while an abandoned embed runs later unpinned cache misses on that index degrade at once rather than queue behind it. The gate clears even if the embed task panics. `0` turns the deadline off (#10194).
