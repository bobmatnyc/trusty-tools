Added
- `POST /search` applies a per-index deadline (default 3000 ms; `TRUSTY_SEARCH_FANOUT_INDEX_DEADLINE_MS`, or `per_index_deadline_ms` in the request). An index that misses it is skipped, and the response carries `rehydrating_indexes_skipped`, `deadline_skipped_index_ids` and `per_index_deadline_ms` (#9027).
- `POST /search` embeds the query once and passes the vector to every per-index search; it previously embedded once for routing, uncached, and again per index. A repeated query now costs no embedder call (#9027).
- `POST /warm` and `GET /warm/status` (socket: `search.warm.start`, `search.warm.status`) rehydrate every registered index in the background, with bounded concurrency. A second start joins the running warm. Warmed indexes stay resident for a window (default 30 min, `TRUSTY_WARM_ALL_WINDOW_SECS`). A start at or past the RSS ceiling (`TRUSTY_WARM_ALL_MAX_RSS_MB`, else `TRUSTY_MEMORY_LIMIT_MB`) answers `503 warm_memory_ceiling`; the status reports per-index state, totals, window expiry and RSS before and after (#9027).
