Added
- `POST /search` applies one fan-out deadline (default 3000 ms; `TRUSTY_SEARCH_FANOUT_INDEX_DEADLINE_MS`, or `per_index_deadline_ms` in the request). The deadline starts when the per-index searches start, after the query embed and routing, and every index must answer by it. An index that misses it is skipped, and the response carries `deadline_indexes_skipped` (also as `rehydrating_indexes_skipped`), `deadline_skipped_index_ids` and `per_index_deadline_ms` (#9027).
- `POST /search` embeds the query once and passes the vector to every per-index search; it previously embedded once for routing, uncached, and again per index. A repeated query now costs no embedder call. The embed has its own timeout (default 1000 ms, `TRUSTY_SEARCH_FANOUT_EMBED_TIMEOUT_MS`); a slow or failed embed degrades every index to the lexical lane, and the response says so in `query_embed` and `embed_degraded` (#9027).
- `POST /search` returns `partial: true` when any index was skipped (cold, corpus failure, migration, deadline) or the query embed degraded (#9027).
- `POST /search` starts corpus rehydrates only for the indexes routing kept (#9027).
- `POST /warm` and `GET /warm/status` (socket: `search.warm.start`, `search.warm.status`) rehydrate every registered index in the background, with bounded concurrency (at most 16). A second start joins the running warm. An index is pinned against idle eviction and the residency cap from the moment it starts warming, for a window (default 30 min, at most 24 h, `TRUSTY_WARM_ALL_WINDOW_SECS`); a failed warm drops the pin, and a deleted index loses it. A `window_secs` above 24 h answers `400 invalid_warm_request` (socket: `invalid_params`). A start at or past the RSS ceiling (`TRUSTY_WARM_ALL_MAX_RSS_MB`, else the memory-pressure high-water mark) answers `503 warm_memory_ceiling`; with no ceiling or no RSS reading the warm runs and reports `ceiling_unenforced: true`. The status reports per-index state, totals, window expiry and RSS before and after (#9027).
