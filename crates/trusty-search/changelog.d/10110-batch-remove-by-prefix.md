Added
- `search.index.files.remove` socket method and `remove_files` MCP tool: remove every file under a path prefix, or in a list of up to 10,000 paths, in one call. The call reads the selected rows by redb key range, so an idle-evicted index is not rehydrated; it stamps one graph-dirty mark, so the symbol graph rebuilds once; and it deletes chunk and entity rows in one transaction per slice of 500 ids. `dry_run: true` reports `matched_files` and `matched_chunks` and changes nothing. An empty prefix, `.`, a `..` segment and the index root are refused with 400; while a corpus rehydrate runs the call answers 503 `remove_files_busy` (retryable). A failed call reports `partial` and the counts removed so far, and a retry finishes it, including vectors and content hashes the failed call left behind. `remove_file` is unchanged (#10110).
