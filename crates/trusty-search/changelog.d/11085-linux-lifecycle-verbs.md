Added
- Linux: `trusty-search restart [--data-dir DIR]` stops the daemon, confirms it stopped (the `daemon.lock` flock is free), then starts the binary in the install dir (`$CARGO_HOME/bin`) and returns once its new pid serves the socket (#11085). A daemon that is not running is started. While the `trusty-search.service` systemd unit is active it sends no signal, exits 1 and prints the `systemctl restart` command. macOS has no `restart` verb.
- Linux: `trusty-search stop` takes `--data-dir DIR`, resolved the same way `start` resolves it (flag, then `TRUSTY_DATA_DIR`), and signals only a `trusty-search` process proven to serve that data dir's socket (#11085). It never signals the pid written in `daemon.lock`, sends SIGKILL after the termination grace, and exits 1 when a process survives or when nothing runs.
- Linux: a detached `trusty-search start` now spawns the install-dir binary, with a cleared environment plus `TRUSTY_DATA_DIR` and the daemon's own non-credential settings, and exits 1 unless that pid serves the socket within 120 s; a child that never serves is killed (#11085). `OPENROUTER_API_KEY` is not passed to the daemon it spawns.
