Fixed
- `remove-file` (HTTP, socket `search.index.file.remove`, MCP `remove_file`) now accepts an absolute path inside the index root. The daemon maps it to the stored index-relative key by text against the root, so the absolute paths search returns remove the same chunks as their relative form, and an in-root symlink removes its own chunks, not its target's. An absolute path outside the root, the root itself, and a relative or absolute path that is empty, `.`, or climbs out with `..` answer `400 remove_file_path_outside_root`, whose message names both accepted forms; before, each answered `200 removed_chunks: 0` and removed nothing (#9236).
- A file removed with `remove-file` is indexed again by the next reindex. Before, its content hash stayed cached, so the reindex skipped the unchanged file and its chunks never came back (#9236).
