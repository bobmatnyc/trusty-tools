Added

- The daemon now deletes a duplicate or unregistered index, corpus included, once it has been idle for 30 days. Duplicate means a worktree root, so a worktree session's own index is covered, or an index parked as `worktree` or `operator`; unregistered means parked as `decommissioned`. Idle time runs from the latest of `last_queried_unix` and `last_indexed_unix` in `indexes.toml`, or from the park time when that is later; grep, global grep, chunk pages and the `search.query.all` fan-out now write `last_queried_unix` too, as search already did. An index with neither stamp (a stamp of 0 counts as none), a main checkout or other registered non-duplicate index, an index named in tm's active set, and a loaded, warm-pinned or reindexing index are kept. Each delete decides again from fresh inputs under the index's teardown lock, so an index loaded, named in the active set or used after the pass read it is kept. A missing root stays with the orphan reaper and its 7-day grace. Nothing is deleted when the active set is not trusted or when `indexes.toml` or `project-map.toml` cannot be read; the error is logged. The pass runs on the orphan-reaper ticker, so `TRUSTY_ORPHAN_REAP_SECS=0` turns it off too (Refs #10534).
