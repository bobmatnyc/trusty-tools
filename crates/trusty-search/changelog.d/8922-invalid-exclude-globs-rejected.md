Changed
- An exclude glob that does not parse is now rejected where it enters: `POST /indexes` and `PATCH /indexes/{id}/config` answer `400 invalid_exclude_glob`, and a `trusty-search.yaml` holding one fails to load. An index restored with such a glob already persisted keeps loading and keeps its chunks: the glob is skipped, as before. Restore now logs it at ERROR with the index id, and `GET /indexes/{id}/config` lists it under the new `invalid_exclude_globs` field. Its match-time error is logged once per pattern instead of once per path, and `trusty-search index` prints the daemon's message naming a refused pattern (#8922).
