Fixed
- A deferred-embed pass now commits each embedding wave's vectors before the next wave starts, so a search during a long index sees them, and it holds one wave of chunks in memory instead of a copy of every owed chunk. The vector snapshot is written every `TRUSTY_EMBED_CHECKPOINT_CHUNKS` embedded chunks (default 16384) or `TRUSTY_EMBED_CHECKPOINT_SECS` seconds (default 120), and on every exit, so a killed pass keeps every checkpointed wave and a restart does not embed them again. A snapshot that fails three times now fails the pass (`semantic: failed`, pending marker kept) instead of being logged while the pass settled `ready` (#10294).
