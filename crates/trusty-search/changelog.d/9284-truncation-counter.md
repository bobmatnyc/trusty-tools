Added
- `GET /indexes/:id/status` (socket `search.index.status`, MCP `index_status`) reports `embed_window`: `{window, truncated, unmeasured}`. An embed pass counts each chunk's tokens, special tokens included, with the tokenizer the embedder truncates with; `truncated` counts embed events for chunks longer than the embedder's input window, whose tail the vector does not cover; a forced reindex or a retry embeds a chunk again and counts it again. Each pass logs one WARN per affected file (index, file, chunk count, tokens, window) for at most 8 files, then one summary WARN. `unmeasured` counts embed events whose chunk length could not be counted (no tokenizer, a tokenizer error, or a failed count task), with one WARN naming the cause. `window` is `null` when no embed pass has run since the daemon started, or when the embedder reports no window (every sidecar embedder today, which counts nothing) (#9284). The counters are in memory only and restart at zero with the daemon; chunking, chunk ids, vectors and stored formats are unchanged (#9284).
