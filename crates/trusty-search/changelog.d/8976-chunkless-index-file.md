Fixed
- A `.json` file of 500 lines or more is now indexed as 200-line chunks. It used to produce zero chunks, so it was missing from search while `index-file` answered `indexed: true` (#8976).
- `POST /indexes/{id}/index-file` (and the `index_file` MCP tool) answers `indexed: false` with a `reason` when a write produced no chunks: `empty_file` for blank content, `no_chunks` for non-blank content the chunker could not split. The non-blank case also logs a WARN (#8976).
- A reindex no longer records a file's content hash unless every chunk of that file reached the corpus. A file whose chunks were dropped (chunk cap, failed pre-commit removal, failed commit, zero chunks) has its hash cleared in memory and in redb, so the next reindex retries it, including after the file is reverted to content an earlier reindex had indexed. Blank files and over-ceiling JSON keep their hash. A batch logs one summary WARN for its withheld files (#8976).
