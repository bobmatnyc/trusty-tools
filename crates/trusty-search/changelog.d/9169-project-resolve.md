Added
- `search.project.resolve` socket method: send `{"project": …}` with a project name or index id, an `owner/repo`, or an absolute path, and get back the one live index for that project (`index_id`, `root_path`, `repo_identity`, `kind`, `resident`, `corpus_modified_unix`, `matched_by`). An exact index id, or the index whose root holds the path, is returned itself unless it is a worktree or an orphaned root. Otherwise the main checkout wins, then the index whose corpus file was written most recently; a worktree root never wins. A subdirectory index (a root with no `.git` of its own) is grouped by its root, not its repo. Every other index of the group is listed in `duplicates`. A miss answers an error whose `data` carries `error` (`project_not_found`, `project_ambiguous` or `no_live_index`) and the nearest `candidates`. A resolve reads disk only for the matched group and the five nearest candidates, and never reads a `/Volumes` root, which reports `kind: "indeterminate"`. Socket-only, in the free lane (#9169).
