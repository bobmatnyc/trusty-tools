Added
- `extract::worker` behind the `extract-worker` feature (SPEC-OKF-01 §2.16, Appendix B, #10746): `WorkerExtractor` runs the out-of-process extraction worker over the Appendix B protocol. The worker starts in its own process group with only `LANG=C.UTF-8` and `TZ=UTC` in its environment, in a fresh empty working directory, and is found only at the configured path (`worker_absent` otherwise).
- Every wait on the worker has a deadline: handshake (10 s), item wall time (30 s), shutdown (5 s) and reap (5 s). A crash, hang, oversize output, bad frame, lied input hash or cancel fails only its item, and the worker is killed (SIGTERM, then SIGKILL to the group) and reaped; `Drop` does the same on a host error or panic. A silent, incompatible or non-deterministic worker fails its items for the run, never falls back silently, and is not respawned.
- The host applies an OS sandbox in its own spawn path (`sandbox-exec` on macOS, `bwrap` on Linux, no network and no file access outside the working directory) and decides from that spawn evidence alone: a connector-store item reaches only a sandboxed worker (`sandbox_required` otherwise), and a worker whose `hello` disagrees with the evidence is `worker_incompatible`.
- `ImportReport::worker_errors` records `WorkerError` (`Spawn`, `HandshakeTimeout`, `Incompatible`, `ShutdownTimeout`, `ReapTimeout`); any entry makes the run incomplete with exit code 3. The worker's stderr is kept as a 64 KiB excerpt for the report only.
- Extracted concepts record `extracted_by`, `extract_protocol`, `xberg_version`, `extract_config` and `extract_input_sha256`; none of them counts as content, so a worker upgrade with the same text keeps a verified revision Verified. `plan_import_with` plans with the worker's full fingerprint, so a worker or configuration change re-extracts exactly the items it produced. `trusty-okf import plan|run --worker <path>` uses the worker.
