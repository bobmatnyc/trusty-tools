Added
- `state` (SPEC-OKF-01 §4.9, #10746): `Bundle::revision_state` and `Bundle::state_summary` report save, index and verification state separately, with the OKF trust tier beside them. `StateSummary::synced` is computed at each read.
- `_sources/revisions.jsonl`: every concept write appends a revision line before its rename; a file reads Saved only when its bytes match a recorded line, SavedExternal otherwise.
- Machine-local index state: `IndexStateDir`, `IndexJournal` and `IndexRecord` live at `<state-dir>/<sha256 of the bundle root>/<index-id>.jsonl`, never in the bundle. A state directory inside the bundle root is refused with `OkfError::StateDirInBundle`; a legacy `_sources/<id>.index.jsonl` is reported as an info finding and never read.
- Index identity (§4.9.2): each confirmation names the `IndexIdentity` it was observed against; a record reads Searchable only under an equal `LiveIdentity::Known`. `Unsupported` (no D1) and `Unreadable` read Pending.
- Operation journal (§4.11): `move_concept`, a logged or content-changing `put`, and `verify` run as one journaled operation under `_sources/ops/`. `Bundle::open` reports an interrupted operation and refuses writes to its paths; `Bundle::recover_interrupted` recovers it (an open never recovers a possibly live writer's operation). An out-of-band edit after a crash is a `recovery_conflict`, writes to its paths return `OkfError::RecoveryPending`, and `Bundle::recover` resolves it, keeping a copy under `conflict/`.
- An ingest run writes `log.md` once, at the end of the run, instead of once per item; each call gets its own batch, so chunked runs and retries with one `now` keep every entry. The entries survive a crash and are written by the next recovery, and wait while a conflicted operation owns `log.md`.
