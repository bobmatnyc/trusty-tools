Added
- `feed` (feature `search-feed`, SPEC-OKF-01 §5, #10746): one pass pushes every concept on disk to the caller's trusty-search index over the Unix socket (`RpcIndexFeed`), withdraws moved, deprecated and tombstoned paths, and probes each acknowledged put. `FeedReport` counts acknowledged, searchable, removed and pending paths separately; only `FeedStatus::Searchable` is success, and `feed::exit_code` maps the other outcomes to a non-zero code.
- A put counts only when the reply says `indexed: true` (or a tombstone `removed: true`) and, when the daemon reports one, its `content_sha256` equals the bytes sent. The journal records the hash of the bytes sent. A journal append that fails after a confirmed put stops the pass with `OkfError::JournalWrite`.
- Each pass refuses an index whose root does not contain the bundle (`OkfError::RootMismatch`) and checks first that no `_sources/` or `_state/` path is indexed; a leak is removed and the pass returns `OkfError::IndexScope` without pushing.
- The retrieval probe is the only way to Searchable: a scoped lexical query must return the current text, and either the index's per-file hash (D1) or the path's chunks must match the current bytes. Without an index identity a pass ends `Unconfirmed`.
- `Bundle::index_backlog` lists what one machine's index still owes, hand-written concepts and moved paths included.
- `retrieve` (feature `search-feed`): a scoped `search.query` whose hits carry the concept, status, OKF trust tier, staleness, trust label and verification state read from the file. A hit with text the current file no longer holds is flagged `stale_revision` and reported unverified; hits for deprecated or tombstoned concepts are dropped.
- With an index identity (D1), the probe accepts the per-file hash only when the `search.index.file.status` reply names the same identity as the acknowledged put; a null or different identity leaves the concept Acknowledged, never Searchable.
