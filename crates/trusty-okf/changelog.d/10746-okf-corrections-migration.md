Added
- Correction lifecycle (SPEC-OKF-01 §2.5, 3c A; #10746): `Bundle::deprecate` retires a concept in place with `status: deprecated` and one `log.md` entry, keeping its verification; `Bundle::supersede` creates the successor with `supersedes`, then marks the old concept `status: deprecated` with `superseded_by`, as one journaled operation. A write of `source_status: deleted` without a non-empty top-level `source_id` is refused with `Conflict { reason: "tombstone_without_source_id" }`.
- Lossless trusty-kb to OKF v0.2 migration (§2.8, §2.9): `Bundle::plan_migration` lists the per-file changes and writes nothing; `Bundle::migrate` stores content-addressed backups and a manifest under `_sources/migrations/`, runs as a journaled `Migrate` operation, audits IDs, bodies, keys, sources, verification events, journals and logs, and on a failed audit restores every file and returns `OkfError::MigrationLoss` (with `restore_failed` for a backup whose hash no longer matches). An interrupted migration rolls back from the same backups.
- `build::rebuild::rebuild` (§4.5): regenerates ledger-owned concepts from store contents as one staged, journaled swap, never touches hand-owned concepts, inserts one `**Rebuilt**` `log.md` entry and reports the lines it added, and leaves byte-identical every concept it cannot prove it wrote (`hand_edit`, `caller_edit`, `no_written_hash`). The trusty-kb v0.1 equality proof binds legacy concepts whose bytes it reproduces.
- `Bundle::adopt` (3q C): a confirmed `human:` actor records reviewed legacy bytes as engine-written; `OkfError::AdoptRefused` (`not_human`, `not_confirmed`) refuses the call with no file changed, and each refused pair is listed (`byte_hash_mismatch`, `not_found`, `not_ledger_owned`, `already_proven`).
- Revision-journal lines carry `proven` and `origin` (§4.5 "Ownership proof"), so a rebuild tells trusty-okf's own writes from hand edits; `ByteHash::of` hashes file bytes for `adopt`.
- While a migration that holds `_sources/revisions.jsonl` is incomplete or conflicted, every write that appends to it (`put`, `verify`, `deprecate`, `supersede`, `move_concept`, `adopt`, `rebuild`, ingest) is refused with `OkfError::RecoveryPending` and changes no file, so a later roll back cannot drop its revision line (§4.11 rule 2).
